# V2 章节手动生产

应用根在旧小说路由之前安装本入口。来源页的 generate、runtime/run、repair、review 和分项 audit 沿用既有协议；按数据库中的作品归属分流。灰度沿用 `PRODUCTION_KERNEL_V2_CHAPTERS`，缺省关闭；V1和关闭灰度的新请求继续原处理器，错误不得触发新旧重试。

每次手动操作通过既有 open_run 命令创建 `production-kernel-manual@1` 单章计划，只有 novel_seed → chapter_batch。它使用现有 worker、真实租约、当前书 epoch、预算与进度表；不伪造自动任务的控制状态，不创建替代 GenerationJob。scope包含新runId，手动作业只认自己的单章回执，不能借前次完成记录跳过重新审校；相同作业的恢复仍复用已保存阶段。

手动写章要求空正文；已有正文使用修章或重新审校。修章先完整审校，依照与自动生产相同的问题策略执行一次安全补丁及事实复验，只有最终选中稿可写入正文。重新审校使用相同长篇能力，但修补额度为0，不改写正文。手动编辑继续由原 ManualChapterStore 保存版本及同步义务；重新审校针对该已保存版本，未保存的不同正文返回保存提示。

`user_requested` 只允许处理启动时已经存在的人工正文，不允许覆盖任务期间的编辑。阶段及实际请求仍核对正文、领取和租约，正文CAS与进度共享事务。原生复验描述使用初审结果内的 assessment，与实际复验请求保持一致，整份服务返回值不能充当评估基线。

兼容SSE仅发布最终选中并保存的正文与 runtime_package，检查、候选选择和回填尚未完成时继续等待。连接断开只结束等待，后台任务继续；失败或暂停从本书导演台已有的来源页处理，运行记录保持只读。不新增用户设置，不改变资料检索开关。

临时库整链使用真实命令、worker、准备、PromptRunner、安全补丁、原编辑保存服务及消费者，仅替换SDK传输。此证据不代表真实模型质量、PostgreSQL或beta发布验收。
