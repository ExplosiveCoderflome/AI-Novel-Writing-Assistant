# V2 长篇内核装配边界

`manual` 在来源页兼容入口中按作品持久归属分流，用独立单章计划复用相同原生内核与任务底座；默认灰度仍关闭。手动审校禁用自动修补，手动作业不得借用其他任务的完成回执；正文编辑保留原保存服务。详见 `manual/README.md`。

本目录拥有 V2 运行契约与长篇生产内核之间的翻译。导演内核不导入 production；V1 及旧生产实现保持冻结。原生入口已接入 productionComposition，开关默认关闭，已经保存的批次实现不随开关改变。

## 持久批次路由

`batch/binding` 在持有书 epoch 与当前步骤租约的事务中保存一次实现选择。恢复只读该选择；切换环境开关不能迁移已开始的作业。存在 chapter_batch_job 或尚未写绑定事件的已启动旧作业时，继续旧路径。冲突绑定拒绝继续。

`batch/router` 只调用已选实现，不在新实现失败后回落旧实现。`batch/handler` 按授权范围逐章执行，局部质量债允许继续；未知结果与人工暂停交回来源页恢复。仅全部章节选稿/提交/回填闭合，且重新读取的当前原文与提交哈希一致时，才能发布批次产物。

## 事务归属

worker 将实际领取的 leaseOwner 显式传入步骤。`execution/ownership` 捕获该身份，在每个业务事务中依次锁定书与控制行，检查导演版本、epoch、合同快照、步骤版本、租约有效期及书章授权范围。不能通过查询当前 leaseOwner 为旧执行者重新授权。使用同一锁顺序，避免不同消费者相反加锁。

## 验收边界

`execution/chapterBudget` 持久保存物理预留与实际用量，明确未发送的预留可释放；迟到用量仍恢复记账。未知用量继续按预留计入。`requestScope` 将每个物理调用与其观察回执配对，观察写入失败不能被下层吞成成功。

`execution/budgetReader` 提供无 worker 租约的只读预算投影。保留原生 `uncached_tokens_v1` 口径，仅扣减已报告且有效的缓存命中；未分类用量照计，历史仅总量的回执保持原始收费。未知请求继续占用各自预留，同一请求下的其他已付费用量仍累加。预算对象捕获契约副本，调用方修改内存对象不能扩大额度。

`recovery/commands` 在来源页显式命令事务内确认质量暂停、追加预算或取消；暂停投影按真实 ProductionUnitRun 及预算拒绝记录读取。授权事件与控制恢复同事务，读取与命令重放不重复授权。未知领取始终保留，取消后旧执行者无法继续预约或业务写入。书 epoch 替换不阻止取消旧任务；质量确认及预算追加仍要求当前 epoch。

`execution/reviewBudget` 为原生初审/候选核对绑定同一份持久重试计数，检查策略快照和当前阶段领取。原生重试作用域会替换外层作用域，因此必须显式串接外层物理预约；内部重试额度拒绝时，只释放有类型证明的未发送预留。存储异常保持锁存，不能退化成可发布的质量检查结果。

`prompts/preflight` 使用 Prompt 层的实际覆盖、上下文选择、模板及结构化提示。配置身份只保存白名单摘要，不保存凭据或原始端点。结构化主模型、备用模型、协议与 JSON 纠错的可执行配置均须预检；实际 SDK 调用与已保存配置不符时锁存拒绝，原生异常处理不能将其吞成有效结果。原生省略输出上限的协议不满足可执行预算合同，应在启用前配置或适配，不能猜测上限。

`prompts/modelWindows` 只读取调用方捕获的明确 provider/model 窗口元数据；没有条目就返回未知，不猜型号族。原生装配将明确元数据随批次模型策略一起冻结。

`modelPolicy` 提供原生配置读取、明确窗口元数据及批次一次性绑定。六类任务的有效配置摘要、主备模型、fallback 和窗口随契约保存；端点、任务输出策略或元数据漂移拒绝继续，凭据只在运行中解析。createNativeKernelRuntime 已将冻结配置检查安装到阶段与物理请求围栏。

`readiness` 在 prepareOpen 中于创建运行、付费准备之前校验存储与模型配置；幂等命令重放仍先返回原结果。已绑定新内核的批次及显式恢复也执行检查，不能借默认关闭的开关绕过。存储检查核对必要字段、主键、完整唯一索引、范围索引与外键，不执行迁移；部分唯一索引不能满足批次幂等约束。单次输出额度由模型路由界面调整，未填写时默认 8192，显式设置优先；实际上下文窗口与原生协议检查继续生效。

`prompts/stageServices` 为 writer、初审、候选事实核对及补丁保存完整只读请求。补丁执行使用预检时保存的 runtime 许可；执行前后复核有效身份。物理预约按每次实际完整消息、响应格式、工具和模型构造参数计入输入，加输出上限与安全余量，不能把初次请求估算复用于更长的纠错请求。

`readModel` 核对当前原文、选稿/提交哈希、阶段回执与章节终态。来源页批次确认及进度读取按持久新旧路由消费这些事实；真实 activeStage/activeRequestKey 标识当前章节，暂停时隐藏运行阶段。读取不恢复任务、不确认质量暂停，也不创建旧 GenerationJob。

`rag` 为原生检索安装持久请求范围。检索配置、准确窗口和分块来源版本在准备时保存；embedding/重排的每次 HTTP 重试、拆分进入独立检查点及同一单章预算。请求许可使用捕获副本，未知结果不重发；配置、来源或租约变化拒绝发布。集合/索引只读检查和空伏笔账本只读范围保持正文准备无隐式索引/账本写入，普通旧调用保持原行为。

三章联测覆盖批次处理器、内核、终态报告、业务消费者及预算/重试；模型输出为显式替身。原生准备、Prompt、批次模型策略、完整生产入口、RAG 开启/空账本和来源页恢复已有临时库集成验证。2026-10-26 本地计划05与规则映射审查完成；用户批准关闭资料检索后，内置浏览器原运行首章 approved/completed，重启无重复正文/报告/调用。文学效果与检索开启的真实提供方场景仍按当日报告单列，不能用替身或映射行数代替。新任务的物理输出额度来自可调整路由默认8192；已保存单元恢复保持原额度快照，审校/补丁/回填与预检使用同一额度作用域。
