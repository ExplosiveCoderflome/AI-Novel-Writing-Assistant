# 批次模型配置

`source.ts` 只读解析原生有效模型配置，不构造 SDK、不探测提供方，也不修改设置。捕获长篇链路使用的 planner、writer、review、repair、fact_extraction、summary 六类任务，以及启用的结构化备用模型。配置只保存白名单摘要；凭据、原始端点和模型附加参数原文不进入事件。

`binding.ts` 在当前书 epoch、运行契约和 worker 租约下保存一次批次快照。来源读取在事务外完成，再次检查所有权后提交；恢复优先读已绑定快照，不重新采用实时设置。事件绑定完整契约哈希；并发捕获只能保留一份绑定。

窗口使用明确的 provider/model 元数据。装配层可注入只读元数据源；默认读取后台环境变量 `PRODUCTION_KERNEL_MODEL_WINDOWS`，格式为 `[{"provider":"已配置提供方 ID","model":"准确模型 ID","contextWindow":正整数}]`。默认空数组，无隐含型号窗口；主模型及启用的备用模型任一缺失窗口均拒绝继续。此处不改写用户配置，不代表开关已启用。

`createKernelFrozenModelPolicy` 提供冻结的 fallback/window 读取及 `assertCurrent`。完整装配必须把后者安装到每个物理请求围栏，Prompt 预检继续检查每次实际消息、协议纠错、输出上限和有效模型配置。凭据可以临时轮换，其余有效模型配置漂移需处理后再运行；不能在新章节中静默接受另一份配置。

createNativeKernelRuntime 已安装到 productionComposition 的持久批次入口，并将模型策略绑定、冻结窗口、fallback 和配置围栏传入原生阶段与物理请求。readiness 在新运行的付费准备之前、已绑定新内核的批次入口及显式恢复时检查存储、准确窗口与六类任务的可执行输出额度。

输出额度在系统设置的模型路由中由用户调整。未配置的任务使用可编辑默认值 8192；已保存或请求明确给出的正整数优先，不按提供商注册表中的旧默认额度静默截断，保存的 4096 也作为实际选择保留。上下文窗口是独立的模型能力信息，完整输入、实际协议与输出预算仍需通过每次物理调用预检。此处不覆盖 RAG embedding/重排请求，也不替代 Prompt 模板/覆盖的实际输入快照。

`outputBudgets.ts` 将已核对配置摘要的任务数值捕获为新单元的阶段额度，并在原生请求描述、执行及恢复期间安装 TaskOutputBudget；服务内部历史默认值不能覆盖用户已选的任务额度。SDK 参数也核对此数值。已有单元恢复继续使用持久 profile 的原额度，不能因部署代码或全局默认变化重写快照；全局模型配置变化仍由原绑定检查拒绝。
