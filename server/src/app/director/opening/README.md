# 原开书界面与新导演交接

## 边界

原 `/novels/auto-director` 是开书前的设置和候选选择界面。产品允许保留这些控件和候选服务；它们不负责小说生产。此入口适配器位于 app 层，不能被新导演 domain/application/infrastructure/steps 导入。

只放行未关联小说任务的候选生成、候选细化、候选修改、标题优化及确认请求。已有小说的旧继续、接管、恢复和章节生产仍由冻结入口拒绝。已通过本入口确认的书允许幂等重放确认，不能重新调用旧正文链。

## 命令与恢复

HTTP 响应只将本次明确请求接受的 commandId 交给执行器；通过数据库原子租约和心跳避免重复执行。不启动旧 Worker，不扫描或恢复历史生产任务。候选阶段复用原注册 Prompt 和保存格式；确认命令绕过旧确认执行器，从选定方向创建稳定小说 ID 并调用新 open_run。

候选失败明确保存为 failed 和 pendingManualRecovery。原页面的重试调用 opening-retry，只恢复未关联小说的最新候选或确认命令，保留旧失败行及原请求，新命令由旧失败 ID 形成幂等键。重复点击复用进行中的重试；明确点击恢复才清除人工恢复标记。不得把继续正文、接管等旧生产命令映射成候选重试。

进程中断不会自动扫描旧开书任务。任务详情只读投影租约过期的未关联小说开书命令为待恢复，让原页面展示重试入口，不写任务或命令。用户明确重试后，在同一事务核对最新命令身份、状态、租约拥有者与到期时间，将过期命令记为 stale，再按原请求建立幂等重试。有效租约保持不变；没有到期证据不能强行释放执行权。不能启动完整旧 Worker 掩盖中断。新导演的章节恢复仍在小说导演台操作。

## 结果与展示

开书记录在交接完成后保存新小说 ID 和明确的 `/lab/director/:novelId` 来源路由。后续状态、范围、确认和恢复由新导演维护；布局和原表单外观不决定生产引擎。用户选择的候选及基础设置进入新书与启动快照；正文范围仅来自明确选择的执行范围或整书自动模式。

任务详情和列表必须优先使用持久化的新导演来源路由。候选阶段历史保留用于查看想法和候选，不能凭 candidateStage 或 candidate_selection 历史标记将已交接任务重新投影为开书页。交接验收必须同时验证数据库来源路由、任务详情返回路由和前端路由解析；仅证明建书成功不足以证明入口闭环。
