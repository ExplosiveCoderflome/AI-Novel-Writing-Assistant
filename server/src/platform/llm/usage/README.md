# 模型调用用量

domain 只归一化供应商返回的统计，不依赖数据库或业务执行。平台门面供旧 llm/usageTracking 和实况消费；业务总量更新仍只有 usageTracking 一个入口。

缓存读取属于输入，缓存创建属于未命中输入，均不可在合计之外再次相加。明确返回 0 与未提供不同；未知为 null，无效计数只使缓存不可用，不丢弃合法基础总量。原生 Anthropic 的 input 不含 read/creation，SDK 标准 input 已包含，必须在协议适配后归一化。

同次调用流片段合并累计量，不求和；不同物理调用才求和。汇总有未提供或无效数据时不伪造完整缓存统计。厂商计数不根据字符数估计。

## 逐次调用台账

终态以 invocationId 唯一插入，不更新首次记录；重复身份但数据不一致记录诊断。台账写入失败只报告日志，不重试模型或暂停创作；现有作业计数独立保留。超数据库 Int 范围的单次计数存未知并诊断，不能截断伪造统计。查询按 runId 隔离、startedAt/id 游标分页，合计覆盖所有已记录调用而非单页；含未知或部分结果时缓存合计保持未知。历史不回填。

数据库新增迁移须由既有部署流程应用，验收库须先备份；本阶段只验证临时 SQLite，不部署用户数据库。PostgreSQL 未有隔离运行验证。

批量去重只在当前批次上下文生效，不能使用进程级响应对象去重来判断新请求；相同响应对象跨批次返回仍代表新的调用观察。SDK 批量返回的 Error 单项保存 failed / 未知统计。明确报告全零与完全无报告仍须区分。

## 书级查询

`NovelInvocationUsageQueryService` 查询本小说全部已记录物理调用，不局限于当前导演运行。应用组合层提供小说信息、章节及关联工作流/正文作业 ID；平台不调用业务编排。开书时 novelId 为空的调用仅能通过保存的关联任务/作业纳入；显式归属其他小说的记录不得纳入。

书级使用数据库 groupBy 汇总，不在内存拉取完整调用表。明细按 startedAt/id 倒序、limit+1 查询，游标绑定书和全部筛选条件。全书 summary 与 filteredSummary 分开，分页不改变合计。缓存已报告部分可汇总，但必须携带报告覆盖数；它不同于旧 run 级完整缓存合同。未知或无效缓存字段不加入已报告部分。

书级日志不与工作流、作业或旧导演计数相加，同一调用可出现在多个旧计数中。未记录历史、未报告 usage 和部分结果必须可见，不补算、不回写。该读路径不触发模型或改变安全预算。详见 [小说 AI 用量统计边界](../../../../../docs/wiki/workflows/novel-ai-usage.md)。

## 计时与载荷

`durationMs`、`firstTokenMs`、`attemptNumber`、`chainId`、`parentInvocationId`、`structuredMode` 随每次物理调用写入统一台账；旧导演启用 telemetry 时使用相同调用 ID 镜像这些字段。未知 Token 的失败尝试仍保留统一台账行，不能从用量缺失推断未发送请求。传输状态与结构化校验分开：响应完成后解析失败可保持 completed，错误在载荷中展示。

`InvocationPayloadStore` 持有 gzip 编解码、脱敏、AppSetting 历史开关和清理策略。`LlmInvocationPayload.usageRecordId` 是统一台账的 1:1 外键；所有消息、原始回答、解析结果或错误一起压缩，计入实际压缩字节数。原始用量行只插入一次；解析完成可更新该行的附属载荷，不能用后一次尝试覆盖前一次载荷。取消后仍允许写观察事实与附属载荷，但不能修改创作状态。

历史默认关闭，默认保留 7 天、100 MB。设置只影响新调用是否保存；关闭后已有载荷仍按保留策略清理。后台启动及每 15 分钟执行清理，先过期再按 createdAt/usageRecordId 移除最早载荷，分批读取；保留用量行、正文和业务计数。容量为周期清理上限，不是单请求硬限制。清理与解析更新并发时使用 updateMany，不重建已过期载荷。

书级详情先验证小说及已保存任务/作业归属，再读取单行和同小说尝试链，最后解压载荷。耗时汇总用数据库分组，最慢查询只取一行；不得为找最慢调用加载所有正文载荷。迁移仅从统一台账已有起止时间补齐耗时，不重建 Token、TTFT 或未知历史请求。支持包仅允许日志和摘要，不包含数据库、载荷表或载荷文件。
