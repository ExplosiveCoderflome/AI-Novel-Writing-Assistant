# 创作工作室边界

## 职责与依赖

`application/CreationStudioService` 将用户表达变为待确认意图；确认短篇后创建作品并交给 short-story，确认长篇后调用已配置的导演入口。HTTP 只校验输入并映射响应，不能自行执行规划或正文生产。

`reference/` 拥有短篇参考来源校验、完整所选结论读取、AI 合同抽取、版本指纹、确认校验和可用性投影。其他模块通过 `reference/index.ts` 消费快照与精炼合同，不深层读取内部来源实现。来源内容一律作为资料，不执行其中的指令。

## 确认与恢复规则

- 参考新短篇需要有效拆书及对应文档；不能因来源失败降级为无参考故事。原人物续写仍走既有长篇路径。
- 分析文字与结构化结论同时保留，人工编辑优先。所选内容过长时拒绝并要求减少范围，不截掉尾部结局。
- 参考抽取和意图解释是注册的结构化 Prompt；确定性代码只负责来源、版本、形态和范围校验。
- 确认前重新检查分析指纹。确认后在作品保存不可变快照，源资料修改或失效不改变已生成故事的参考约定。
- 方向失败也保留任务及原始选择，用户从 `/create?taskId=...` 继续。首次失败返回 failed 投影，调用方必须按任务状态判断，不能仅按 HTTP 201 认为方向生成成功。
- 幂等确认优先返回已有作品；来源删除后重放同一确认不能创建第二部作品，也不应破坏原确认。
- 模型尝试诊断由平台记录，失败投影只提供摘要与定位 ID。恢复入口遵守限流等待，不能绕过短篇已有检查点。

## 资料权限

现有系统为工作区共享资料，authMiddleware 不提供用户级 ACL。来源服务核对实际记录、文档 enabled 状态、分析成功与文档版本归属；加入多用户模型后，在同一读取边界补授权策略。

完整状态合同见 [创作与短篇工作流](../../../../../docs/wiki/workflows/creation-studio-short-story.md)。
