# 长篇正文生产内核

当前实现领域、应用执行器、可注入 Prisma 仓储、原子正文提交、阶段/原生服务 API 适配、事务业务消费者、回填恢复与共用安全工具。V2自动生产已经由应用层接线，手动入口通过独立单章计划复用相同内核；默认灰度仍关闭。短篇保留独立生产，不进入本内核。导入本模块不会创建数据库连接或模型调用，测试同时检查传递依赖。

## 归属与依赖

- `domain/` 拥有显式单章进度、配置校验、下一动作、候选选择和回放；只依赖自己的文件、common 的结构化合同与 Zod。
- 外部能力统一从本目录 `index.ts` 消费；领域测试按阶段方案直接验证 `domain/index.ts`。
- `application/` 负责阶段领取、执行、结果保存和端口；`infrastructure/` 拥有可注入的进度仓储与原子生命周期写入。V2 导演只由 app 层装配，不进入领域依赖。
- 长短篇共用约定和工具从 `common/index.ts` 消费。common 的原始债务封装保留来源完整字段，domain 的决策投影只消费结构化风险；短篇不能导入内核其他部分。旧调用方尚未替换。

## 决定与持久化分开

`decideNext` 只返回动作，不修改输入。无候选稿时，`select_final` 经 `applyUnitAction` 保存最终选稿、正文哈希及原因；有变化候选稿必须完成 `repair → verify → select`，通过 `applyStageResult` 保存相同字段。`commit` 只能引用保存的选稿。

质量债也通过显式动作保存。同一个动作和同一个阶段结果重复应用幂等；冲突重放拒绝。序列化恢复不重新解释已保存的选稿。修复失败或无变化仍记已用次数，但不对不存在的新候选稿付费复验。

## 安全与验证边界

候选必须有可信复验和事实保持，不能新增严重问题、义务缺口或表达退化。总分变化不构成采用依据。最终选稿阶段再次核对选择规则，拒绝伪造的安全选择结果。

领域层只消费结构化结论和输入事实。人工编辑、正文身份不匹配、全书重规划与明确人工策略均有独立处理。局部窗口和普通质量债不升级为全书失败；回填 pending 保持可重入，failed 不能伪装完成。

`ProductionUnitRun` 按 ownerKey/chapterId 隔离作业，保存三份配置快照、进度、制品、请求身份与版本。仓储 CAS 在事务内核对调用方注入的持久所有权；commit 的正文版本检查和回执保存共享同一事务。已通过临时 SQLite 的并发、失权、编辑冲突和保存后恢复验证。

真实模型请求之前仍须由调用方 BudgetPort 完成持久预约，领域次数不能代替它。文本和结构化调用均进入既有物理请求预算；审校必须绑定持久且冻结的共用检查重试额度，不能回落到书级实时策略。请求发出而结果未保存的窗口返回 unknown，保留领取，禁止自动重发；StagePort.recover 只读取已有模型结果，可继续有独立幂等保护的消费者。模型替身不证明真实提供方调用严格一次；业务消费者已用真实临时库验证。

配置快照改变会拒绝同作业恢复；模型快照采用字段白名单。适配器 describe 必须只读并计算完整实际输入指纹，不能只用正文哈希。已选稿与制品不可被后续阶段暗中替换。

原生审校与补丁的请求构造位于 `infrastructure/services/prompts/`，只复用注册资产和纯上下文/写法函数；语义审校、重试和安全补丁应用仍由原生服务负责。app 调用方必须解析正式覆盖、模板及结构化提示，保存完整有效消息身份，并在实际 SDK 请求之前检查模型配置和完整输入预算。原生请求字段的变更须同步逐字段对照测试，不能以缓存键或截断正文代替请求描述。

只有类型明确证明未发送的预算拒绝才能清除领取。清除时保存 `deferredDescriptor`，显式恢复继续使用原始请求输入；不能重新读取已被前序消费者修改的账本而产生第二次抽取。缺少使用量观察不证明未发送，远端结果未知仍保留领取。

## 阶段适配与回填

准备适配器先完成执行合同，再调用现有只读上下文组装器；只允许准备期间的元数据版本更新，正文变化会阻止继续。注册 writer 适配器只返回整章草稿，修复候选必须携带事实核对基线；底层补丁服务包装的网络异常不能当作确定的补丁失败。

回填把抽取输入保存在阶段描述中；严格兑现复核和时间线抽取也先保存完整输入，避免自身写入或外部账本变化导致恢复时重复付费。各消费者独立检查点绑定运行、阶段请求、正文、输入和租约。`causal_closure` 配置要求时间线持久边界；缺少适配时返回 pending，降级边界保留 degraded。

正文版本与执行租约是不同保护。`persistence/` 的业务写入与回执共享事务，写前后复核并持有租约、运行和章节锁。检查点键包含运行/作业身份，不能因正文相同跨作业复用。资源完整规范版本和时间线仓储显式绑定 tx；严格对账另有事务提交边界，缺失时保持 pending。

回填闭合时，选中稿的 accept/verify 报告、审校来源冲突、章节终态和 reconcile 进度回执共享事务。不可用审校不发布质量分数；pending/failed 不发布终态。完成读取还要核对当前原文与所选/提交哈希及章节终态引用，不能仅靠 approved 标签跳过。

摘要、事实、兼容抽取投影及 RAG 任务一起提交。兼容投影使用既有归一化 24 位哈希，内核继续使用完整原文 SHA-256；时间线兼容检查点另用 SHA-1。保持格式是为读取端互通，不是版本路由。`createStoryStatePort` 只允许使用当前已领取阶段的保存描述执行回填。

质量优先在正文 commit 后保存 `qualityPause`，此后才返回人工暂停，回填等待显式恢复。自动重启或轮询不解除该标记；来源页命令通过归属/正文核对后执行 `acknowledgeUnitQualityPause`，原策略快照保持不变。

五份人工审定的结构化夹具仅验证新领域决策的稳定回放，不是与旧流水线同样本运行的等价证明。旧/新差异清单仍是计划 05 切换前的独立门槛。
