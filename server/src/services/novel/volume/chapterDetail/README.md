# 章节执行合同细化边界

## 职责

本目录负责卷规划进入单章生产前的最后一层结构化细化：章节目的、边界、任务单、读者体验合同与场景卡 Schema，以及对应的 AI 生成和质量门禁调用。

## 依赖规则

- Prompt 资产可以通过 `volumeGenerationSchemas.ts` 的兼容导出取得 Schema；Schema 文件不得反向加载 Prompt 或生成服务，避免模块初始化循环。
- AI 生成只通过 Prompt Registry 资产与 `runStructuredPrompt` 进入，不允许在服务内新增内联业务 Prompt。
- `volumeGenerationHelpers.ts` 是兼容门面；外部调用方不应深层导入本目录内部文件。
- 已有任务单和场景卡在无新 guidance 时继续复用；质量门禁、读者体验字段和场景体验字段不得在兼容层放宽。

## 实际前文与局部修订

即时细化从持久化章节读取最近一章实际正文及摘要，作为 `previousChapterResult` 传入生成和质量审阅；正文优先于尚未执行的规划，程序不猜测物品、角色或时间的语义关系。

自动模式下 AI 建议 `repair_contract` 时，合同生成与形状纠正共享两次生成上限。仅发布最终质量评估；剩余指导随 taskSheet 保存，供写作、验收与修文消费。第二次输出形状不可用可保留先前结构有效合同，但取消、连接故障、数据错误与明确重规划继续抛出，不伪装成正常修订。

## 准备与请求归属

单章调用方可通过 `chapterContractPorts` 接管注册 Prompt 执行与语义审查。端口收到每次真实请求（包括局部重试的指导和完整前文），负责输入快照、预算预约与结果保存；合同形状检查、两次生成上限和指导投影仍由本模块负责。未注入时沿用原生执行。

连续性审查的注入端口不访问旧版全局缓存。持久化归属由调用方的运行、输入版本与事务确定，不能用 novel/chapter 级缓存代替当前执行者的回执。
