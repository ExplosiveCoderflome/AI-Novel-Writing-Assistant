# V2 正文人物身份处理

本模块消费最终正文的 `characterCandidates`，不发起模型调用，不调用 V1 角色自动确认、全阵容重建或开书补全。

## 边界

- `DirectorCharacterCandidateService` 在短事务中核对小说版本、执行代次、当前运行、控制状态与正文哈希，保存候选、最小角色身份和处理记录。
- `references` 只绑定结构化身份引用，保留原正文与证据。未确认或忽略的人物不进入角色状态消费者，避免旧消费者的模糊姓名匹配误绑定；原提取保留在提取检查点中。
- 运行模式来自持久合同。全自动执行有正文证据的 AI 建议，身份不确定时留下候选继续生产；半自动等待作者逐项选择，批量确认后由显式恢复命令继续。
- 候选、角色写入和检查点是一个事务。同一运行、章节、正文哈希只创建一次；恢复从原提取重新绑定身份，不重新调用模型。
- 候选使用 `v2_pending/v2_confirmed/v2_ignored`，旧导演的待确认队列与手工接口不得处理这些记录。
- 全自动未决候选在相同小说、相同代次的后续运行中仍可读取与人工确认；处理绑定当前运行的写权限和原正文哈希，不启动旧运行或继承旧半自动门禁。

## 调用方向

`ChapterArtifactRecoveryService` → 本模块 → 角色持久层；确认接口由 `app/director/services` 组合到 V2 HTTP 依赖端口。本模块不依赖 V2 内核的命令、调度或投影，领域层不引入数据库依赖。

半自动等待以 `CharacterCandidateReviewRequiredError` 返回，资源同步保留 `characterReviewId`；正文作业设置 `pendingManualRecovery` 与 `pendingCharacterReviewId`。确认接口只保存选择，`resumeBusiness` 核验已确认和正文哈希后才允许显式恢复。后台轮询不得清除等待状态。

## 不变量

先最终修复与保存，再提取与人物确认，再回填角色状态、资源等消费者，最后关闭章节并进入下一章。已完成的历史章节不自动重跑；新人物只建必要身份，不补全整个人物档案。全自动遗留的不确定人物可在本轮处理结束后手工确认，确认不会重写历史正文或补跑整套资源提取。
