# 导演 V2 角色出场记录

本模块通过 `index.ts` 对外提供最终正文出场写入与只读查询，不依赖 V1 导演或角色动态重建。

- V2 拆章在原请求中输出逐章 `plannedCharacterIds`，保存于 `VolumePlanVersion.contentJson` 的章节对象（版本文档是完整卷规划来源，无需新数据库列）。缺字段表示未排期，空数组表示明确没有现场角色。
- 计划出场优先采用最新有效章节 `StoryPlan.participantsJson`，再采用初排；有效空名单同样覆盖初排。初排供详细任务细化，实际正文出场独立核对。
- 实际出场复用 `chapterArtifactDeltaPrompt` 的 `characterAppearances`。正常写入位于最终修复、正文保存和候选身份处理之后，下一章之前。
- `present`、`mention`、`flashback`、`dream` 由 AI 结构化分类。持久化只校验本书身份、正文短摘录和版本，不通过名字匹配正文推测出场。
- `applyFinalChapter` 校验 V2 归属、运行批次、执行世代和运行控制。`writeCharacterAppearances` 供已持有归属锁的候选确认事务使用，不能作为绕过归属检查的公开写入入口。
- 出场投影存放于按小说、章节、正文哈希隔离的检查点。重复消费幂等；正文改变时旧记录不会展示。
- 自动模式暂缓的候选使覆盖状态保持 `untracked`；确认身份时复用持久化提取结果，事务内补齐首次出场，无需新 AI 调用。
- 缺少字段的历史提取、无效证据或未解决身份不能解释为角色缺席。已知的有效事件仍可显示，但只有完整覆盖章节允许提示计划与实际不一致。
- 查询不写库、不调用模型、不重建动态。V1 的旧时间线保持原链路。
- `planning/InitialCharacterScheduleService` 提供显式补齐：每次最多 24 个未排期且未准备详细任务/正文的章节，复用原规划摘要，仅生成 ID 名单。重复请求无缺口时直接返回，同进程同书并发在模型前拒绝；写入前校验导演世代、当前运行控制、活动规划版本及原始内容。只更新版本文档，不创建 Chapter，不触发执行同步、伏笔整理或 V1 动态重建。
- 本书处于运行、确认或恢复等待时拒绝补齐。界面操作属于小说的角色时间线，任务中心仅查看记录；GET 不触发补齐。新书拆章 V2 使用 v10 契约，V1 保持 v9。
- `readNovel` 为全员时间线提供按章节合并的只读响应，章节元信息不按角色重复。它与单角色 `read` 共用 `readChapters`，每章只计算一次正文哈希并解析一次检查点；不循环调用单角色查询。仅加载本书角色、最新有效参与者与当前正文版本记录，已删除或其他小说的角色事件不能混入图中。

详细语义见 [工作流 Wiki](../../../../../../docs/wiki/workflows/director-v2-character-appearances.md)。
