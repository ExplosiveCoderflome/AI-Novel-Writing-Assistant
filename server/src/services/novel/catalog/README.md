# 小说目录查询

`index.ts` 是目录查询的入口。`queries/NovelCatalogQuery` 负责分页筛选、关联事实读取和列表投影；核心 CRUD 服务仅转交列表请求，继续拥有写命令。

目录查询只读取小说、封面、用量及任务事实。不得触发任务恢复、重试、状态修正或自动导演执行。最新任务先按更新时间和 ID 排序，再排除归档项；失败和等待恢复的任务仍是有效的最新任务。活动步骤只补充空白标签，不改变任务状态。

分页总数和列表使用相同筛选条件。返回字段、空关联的 `null` 和至少为 1 的总页数属于兼容契约。数据库失败应向上传递，不能投影为无小说、无任务或零用量。

## 正文数量与创作状态

- `_count.chapters` 是目录行数，允许包含大量空正文的路线占位，不能显示为已写正文数。
- `queries/NovelBookProgressQuery` 按书聚合非空正文的唯一章序，返回 `bookProgress.writtenChapters`。空格、换行和制表符不构成正文。查询只返回计数，不把所有正文传给客户端。
- `targetChapters` 来源于已保存的全书预计章节数；未知时返回 null，不以目录行数或某次运行的范围推断全书目标。
- `director` 只提供当前世代的最新 V2 运行控制状态。旧世代、显式 V1 与短篇不使用该状态；运行完成只说明本次授权范围结束，不能表示整书或质量验收完成。
- V2 目录不把旧开书交接的成功任务暴露为 `latestAutoDirectorTask`。历史任务完整保留，V1 沿用既有任务摘要。目录读取不得修改任何旧任务或运行控制列。
- 客户端使用服务端来源路由进入 V2 导演台；缺少有效来源时重新读取，不能回退到 V1 编辑器或从首页恢复旧任务。

影响范围为首页、书架与目录接口消费者；任务中心保持只读，确认与恢复仍在来源工作台。
