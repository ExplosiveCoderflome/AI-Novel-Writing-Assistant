# 小说正文生产执行边界

`NovelCorePipelineService` 是章节流水线任务的门面，负责创建、复用、恢复、取消任务、领取持久执行租约以及维护任务生命周期。

`NovelPipelineExecutor` 负责一次已领取流水线的章节执行循环，包括正文生成、质量闭环、滚动路线补齐和章节边界交接。它不提前生成下一章正式执行合同，也不创建第二套正文能力；具体章节写作、审校、修复和事实提交仍委托统一的 `ChapterRuntimeCoordinator`。

执行器内部按职责使用三个明确子边界：`qualityClosure/` 负责章节审校、质量债和明确重规划结果，`issueGovernance/` 负责把任务策略转换成继续、暂停或失败控制流，`handoff/` 只在章节安全落库边界处理生产体验交接。

维护规则：

- 自动导演、手动批量和恢复入口都通过流水线门面进入同一个执行器。
- `preparation/` 拥有正文执行前的规划写入：autopilot 路线与章节执行合同先准备，章节计划随后确保完成。执行合同以当前卷规划为结构基线，并由共享策略分别判断结构完整和正文入口字段兼容；手动与自动入口不得自行维护简化复用条件。`GenerationContextAssembler` 只读取这些产物；审阅、修复和预览等上下文读取入口不得隐式触发规划写入。
- `runtime/context/chapterContextProviderContracts.ts` 定义章节上下文提供者合同。角色硬事实、上一章实际结果和章节义务必须按适用阶段到位；首章的上一章结果不适用，后续章节缺失时必须返回明确缺口。软上下文只能按声明的降级/可选语义处理。
- 稳定层缓存通过 `novel:updated` 以及角色、卷规划、大纲、书级合同和流水线完成事件失效；任何改变章节上下文的写入口都必须发布其中一个事件，不能只依赖 TTL。
- `NovelProductionOrchestrator` 的阶段返回区分“已交接执行”和“章节已完成”：正文/修复流保持 `checkpoint + awaiting_stream_completion`，流水线任务保持 `checkpoint + queued/running`，并提供唯一的源页或任务恢复目标。阶段返回不得另行推进 `quality_repair`，因为质量闭环属于统一章节运行时。
- 路线窗口只保证未来方向可用；完整执行合同只为下一章即时生成。
- 普通质量债不能停止全书生产，只有明确重规划或运行时安全问题可以停止。
- 自动修复稿在复审和版本选择完成前只作为运行内候选；选择器复用两次已有验收，选定后才允许保存候选并对唯一保留稿提交时间线、事实和最终资产。
- 最终资产同步返回 `completed / pending / degraded / failed` 与正文版本；只有完成或明确降级后才发布章节终态，排队、运行中和失败结果必须保留给恢复入口，不能写成已完成。
- 同正文版本并发同步共享抽取、连续性边界持久化和成功缓存的完整结果；边界落库失败时所有等待者都必须收到失败，不能有调用方提前看到 completed。
- 导演进度是章节生产结果的只读投影：只有当前正文 hash 的资产连续性边界、状态提交和可审阅/已批准事实同时存在时，章节才计入完成范围。草稿存在、旧版 `approved` 或其他过期产物不能替代当前版本闭环；明确 `degraded` 边界可继续生产，但必须在投影中保留降级事实。
- 流水线的 `skipCompleted` 也只跳过上述当前版本闭合章节。旧终态记录没有匹配边界时，恢复会保留已有正文并补齐审校或连续性收尾；范围已经全部闭合时，恢复任务应直接成功结束。
- `runtime/artifactSync/` 提供正文版本 hash 与连续性边界的稳定契约。导演只从该契约读取事实，不能反向导入或解释后台同步的执行细节。
- 资产回灌按“版本化抽取结果 + 逐消费者应用检查点”恢复：抽取输出先持久化，失败恢复只补未完成消费者，不能重复调用模型；每个最终写入点还要核对当前正文版本，正文已变更时以失败边界收束，不把旧结果写回当前章节。
- 问题事件只有在流水线状态或控制流真正采用对应动作后，才允许登记为已执行。
- 章节自动处理额度由 `attempts/` 持久化拥有，质量修复与运行异常重试须在调用前领取同一 job + chapter 的唯一预约；重入不得仅将局部计数清零来恢复额度。
- 导演 Worker 租约只负责重新挂接监督命令，不另设章节重试次数。任务绑定的流水线仍可恢复时，导演恢复应复用原 job；任一侧已进入人工恢复状态时，后台恢复不得清除暂停。
- `executionLease/` 持有 job 级跨进程执行所有权。调度器领取后才能进入执行器；租约续期只允许当前且未过期的 owner，并且到期时间只能向后推进。所有 owner 常规状态写回还必须确认作业仍处于可运行状态、未取消且未人工暂停。
- 旧执行者失去租约后应静默退出，不得把新执行者的任务写成失败；租约存储不可用时须在模型调用前转入人工恢复。
- 取消收尾使用独立的条件写入，只能收束已取消或已有取消请求的作业；成功、失败和进度写回不能覆盖并发到达的取消或人工暂停。
- 逐章预约只约束自动修复和运行异常重试，job 级租约约束首次生成和完整章节循环，两者不能互相替代。
- OpenAI 兼容客户端不执行隐式网络重试；结构修复、JSON 修复和业务重试均保留为显式调用。只有供应商返回 usage 的调用可精确累计，网络失败不得伪造物理请求或计费次数。
- 从简易自动创作交接专业工作台只能在章节落库边界生效。
- 延迟角色、世界和规划增强的优先级低于正文、审校、修复和下一章执行前 JIT。
