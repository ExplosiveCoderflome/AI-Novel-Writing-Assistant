# V1 自动资源确认

全自动创作在已保存正文的资产同步完成后、处理章节质量提醒和推进下一章前，核验本批次的资源提议。最后一章也必须经过这一边界。

`DirectorResourceConfirmationService` 负责冻结任务、正文作业和章节范围的归属检查，以及按任务与正文版本保存核验检查点。它仅接收 V1 全书自动模式的成功作业；V2、半自动、人工工作区作业、人工恢复锁和受保护正文不能提供自动确认权限。

持久化任务通过 `state` 公共入口读取 launch/run 状态，不能在自动执行模块直接解析任务载荷。调度和资源写入复查使用同一个共享模式权限，避免临时请求与保存模式各自维护自动确认条件。

故事事实由已注册的 `director.state_proposal_resolution` Prompt 判断，不通过事件名称、词语匹配或资源名推断是否可信。核验上下文包含保存正文、相关角色、精确资源键对应的当前账本和书级约束；未出现待确认提议时不调用模型。

AI 选择可信提议后，`StateCommitService` 在事务内复查任务归属、正文版本、提议来源、资源冲突和提议状态，再同步账本、事件和提议。消耗、失去或局部正文质量提醒不直接等同于人工确认；高风险、低置信度、无证据和资源状态冲突继续保留为待核验事项。

AI 核验失败或只批准部分提议时，保留未确认提议，不改变成功章节和全局导演状态。正文版本变化或执行归属失效属于完整性问题，必须拒绝写入。检查点防止同一正文版本反复调用 AI；历史提议不通过读取页面或批量 SQL 直接确认。

公共入口为本目录 `index.ts`。详细规则见 `docs/wiki/workflows/director-v1-resource-confirmation.md`。
