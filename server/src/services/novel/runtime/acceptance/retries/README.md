# 章节检查重试边界

本模块只拥有初审与修文复验的额外请求额度。正文生成、局部修文、资料同步和任务恢复的额度仍由各自模块负责，不能把检查额度当作整章全部 AI 调用数。

`ChapterReviewRetryBudget` 负责请求预约和结果标记，`ChapterReviewRetryStore` 负责既有检查点表的比较更新。外部从上一级 `acceptance/index.ts` 使用；底层模型调用仅依赖 `platform/llm/retries` 的通用请求上下文，不依赖小说或数据库服务。

初审和候选复验各有一个正常首次请求，其余格式纠正、证据纠正、协议重发、备用模型和传输重试共用单章最大次数。0 次只允许正常首次请求。重试是发出请求前的预约，进程在预约后退出也不退还；恢复同一作业不得重新获得正常首次请求。

预约用 `chapter_review_retry_budget:v1` 检查点保存，身份是小说、章节和 generation job；contentHash 列承载作业标识，不能换成正文 hash。原稿与候选稿、协议和 Prompt 版本变化都不能重置本作业额度。数据库中的策略是已冻结快照，加载实例时传入的新默认值不能覆盖它。

每次真实请求前先执行取消和 Token 预算检查，再保存预约。预约损坏、写入失败或并发更新无法收敛时抛出 `ReviewRetryPersistenceError`，按数据完整性问题停止，不能吞为普通审校不可用。Token 和取消保护保留原始错误身份，不得伪装成检查耗尽。

格式修复携带当前检查的完整原始任务和报告，不能在没有正文的情况下补造证据。语义纠正携带最新错误报告，但不累积整个失败对话历史。报告是否可信仍由既有 AI 合同和原句校验决定。

耗尽摘要随定稿收据保存。生产质量闭环依据快照决定继续或暂停；跳过不等于通过，候选复验失败仍保留原稿。V2 的显式次数暂停使用 `retry_policy` 来源，普通完成优先质量债仍不可自动升级为全局暂停。更多说明见 [章节检查重试策略](../../../../../../../docs/wiki/workflows/chapter-review-retry-policy.md)。
