# 重规划编排边界

本目录负责把显式重规划请求解析为章节窗口、逐章调用规划生成并记录重规划运行。是否停止全书的确定性判断仍由 `replanDecision.ts` 负责；本编排层不得把 payoff 逾期或局部质量债自行升级为全局停止。

`PlannerService` 保留公共门面，并以最小适配接口向本模块提供规划读取和生成能力。调用方不得绕过门面直接拼装重规划持久化流程。

`context/` 是重规划决策输入的纯投影，独立于编排和持久化。审校报告保留报告身份、章身份和全部问题；相同的结构化评估只存一次，由 assessmentIndex 引用，解析失败的历史评估保留原始值。不得根据文本关键词删问题或选择章节。状态快照必须是完整合法 JSON；任意字符截断会丢失尾部伏笔与保密约束，不能用作上下文预算策略。

`ReplanStateContext` 将书级合同与世界规则基线放在动态原因之前；当前处境、人物、冲突、时间线仍从本次快照读取。伏笔列表仅共享完全相同的记录，通过 `payoffStates` 的零基索引表达 pending/urgent/overdue 归属，列表顺序与重复成员保留，同 ID 的不同版本分开存放。这是 Prompt 投影格式，不能写回 canonical state 或替代持久化契约。

决策服务将状态、审校、账本、章节目标和保密约束作为必需且禁止摘要的上下文块发送，纳入输入估计；超过可选上下文预算时保留完整约束，而不是裁掉尾部事实。调用仍只执行一次窗口决策，不为缓存追加预热或重试。供应商实际输入与缓存报告仍是用量判断依据，字符数或估计值不是计费 Tokens。
