# 规划持久化

`contract` 拥有执行合同哈希、任务单/场景投影与持久输入结构；`storyPlanStore` 只对传入客户端执行计划和场景读写；`index` 提供旧默认事务和显式事务内的单章入口。外部沿用 `plannerPersistence` 兼容门面。

旧调用仍自行开启原有事务。新调用必须提供事务客户端和 before/after 归属检查：before 负责锁定运行与输入版本，after 再次验证执行权限。新入口不创建嵌套事务，调用方可把业务结果与自己的提交回执原子保存。检查抛错应使整个调用方事务回滚，不能在捕获后继续提交。

该模块不解释导演策略、作业身份或回填阶段，也不包含模型调用。
