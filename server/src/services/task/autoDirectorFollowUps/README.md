# 自动导演跟进与通知

本模块解释任务的跟进原因、可执行动作和通知投递，不能自行生成正文或修改导演状态机。

- 根入口服务负责投影、事件订阅过滤、投递去重和动作日志；DingTalkNotifier / WeComNotifier 负责官方机器人协议与传输，内部通知对象只用于模块协作和投递记录。
- `channels/feishu/` 拥有官方 SDK 的长连接生命周期、卡片构造、平台操作人映射与卡片结果更新。后端启动/停止和设置保存事件驱动连接生命周期。平台回调复用根动作执行器，不直接操作导演仓储。
- `application/v2ChannelAction.ts` 是原生 V2 Run ID 到 V2 命令服务的应用适配器，负责版本检查、动作映射和幂等重放。它不把旧 workflow ID 翻译为新的 Run，也不修改通用内核或恢复事务。
- 渠道配置由 settings 服务拥有；通知依赖配置读取和变更订阅，settings 不反向导入通知或导演服务。

新增平台协议放在 `channels/` 下，不继续增加根目录同级适配器。新动作先扩展共享动作契约，再实现各导演版本的应用入口。人工暂停只能由明确操作解除，投递失败不得阻止自动导演完成小说。

完整边界见 [开发 Wiki](../../../../../docs/wiki/workflows/auto-director-channels.md)。
