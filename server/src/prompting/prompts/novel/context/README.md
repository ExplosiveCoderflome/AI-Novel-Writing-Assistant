# 章节 Prompt 上下文模块边界

## Background

章节规划、正文生成、验收与修复需要共享同一份运行时合同，但合同构建、历史兼容与 Prompt 文本渲染属于不同责任。将它们堆叠在单一文件中会扩大修改影响面，也容易让旧运行包兼容逻辑与具体 Prompt 表达互相污染。

## Decision

- `chapterLayeredContext.ts` 是稳定门面，负责构建书级、卷级和章节级合同，并保留外部兼容导出。
- `chapterContextPolicies.ts` 负责旧运行包归一化、默认值投影和写作所需角色硬事实筛选。
- `chapterContextBlocks.ts` 只负责把结构化章节合同渲染成 writer、review、repair 可消费的上下文块。
- `chapterHistoricalContext.ts` 负责历史参考窗口和重复账本提醒的无损共享。

## Current Rule

1. 新的读者体验、章节义务或连续性能力先进入共享结构化合同，再由上下文块渲染层消费。
2. 历史兼容只放在策略层，不能在各个 Prompt 渲染函数中重复添加分支。
3. 外部模块从 `chapterLayeredContext.ts` 门面导入，不深度依赖 `context/` 内部文件。
4. 普通章节读感问题只能形成本章修复建议或质量债；只有结构化决策明确要求重规划时，才允许影响全局执行链。

## Failure Modes

- writer、review、repair 分别拼装不同版本的章节目标，导致验收和修复偏离正文任务。
- 在渲染层临时猜测缺失字段，使历史兼容规则无法统一测试。
- 将 Timeline、Fact Ledger、Payoff Ledger 与读者体验合同混为同一责任，造成上下文重复和错误质量告警。

## 复用范围

文风合同以结构化来源声明 book；场景、角色事实、资源、义务和近期状态缺省 request。布局在预算取舍之后进行，同层保持声明顺序，不能为提高命中冻结任何内容或复制全书上下文。参考 core/cache 的边界规则。

## 当前合同与历史参考

- 本章任务单、必须推进、必须保留和收尾要求在 `chapter_mission` 中完整发送，禁止预算摘要。历史事实不得放入该必需块，避免历史增长挤掉其尾部任务。
- `completed_milestones` 仅提供近期已完成事项参考，最多 24 条、事实正文合计 1,600 字符，按源列表从后向前选取完整且去重的事实；不截断单条、不改原数组。预算不足时整个参考块可省略。这个窗口不是全书事实全集；缺席不表示未发生。
- 长期事实仍保存在事实账本及相关章节资料中。当前角色硬事实、当前状态、明确的章节义务、位置来源、保护秘密、伏笔操作指令和修文世界约束继续走各自的正式块，不能因历史参考预算省略而撤销。
- `payoff_ledger` 是关注提醒，不能自动成为本章必须兑现的义务。正式动作仍来自 `payoff_directives`、`obligation_contract` 和章节任务。提醒块预算不足时整体省略，不产生只剩编号却缺失内容的引用。
- 多个提醒列表的完整展示内容相同时只写一份正文，用编号保留各列表成员、顺序与关注级别；不同展示事实保持独立。不能按同一个 ID 强行合并不同事实。

## 用量与恢复

最近一章的正文是审校和修文的必需事实源，通过 `previousChapterContent` 传递，在 `recent_chapters` 完整渲染，不摘要、不因预算丢弃。没有正文的历史运行包才使用最近一条摘要。只保留一章，避免全书历史无限进入每次检查；writer 继续使用原有摘要与章尾窗口，不重复注入整章。真实输入增加须计入既有单章预算，不能声称零成本或用缓存命中抵消安全额度。

上下文预算只约束参考材料，不授权截断当前合同。必需内容超出估算预算时仍完整保留，真实模型输入输出量继续由单章 100,000 Tokens 预算控制。缓存命中属于输入用量，不能抵扣安全计数。修文后的候选需要独立复验；暂停任务只能显式恢复。

修改块内容、摘要策略或 Prompt 版本后，检查分层上下文、审校缓存身份、稳定前缀和高级模板兼容，并同步受影响资产的精确注册版本。字符估算和合成窗口测试不能作为真实 Token 降幅证据。
