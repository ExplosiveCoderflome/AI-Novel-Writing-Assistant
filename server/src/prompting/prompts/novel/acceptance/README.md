# 修文复验证据合同

## 背景与边界

首次审校的证据属于原稿。把它与候选正文一起直接呈现，容易使模型复述旧结论，甚至把已删除的标点或已补入的动作继续列为缺陷。本模块由 Acceptance 注册资产使用，负责核对清单、结构化结果与确定性证据校验；不调用模型、不写数据库、不决定剧情是否成立。

## 规则

- 复验输入保留首次问题 code、修复要求、义务 kind/summary 与指令；渲染时去掉历史 evidence，清单放在完整候选正文之后。
- 模型返回 `repairVerification`，原样回传候选正文 SHA-256，对唯一的 issue/obligation 标识逐项给出 resolved/unresolved、当前原句和判断理由。
- 同一 code 或 kind/summary 只需核对一次；遗漏、重复、未知标识及错误正文身份均无效。
- 原句引用最长 350 字；仅忽略空白差异，不能更换文字或标点。所有复验核对项、仍未解决与新增的问题/义务都必须引用当前正文。
- resolved 项不能同时列为缺失；有 unresolved 项不能声称 accepted。证据来源校验不能证明语义正确，剧情判断仍由 AI 完成。
- 首次审校不要求复验字段，保持已有输出兼容。

## 失败语义

证据校验失败抛出专用异常。验收资产声明格式修复与语义纠正共享一次额度：已经执行格式修复就不再追加语义纠正；语义纠正不再带一轮格式修复，备用模型的格式修复额度为零。未声明共享额度的其他资产保留原有策略；协议降级仍遵守 LLM 层设置，不表示全链路最多两次计费调用。

首次验收输出上限为 4096 Tokens，修文复验为 6144，以容纳逐项核对清单；证据应优先使用足以定位的短原句。实际调用与审校缓存身份共用同一额度解析函数，避免输出被截断后反复格式纠错。额度增加只允许模型完整返回证据，不改变单章用量暂停或用户追加授权。

纠正仍失败时，修文身份、事实保护和跨章证据核对不可绕过：服务保留 `acceptance_gate_unavailable`，追加安全的细分类诊断；候选不能取代原稿。只有写法报告失败而其他校验均有效时，清除未验证的 voice 建议，保留独立剧情结论并记录 `style_review_unavailable`。两种降级都不能缓存为成功，也不能将待复查项目当作正文补丁目标。

候选选择必须拒绝把不可用复验的兜底分数当作改善证据。保留原稿、原审校、质量债与最终资产来源；不放宽完成优先/质量优先的既有政策，也不覆盖已保存正文。外部从目录 `index.ts` 使用能力，业务服务通过注册资产导出的异常识别失败类别。

## 跨章事实核对

存在上一章正文时，同次验收返回 1-4 项 `continuityChecks`，分别引用前文和当前正文，判断一致、冲突或不确定。冲突须引用同次 continuity 问题编号；程序仅核对来源及引用，不能用词语匹配替代 AI 语义判断。上一章未提及的信息不自动等于明确不存在。历史输入没有完整前文时保留兼容，不能伪造跨章检查已执行。
