# 模型能力适配边界

本模块只描述模型接口能力，不识别创作意图，不决定业务任务走向。

- `profile.ts`：Zod 合同和厂商／完整模型名／可选主机的身份键。模型家族识别去掉 `vendor/`，存储身份保留完整模型名，防止网关别名串用结果。
- `defaults.ts`：思考控制与保守能力默认值。现有结构化输出的细分端点规则仍由 `structuredOutput.ts` 维护；后者先应用已加载档案，再使用原有启发式。
- `store.ts`：通过 `appSetting` 保存探测和用户覆盖，覆盖优先；串行累计同进程的失败模式，成功写入后更新缓存。
- `adapter.ts`：把结构化思考控制提示转换为请求参数。业务层不应按模型名拼参数。
- `probing.ts`：探测能力的外部入口；`probe.ts` 负责小请求、异步任务与最近状态。真实网络必须显式同意，启动应用不会探测。
- `http.ts`：设置页接口，沿用设置路由的鉴权与校验。

`factory.resolveLLMClientOptions` 在构造参数前加载档案，保持现有同步能力查询函数兼容。调用层通过 `index.ts` 使用档案与适配参数，通过 `probing.ts` 触发探测，避免业务模块依赖存储细节。

调用顺序与安全边界见 [模型兼容性合同](../../../../docs/wiki/prompts/model-compatibility.md)。
