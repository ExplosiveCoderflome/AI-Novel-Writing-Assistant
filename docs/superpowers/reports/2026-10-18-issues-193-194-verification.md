# #193 / #194 修复范围与核验

## 基线与原因分类

基线为正式版 v0.5.12、main/beta 同一提交 `d1c467a4`，开发分支为 `codex/fix-issues-193-194`。两项主因均为功能闭环缺失，正常产品路径可以再次产生，不属于仅需清理的脏数据。

- #193：回答提交只更新旧版世界文本与问答状态，结构化手册和阅读视图继续读取旧内容；页面清空草稿且没有提交反馈，旧问答再次出现时也不回显已保存回答。诊断阶段以实际服务代码和内存 Prisma 替身复现了“回答已保存、结构化内容未更新、重复提交再次追加”。
- #194：生产计划把准备章节路线声明为覆盖已有任务，而接管资料统一带保护标记；拆章步骤不可门控，受保护任务或过期路线不能进入已有确认门。按真实生产计划构造第 34–36 章范围时，显式恢复后仍选择相同步骤并再次拒绝。Issue 截图没有运行 ID，不能据此确定该用户实际是哪项资产触发。

## #193 的完整边界

阶段提交：`a316b37d`。

- 注册 `world.deepening.integrate_answers@v1`，接收当前手册、来源资料与明确的问答，由 AI 输出稀疏结构变更和逐题总结。沿用来源页选择的厂商、模型，不依据旧字段标签执行语义路由。
- 结构更新保留未涉及的字段、实体、地图与既有关系，集合按 AI 给出的 ID 合并。非法实体、悬空关系、缺少逐题结果或没有有效变更均不能落成“已整合”。损坏的手册 JSON 不得被空结构覆盖。
- 模型调用在事务外；写入时核对原手册版本、更新时间、结构和问题更新时间。手册、兼容文本、回答状态和快照同事务保存，并发修改或任一步写入失败均回滚。
- 版本化整合回执保存摘要与回答哈希；同一回答重放不再调用模型，旧纯文本问答仍可显式重新整合。样本整合不会自动推送覆盖小说内的世界副本。
- 页面回显已保存回答和整合摘要，提供成功/失败反馈。成功只清理本次提交且内容未变化的草稿；请求进行期间新输入的内容继续保留。

## #194 的完整边界

保留已有内容的路径采用安全补缺，不新增无法完成的确认门，也不取消保护标记。

- 生产计划以 `preservesInChapterRange` 声明有效正文授权下的节奏准备与路线补缺合同。仅这些适配器可在保留已有资料的前提下补缺；没有有效章节范围的整卷重生成和其他步骤继续受保护守卫约束。
- `NovelVolumeService.appendMissingRoutes` 在事务中重新读取最新规划，只追加缺少的卷、节奏与章节。已有卷属性、章序、标题、任务、场景和正文保留；正文表只补建缺少的空章节，规划链接与工作区一起保存。
- 规划读取关闭 Chapter 字段回灌；生成候选不能在保留性合并前提前保存。`persistIntermediateDocuments=false` 同时禁止中间和最终候选自动写入，其他调用方保留原默认行为。
- 连续窗口同时核验规划与实际章节；完整规划缺少执行行时只补空行，不重新调用 AI。候选没有增加可用连续路线时结束本次尝试，避免循环生成。
- 新路线产物继承原保护标记。旧暂停仍等待用户在本书导演台显式点击“从保存进度继续”；后台轮询、Worker 重建和运行记录页面不会解除暂停。
