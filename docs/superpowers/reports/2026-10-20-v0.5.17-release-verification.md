## 修复

- #196：章节 writer 只输出一条位于首位的 system 消息，篇幅和补写要求继续保留，适配严格聊天模板。
- #198：对 AI 已输出的题材和叙事模式目录名称、序号进行确定性规范化，避免名称附带序号时无法正确采用推荐结果。
- #199：开书确认从已有创建信息恢复预计章节数；请求和候选都缺失时归一化为有效默认值，使新书和冻结执行范围一致。
- 测试契约同步：修正旧 writer 消息下标断言、开书测试依赖装配，加入真实缺省章节数覆盖，将 #196 独立回归登记到质量门禁。
- 缓存测试区分仅改变章节任务与改变篇幅参数：前者验证稳定前缀，后者验证首位唯一 system 携带新要求；两者都纳入门禁，产品 Prompt 不变。改变模式或篇幅参数会改变系统输入及其缓存身份，不能承诺此时完整前缀仍相同。

## 额外快速入口的验证边界

正式发布工作流不运行默认 fast 入口。本轮额外在新建且已迁移的临时 SQLite 上运行该入口，2215 项中 2191 通过、12 失败、12 跳过；不能宣称完整测试集全绿。

为判断是否由本版引入，聚焦这 12 项所属的七个文件。它们自身自 v0.5.15 起无变化；v0.5.15 与候选之间也仅有五个产品模块变化，其余产品源码、依赖与迁移一致。在独立测试子进程中，以只读加载覆盖方式恢复这五个模块的 v0.5.15 源码与编译实现，保留真实依赖及隔离数据库；没有重建旧版安装包，也未改写当前源码。

旧实现与当前实现各运行同样 66 项对照，均 55 通过、11 失败，失败名称完全一致，涉及拆书命令夹具、修文提醒、旧规划与管线断言、前端简化阈值等历史检查。额外 fast 中失败的 RAG 设置路由在两轮对照均通过；可能受并发或夹具交互影响，具体原因未确定。原始日志为私有 `fast-ready.log`、`v15-baseline.log`、`current-control.log`，比较结果为 `baseline-comparison.json`。

本版新增的 writer 缓存断言问题已修正并进入最终 569 项质量门。上述 11 项历史失败与一项未稳定复现的额外检查保留为测试债；不扩大本次发布范围修改无关业务，也不把对照通过误报为 fast 全绿。发布依据是项目规定的质量门禁和本次变更的定向检查，GitHub 发布工作流仍在公开上传前重复规定检查。

GitHub 工作流会在公开上传前执行类型检查、构建、迁移、质量门禁和包布局验证。按项目约定，推送并触发后交付标签和工作流链接，不默认等待、轮询打包结果或建立监控。本报告不作为新安装包上传完成的证据。

本轮不修改开发库、小说正文或模型配置，不调用付费模型，也不执行 UI、真实供应商或新安装包验收。用户已有 `_chat/`、私有协作规则及中央记录均保留本地。
