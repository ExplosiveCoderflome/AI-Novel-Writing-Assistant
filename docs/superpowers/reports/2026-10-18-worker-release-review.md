# Worker 发布前复审与补修

## 范围与主因

用户授权复审当前修复，有问题先修复，再发布新版本。基线正式版为 `v0.5.14` / `3d0a9fc9`，待发布修复为 `a0ee06d0`。远端 main/beta 没有其他新提交，未混入历史分支草稿。

主因分类：实现缺陷。本次复审在单次租约收尾和领取时序中确认三个边界错误，均先以故障注入测试得到失败结果，再修改共享执行边界。

| 边界 | 失败证据 | 修复规则 |
| --- | --- | --- |
| 步骤完成时续约仍悬挂 | close 清除到期计时后 await 心跳，tick 超过测试观察窗口仍不返回 | 业务执行已收束后立即关闭会话、撤销作用域并释放当前 owner；不等待悬挂心跳。迟到结果被关闭标记忽略，独立 owner 不能影响下次领取 |
| 服务停止期间领取才返回 | stop 在 acquireLease 等待期间执行，返回后仍调用一次业务执行器 | 成功领取后复查停止状态，只撤销与释放，不启动业务；领取前也复查停止状态 |
| 领取返回时租约已到期 | 定时器设置为零延迟，但执行器先被调用，tick 错误返回成功 | 已到期同步撤销，不依赖下一轮定时器；续约返回也遵守同一规则 |

正常产品路径遇到慢数据库或关闭服务时可产生上述竞态。它们属于设施时序保护，不能据此认定 Issue #195 报告者的原始触发原因；对应时段日志仍缺失。

## 复审范围

- 逐项检查原四处修复的 Worker 生命周期、心跳串行与独立 owner、LLM/Prisma 撤销作用域、queued 投影、retry_start HTTP/事务/客户端接线及生产装配。
- retry_start 保持 queued 专用，校验版本、有效租约、小说执行世代；人工暂停、确认门、运行中及终态不能经此恢复。运行记录仍只读。
- 没有依赖、锁文件、迁移、桌面主进程或打包工作流变更。没有改动用户数据、API 配置或模型预算，没有付费调用。
