# 章节细化误判修复与真实生成核验

## 范围和证据

2026-10-21，以 `f2beb8ef`（`v0.5.18`）为基线，在独立分支 `codex/fix-issue-170-refinement` 检查最新 Issue。

- 按创建时间最新的 [#200](https://github.com/ExplosiveCoderflome/AI-Novel-Writing-Assistant/issues/200) 已有单章预算配置修复，未发现新的后续反馈。
- 按更新时间最新的 [#170](https://github.com/ExplosiveCoderflome/AI-Novel-Writing-Assistant/issues/170) 于北京时间 23:02 收到无法继续细化的反馈。原始两张附图分别要求不存在的 `readerExperience.sceneCards` 层级、固定章末钩子格式，并对合法的 `mustAdvance` 数组提出类型异议。

主因分类：审核输入协议不明确，导致 AI 可以把合法存储结构误当作内容冲突。共享合同实际是 `{ targetWordCount, lengthBudget, scenes, readerExperience }`，其中 `scenes` 与 `readerExperience` 同级，场景推进要求为字符串数组。旧审核输入只有 `sceneCards` 标签及一段 JSON 字符串，没有说明正文解析后的契约。

未取得报告者的完整原始章节合同或原始模型响应；本轮同一有效样本在旧提示下的两次真实审核均通过，不能宣称稳定复现了报告者现场。修复针对附图中可证伪的结构要求和当前代码缺少的输入约束，不承诺所有模型与所有小说均不再误判。

## 修复边界

- 审核使用正文共用的 `parseChapterScenePlan`，将明确的 `candidate.scenePlan` 对象交给 AI，保留任务、章节边界及上一章事实。
- 说明场景与读者体验的真实层级、数组类型、自然语言钩子及章级与场景级目标允许呼应的关系。
- 程序负责结构校验，AI 继续负责具体内容缺口、实际矛盾、前文承接和职责过载。没有根据关键词过滤审核意见，也没有放行所有合同。
- 质量资产更新到 `novel.volume.chapter_task_sheet_quality@v5` 并同步注册；无数据库迁移，无客户端行为修改。
- README、日期发布说明及读者体验合同 Wiki 同步；桌面候选版本由官方脚本升至 `0.5.19`。

## 真实生成

按用户本次明确要求调用已配置的 DeepSeek。源开发库只读打开，仅复制表定义和一个已启用的供应商配置到新建临时 SQLite；起始小说数量为 0，没有复制或写入用户小说。测试脚本没有替换模型、Prompt Runner 或生产依赖。

| 步骤 | 实际结果 |
| --- | --- |
| 旧提示基线 | 有效样本在副驾、全自动模式各审核 1 次，均可用；不作为问题稳定复现证据 |
| 新提示正例 | 同一有效样本在副驾、全自动模式各审核 1 次，均可用 |
| 新提示反例 | 合同要求先烧毁全部凭据、再使用完好原件；副驾审核识别真实矛盾并阻止执行 |
| 真实细化 | 正式 `generateChapterTaskSheetDetail` 生成 4 张场景卡，审核通过；数组推进要求和章末悬念保留，计划目标 2200 字 |
| 正文生成 | 正式 `ChapterRuntimeCoordinator.createChapterStream` 完成上下文准备、正文生成、接收检查与保存，首稿 3002 个含标点及换行的字符 |
| 正常修文 | 首稿有省略号风格问题；人工核验发现结尾账目需明确按争议实收数量计算差额。通过正式局部修文入口调用 AI，保留原始测试稿和检查记录 |
| 最终接收 | 修文后 3065 个含标点及换行的字符，评分 84，最新审核无开放问题；`generationState=approved`、`chapterStatus=completed`，场景合同保持一致 |

实际测试小说为《青石账房》，仅生成并接收第 1 章，不代表整本书测试通过。共记录 17 次实际调用、74,249 原始 Tokens，其中供应商报告缓存命中 15,488；计量包含基线、正反审核、细化、正文、修文和资料同步，不等于单章正文成本，也不是账单金额。主模型为配置的 `deepseek-v4-flash`，默认伏笔同步使用 `deepseek-flash`。

样本正文高于计划字数：首稿去空白 2912 字符，修文后 2975 字符，不能据此宣称严格达到 2200 字目标。本次没有改写作长度控制；该样本用于检验细化合同能否进入真实正文和正常修文链，不构成全量内容质量或整书稳定性保证。

最终临时库 `quick_check=ok`。模型配置、数据库、原始日志、测试正文和私有协作记录均不提交或打包。
