# 正文生产内核计划 02：领域层实施与验证

2026-10-22，Asia/Shanghai。分支 refactor/production-kernel；HEAD 8b1ecd86，修改保持未提交。当前代理独立实现与自查，没有子代理或独立审查者。

## 实施结果

- 修复两处选稿契约：额度只限制下一次修复，不能跳过已有候选的复验/选稿；显式动作保存最终选稿、正文哈希和原因，纯决策不修改输入。
- 新增领域类型、Zod 配置校验、纯状态转换、下一动作、候选比较、具名质量规则和回放。配置 ID 去重通过显式已定义集合校验，不建立隐藏全局注册表。
- 修复失败或无变化保留已用次数；有变化候选即使额度用完仍进入 verify/select。复验未知、事实不保留、新增严重问题或义务缺口、表达退化等情况保留原稿。
- 原稿通过时不绕行候选 select；人工编辑阻止旧稿提交。重复结果幂等，冲突选稿/哈希/复验结果拒绝。回填 pending 可重入，失败不伪装完成。
- 五份手工结构化夹具覆盖直提、采用候选、保留原稿、审校不可用、全书重规划。它们是合成回放，不是历史真实模型样本，也不是新旧流水线等价证据。
- 模块 README 和现有 Runtime 边界 Wiki 记录长期职责。没有产品入口接入或用户可见变化，本轮跳过 README 最新更新和公开发布说明。

## 保护与局限

没有连接业务库、执行迁移、调用真实模型或做 UI 验收，没有改 V1/旧生产代码。现有自动与手动入口继续走原链路。

领域进度尚无真实持久化；序列化测试证明状态合同，不证明跨进程恢复、预算预约、物理请求次数或事务围栏。IssuePolicySnapshot 是独立的结构化领域合同，完整旧策略与问题动作的映射必须在适配器阶段明确并验证，不能直接以简化字段替代旧快照。
