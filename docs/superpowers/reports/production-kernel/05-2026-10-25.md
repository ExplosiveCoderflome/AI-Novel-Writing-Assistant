## 已完成

- 真实 chapter_batch 入口按持久绑定调用内核。关闭开关的新批次和已有旧作业保持 legacy；已绑定的 kernel 批次跨进程恢复时不受开关变化影响。批次制品哈希与来源页确认使用相同算法，不创建虚构 GenerationJob。
- 原生运行时捕获完整契约、全量问题策略、明确主备模型和有效配置。Chat 请求安装完整 Prompt 预检、物理预算与用量观察；每次核对当前书 epoch、worker 租约、单章版本/领取及完整正文。新增反例证明改变单章领取后不能继续发送。
- 收尾复核以反例发现装配仍引用调用方的可变上下文；现已捕获独立的契约、控制和 worker 副本，返回的请求/端口也分离单章引用。后续调用方对象变化不能改变已捕获配置或执行身份。
- 原生装配安装已批准的合同/章规划准备端口、上下文组装、平台合同与 context broker、注册 writer、接收闸门、安全补丁、统一抽取、人物身份处理、十类消费者、完整规范版本和时间线，以及按风险触发的全量伏笔对账。
- 复用原生人物服务时，将 callback 事务绑定到当前内核事务。待确认错误在提交后传播，使辅助模式的确认记录不会随暂停丢失；重复调用不重复创建候选。当前 worker、单章领取和完整原文的检查不能由旧服务较宽的检查替代。辅助人物未处理时，来源页恢复在同一命令事务内拒绝。
- 全局重规划的显式恢复只接受较新已保存路线、未提交且未被编辑的正文；归档旧决定和制品，重新准备章节，保留冻结策略与已发生用量。较旧路线、已提交正文、人工改稿和事务回滚均有验证。
- 阶段输出额度预检不重复收取物理请求预约。统一抽取与完整伏笔对账分别保留主模型实际输出上限和备用模型最大预约额度，防止备用额度意外放大主模型请求。

## 真实入口验证及限制

新增三项跨进程临时 SQLite 联测，使用真正的 productionComposition、上下文、PromptRunner、接收服务、生命周期和事务消费者，提供方 SDK 传输为明确替身：

1. 从空正文完成一章；重启并关闭开关后读取原完成结果，无重复模型、报告或旧作业。
2. 质量优先保存正文后暂停，来源页显式确认后只继续回填，不重新写稿。
3. 使用明确的既有付费用量夹具使剩余额度不足；真实入口保存未发送拒绝，来源页追加本章额度后继续完成，无旧作业。

以上场景 **RAG 关闭、伏笔账本已有数据、合同和章规划已保存可复用**。新生成准备/候选修复的恢复另有既有原生定向测试；不能把两组测试合称所有原生准备场景均已贯通。

实跑发现 getPayoffLedger 默认会在空账本时调用模型并写库。已授权 planner 来源使用已有 syncIfMissing:false 参数；冻结组装器的隐含请求由准备的拒发锁存保护。RAG 启用时在准备前拒绝，避免未经保护的 embedding/重排 HTTP 或集合补建。旧 RAG 和 PayoffLedgerSyncService 均未修改；正式开关不能在这些边界完成前启用。
