# 导演 Worker 四处缺陷修复核验

## 范围与原因分类

基线：正式 `v0.5.14` / `3d0a9fc9`。修复分支：`codex/fix-director-worker-recovery`。本轮用户授权先修复四处已确认缺陷，没有执行 beta/main 合并、推送或新版本发布。

主因分类为实现缺陷，次要因素为运行健康投影与来源恢复入口未闭合。Issue #195 的新截图显示 v0.5.14、DeepSeek / deepseek-flash、新书等待开始、0/7；这些缺陷可通过故障注入产生相同类别的停滞，但尚无报告者对应时段日志，不能把触发原因直接归结为其中某一项。

| 缺陷位置 | 修复规则 |
| --- | --- |
| `application/worker.ts` 常驻循环异常向外退出，应用启动层仅打印错误 | 循环按有限退避继续服务；隔离单个候选的归属/领取错误；重复 start 共享同一 Promise，显式唤醒中断等待；停止服务撤销在途执行 |
| 定时心跳没有捕获 Promise 拒绝，多个续约可能重叠 | `application/execution` 拥有单次租约会话，串行续约、捕获失败，独立到期计时覆盖悬挂的续约 |
| 心跳 false 被忽略，旧执行仍可请求模型或写入 | 每次领取使用独立 owner；失败/丢失/到期撤销执行作用域，合并 LLM AbortSignal、取消等待配额的请求、拒绝后续业务 SQL；正常收束也撤销遗留异步操作并按 owner 释放租约 |
| queued 只提示等待，没有健康说明和恢复入口 | 读取当前租约与进程健康，解释启动中、其他作品处理中、后台重试/不可用；在本书导演台提供 retry_start，事务校验版本、归属及租约，保留同一 Run、正文、范围和用量 |

## 安全与模块边界

- 设施恢复不会直接解除人工暂停，也不更改质量策略、章级修复次数或 Token 预算；中断后确需重做阶段时，仍遵循原有阶段恢复预算和保存事实。
- retry_start 只接受 queued；running、paused、waiting_gate 与终态拒绝。有效租约不可抢占，过期租约与旧版本/旧 epoch 分别验证。重复命令只重放，并请求幂等唤醒，不创建第二个 Run。
- 运行记录保持只读。命令按钮由服务端投影提供，仅在来源导演台渲染；GET 不启动 Worker，不协调任务状态。
- 应用内核只依赖取消端口。`infrastructure/execution` 经平台 facade 注入异步作用域，业务数据库和 LLM 适配器消费该信号；架构测试仅开放这个明确的基础设施依赖和纯类型 DTO，没有放开应用/领域导入其他业务模块。
- 取消前已提交的数据保留。AbortSignal 不能撤回已经发出的 SQL；事务内后续操作被拒绝时整体回滚。LlmInvocationUsageRecord 属于实际调用观察事实，取消后仍允许保存，避免漏记用量。
- 健康投影适用于当前单进程装配，持久租约具有优先权。健康处理其他书籍时解释串行等待，不让“重新启动”承诺抢占其他作品。
