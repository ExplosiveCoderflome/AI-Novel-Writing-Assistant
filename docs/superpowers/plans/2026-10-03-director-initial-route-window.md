# 导演首次正文路线窗口

## 要求

对齐继承规则 R16：正文关键路径只准备近期路线与下一章执行合同。只做规划仍允许整卷规划；两种行为从持久化正文授权范围决定，不使用界面偏好或关键词判断。

## 实现边界

- steps/planning/chapterRouteWindow 只适配注入的底层路线服务和卷读取服务，校验保存归属和连续章序后落账。
- app/director 的生产装配按 chapterRange 选择窗口或整卷适配器，模型来自同一 Run 快照。
- 授权第一章正文时，卷骨架请求只要求一个初始卷，保留全书目标和策略，远期骨架由现有滚动服务扩展。
- ChapterRouteWindowService 的目录可用数量来自连续章序，不能把远期目录当作当前窗口。
- 不改生成 Prompt、章节生成/审校/修复算法，不调用旧导演编排，不删除现有规划或正文。

## 验证

窗口测试覆盖模型快照、最低 3 / 目标 5、短范围、保存事实、缺口、重复及跨书拒绝。实际注册处理器测试覆盖生产窗口和规划整卷的区别，以及远期骨架延迟。底层服务回归先复现远期目录误算，再验证补齐当前缺口；保留已有未来骨架的检查。完整结果记录在清理前核对文档，真实 AI 及交互未验收。
