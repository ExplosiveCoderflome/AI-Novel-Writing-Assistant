# 03 回填适配：冻结边界的 G1 决策

状态：2026-10-22 用户明确批准“该回填边界方案，继续开发”。进入下述移植范围；此前批准的单表迁移和原子正文保存已通过临时 SQLite 验证。

## 发生冲突的具体位置

任务级计划 03 同时要求复用 `ChapterArtifactDeltaService` 及消费者，又要求“不得走进旧代码中的 V2 分支”。当前代码中的 V2 不只代表旧流水线调度：

| 现有位置 | 承载的能力 | 直接按 V1 参数调用的后果 |
| --- | --- | --- |
| `runtime/ChapterArtifactDeltaService.ts:125` getChapterArtifactConsumers | 人物位置与出场消费者 | 漏掉这两类资产回填 |
| 同文件 :324、:351 | 资源/对话影响读取失败时的严格处理 | 读取失败被降为空数组，无法保证输入完整 |
| 同文件 :359、:370 | 位置上下文和人物候选识别 | 不组装相关上下文，关闭候选识别 |
| `runtime/ChapterArtifactSyncService.ts:113`、:149 | 跳过旧名字匹配时间线和旧 RAG 投影 | 启用旧的文本名字匹配并写入另一套投影 |
| `state/persistence/StateProposalStore.ts:122` | V2 小说归属、正文哈希与资源确认保护 | 不能移除；盘点 B008～B010 已归为保留 |

因此不能把选项改成 V1 来“绕过分支”，也不能把整个旧协调器封装后直接调用。两者都违反设计目标。此次并未修改这些冻结文件。

## 建议的具体处理

批准 G1 范围内的移植，并明确将“旧 V2 生产调度”与“共享持久写入保护”分开：

1. `infrastructure/storyState/extraction.ts`：移植现有统一抽取的只读输入组装和已注册 Prompt 调用；位置、候选等能力来自冻结的 `profile.capabilities`，没有导演版本判断。不得重新引入文字匹配识别。
2. `infrastructure/storyState/reconciliation.ts`：移植恢复协调的“抽取结果 → 消费者检查点 → 各消费者应用”顺序；检查点按正文哈希、实际输入与运行身份绑定。恢复只补未完成消费者。
3. `infrastructure/storyState/consumerPorts.ts`：定义消费者接口。app 层注入已有的下层写入服务；允许这些服务继续执行盘点已归为保留的正文、归属和人工编辑安全保护。不调用旧 V2 流水线、自动继续或任务控制。
4. `infrastructure/stages/reconcile.ts`：只适配上述新协调器，返回 completed/degraded/pending/failed 结构化结果；正文提交完成不代表回填完成。

上述移植分成职责明确的文件，每文件不超过 400 行，预计新增 300～600 行；仅复用现有 PromptAsset，不改提示词。若剩余消费者含未盘点的生产调度依赖，必须继续报告具体边界，不能扩大为任意修改冻结目录。

任务级计划 03 的原句改为：不进入旧 V2 **生产调度**分支；允许复用已盘点为保留的共享持久写入保护。计划 08 仍只删除已迁走的旧调度，保留共享保护。

## 新增验收

- 临时库：同一抽取结果只生成一次；消费者 A 成功、B 失败后恢复只执行 B 及后续；正文被编辑、租约失效时拒绝回填；位置与出场两消费者不遗漏。
- 静态边界：新协调器无导演/工作流/短篇 import，无 directorVersion 分支；冻结目录零差异。
- 服务端构建、93 项现有生产测试回归，以及新适配测试。

批准此方案不会授权真实作品库迁移、beta/main 合入、开关启用或发布。
