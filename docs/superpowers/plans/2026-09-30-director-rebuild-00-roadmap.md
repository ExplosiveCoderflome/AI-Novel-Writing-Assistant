## 3. 执行协议（所有计划通用）

1. **一次只交付一份计划**；执行者不得提前做后面的计划。
2. **只改计划列出的文件**。任何需要改动其他文件的情况都是停止条件。
3. **测试就是完成标准**：不得修改、跳过、放宽断言。
4. **不得修改旧导演代码** `server/src/services/novel/director/`、旧路由、旧表，直到 08（仅允许在 `open_run` 入口处放置开关）和 09（清除）。
5. **提交**：一个 Task 一次提交；信息以 `优化：` 或 `新增：` 开头；只 `git add` 列出的文件；不得 `git add -A`。
6. **不要运行数据库迁移到开发库**。迁移验证只使用临时数据库；任何对开发库的操作必须由用户批准并先备份（`AGENTS.md` 数据保护规则）。
7. **不得使用子代理**；不得新增依赖。
8. **报告**：每份计划结束时按该计划给出的模板在对话里交付，不提交到仓库。

### 通用停止条件

| 编号 | 情况 |
| --- | --- |
| G1 | 需要修改计划范围之外的文件 |
| G2 | 需要修改、跳过或放宽测试断言 |
| G3 | 构建或类型检查因与本计划无关的原因失败 |
| G4 | 需要修改 Prisma schema、迁移或任何数据库数据，但计划没有明确授权 |
| G5 | 想使用 `any`、`@ts-ignore`、新增依赖，或 import 旧导演代码 |
| G6 | 计划内容与仓库现状不一致（路径不存在、函数签名不同） |

遇到任何停止条件，立即停止，写报告说明，不要绕过，不要自行决定。

## 4. 验收流程（我执行）

对每份计划：

1. 读取执行报告，但不采信。
2. 检查 `git log` 与 `git diff --name-only`，确认改动范围。
3. 重新编译，重新运行该计划声明的全部测试，核对数量。
4. 逐文件比对仓库内容与计划内容。
5. 按计划"验收者检查项"做变异检查或抽查。
6. 给出结论：通过 / 需返工（列出具体文件与原因）。
7. 通过后在本文件第 2 节更新状态，并细化下一份计划。

## 6. 全局约束（来自设计文档，所有计划隐含包含）

- 新内核位于 `server/src/modules/director/`，分 `domain/`、`application/`、`infrastructure/`、`http/`、`legacy/`；只通过各层的 `index.ts` 对外；模块内依赖方向为 `http → application → domain`，`infrastructure → domain`，`legacy` 只读。
- 单个源文件建议不超过 1200 行，超过 1300 行必须先拆分。
- 进度只来自产物台账与章节事实，不持久化"当前第几步"。
- 质量问题只产生质量债；只有明确重规划、无可用正文、安全或数据完整性故障才能暂停 Run。
- 人工暂停只能由 `resume` 命令离开。
- 语义判断（意图、质量、身份承接等）交给 AI 结构化输出；确定性逻辑只做输入校验、安全守卫与对结构化输出的后处理。不得用关键词或正则做创作语义判断。
- 用户可见文案用用户视角，不写开发或改动过程的叙述。
- 运行记录只读，不放置任何改变任务状态的动作。
