# 导演 V2 伏笔与角色资源迁移实施计划

**目标：** 按用户确认的顺序，在修复完成并保存最终正文后完成资源回填，再启动下一章；减少回填重复调用、伏笔整体校准与缓存前缀变化带来的 Token 消耗。

**设计确认：** 2026-10-08 用户确认开发。优先完成生产边界和回填成本优化；不新增每章独立的资源核验 LLM 调用。资产展示页面另行扩展。

**架构：** 保持导演领域内核与数据库、LLM、小说业务隔离。使用 app 装配注入章节生产业务端口；统一 AI 抽取归属章节运行时，应用继续使用共享状态服务。V2 通过作业显式选择必要回填策略，复用共享账本，不复制 V1 编排器或调用 V1 自动确认服务。

**创作原则：** 伏笔区分计划与正文证据，呈现铺垫、目标兑现范围和回收状态；资源表达所有者、持有者、当前状态、叙事作用与使用限制。读页面不调用模型、不补写资产、不恢复任务。局部核验失败保留待核对记录，不重写正文、不触发全局重规划。

## 范围与边界

- V2 入口核对同书身份、运行代次、正文作业所有者、授权范围和运行状态；共享资产应用继续核对当前正文版本。
- 统一 AI 抽取以唯一保留正文的证据返回资源和伏笔变化及结构化同步计划；应用复用既有提案校验和冲突核对。不新增每章独立资源复核调用，不把待核对提案伪造成已确认资产。
- 提交继续使用共享状态服务的事务、冲突核对和条件领取。保护作者资产，不绕过手动暂停或安全预算。
- 保存正文后的核验通过按正文哈希的持久检查点去重；失败有有限重试，不通过刷新反复调用模型。
- 不进行真实库回填或旧任务迁移。本轮只完善生产与上下文链，V2 伏笔、背包展示和待核对操作页面留给后续独立阶段；运行记录继续只读。

## 实施阶段

- [x] 生产边界：V2 显式选择回填策略；未完成的必要增量不能发布完成边界；V1 保留既有控制行为。
- [x] 恢复：按作业和最终正文版本持久化生产结果，回填中断后只重试未完成消费者，不重新生成、审校或修复。
- [x] 校准：V2 增量回填正常章不按固定三章重复对账；保留卷末与 AI 结构化要求的整体校准，并补齐模型和用量归属。
- [x] 缓存：稳定角色基础和资产目录在前，动态状态及正文在后；排序与序列化稳定，保留行动约束、秘密和可用性，不冻结过期状态。
- [x] 回归验证：隔离 DB/LLM 依赖的源代码测试及编译产物测试覆盖等待、失败、恢复、缓存前缀、版本失效和 V1 兼容；服务端构建和客户端类型检查通过。无数据库结构变化，无需迁移或真实库测试；UI 验收由用户执行。
- [x] 收尾：维护模块边界与 wiki，更新日期发布说明和 README；仅提交本阶段文件，不推送或合并。

## 验收标准

1. 修复候选稿不触发回填，仅最终保留正文回填一次；必要回填未完成时不能开始下一章。
2. 全自动当前章保存并同步后，可信资源变化自动用于后续上下文；不确定提案仍可在工作台核对。
3. 重启、重复恢复、重复提交不会重复应用资源事件，作者正文与其他书不变。
4. 阶段确认方式保留显式用户核对；局部资源问题不误变为导演失败或重规划。
5. 域层不增加小说业务依赖，不增加 V1 控制调用，真实开发库不参与测试。
6. 恢复复用最终生产结果与抽取结果，已成功消费者不再执行；当前正文变化使旧结果失效。
7. 同书相邻章固定输入前缀可复用，动态账本保持最新；提供输入命中、未命中与输出用量，实际命中比例由厂商返回验证。

- 9 个编译产物测试文件共 61 项通过：生产链与 V1 兼容、章节用量恢复、注册提示词、稳定前缀布局及缓存请求序列化。真实 SDK 测试替换 fetch，不发起厂商请求。
- 服务端 `pnpm exec tsc -p tsconfig.json`、客户端 `pnpm exec tsc -p tsconfig.json --noEmit` 通过。源码最后修改后取得的检查结果覆盖最终提交；仅文档和测试调整不重复构建。
- 无真实数据库写入、模型消费或历史资料补写。页面验收与新调用真实命中/未命中量由后续生成验证；不据布局测试宣称厂商命中比例已提高。
- 本阶段完成资源回填顺序、恢复和成本边界；伏笔/背包资产页面与新资源审核交互属于后续迁移范围。
