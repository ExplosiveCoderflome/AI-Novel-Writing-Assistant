# 05 原生上下文检索：外部请求与只读索引边界提案

状态：2026-10-26 用户明确批准两项边界并要求继续开发验收。既有准备端口批准覆盖非冻结 planner/volume 的单章规划接口；本文不重复申请该范围，不修改冻结的上下文组装器。

## 已核实的调用链

1. 冻结的 `GenerationContextAssembler.assemble` 调用 `ragServices.hybridRetrievalService.buildContextBlock`，异常会被捕获为空检索上下文。
2. 非冻结 `HybridRetrievalService` 的向量检索调用 `EmbeddingService.embedTexts`。后者直接 HTTP 请求，包含重试和自适应拆分；这些请求不经过原生 Chat LLM 的物理预算/用量观察作用域。
3. 可选 `RagRerankerService.rerank` 也直接 HTTP 请求，异常返回 `used=false`。因此只在外围包 Chat LLM 的 scope，不能保护这两类付费调用，也不能防止守卫错误被兼容降级吞掉。
4. 向量检索会调用 `VectorStoreService.ensureCollection`，可能创建集合或补建索引；它并非纯读取。

把整个组装器写入一个“只读准备”检查点不能消除上述内部效应。进程在 embedding 结果后、外层上下文回执前退出时，仍可能再次付费；也不能用关闭向量检索或重排来隐式改变既有上下文质量。

## 请求批准的有限调整

允许对**非冻结 RAG 服务的可注入执行接口**再作一次有限例外，默认旧调用仍走原实现。新增/移动代码合计预计约 400～700 行，拆入明确职责模块，不复制整套检索或上下文组装器。

- 为 embedding 与重排提供只读的实际请求描述和物理执行端口，包含完整文本/查询/文档、明确模型、有效配置身份及可用输入额度。凭据只在执行时解析，持久快照仅保留白名单及端点摘要。
- 新内核按检索/embedding/重排请求分别保存输入、领取和结果；每次实际 HTTP 请求（含重试/拆分）均核对租约、正文/来源版本与持久额度。未知结果保留领取；底层兼容捕获不能清除预算/失权/未知错误。
- 使用并发隔离的可注入检索执行范围，让现有组装器复用当前运行已保存的检索结果；不修改全局单例，不使用生产 monkey patch，不改变普通旧调用。
- 正式准备的集合校验只读；集合或索引缺失时返回已有知识库/索引来源页处理，不能由正文准备创建集合或补建索引。既有显式索引生产流程保留原行为。
- 不新增表、不迁移业务库、不调用真实付费模型、不增加依赖；冻结目录保持零修改。模型窗口仍要求明确元数据，未知额度不猜测。

## 验证

- 原生默认调用与同夹具请求/结果保持一致；词法融合、排序、章节衰减和事实上下文不重写。
- 全新临时 SQLite 与 HTTP 传输替身：embedding/重排结果已保存但外层组装未完成时恢复不重发；未知请求不自动重发；明确未发送预算拒绝可显式恢复。
- 每次实际重试/拆分保存独立请求与预约；配置/正文/前文/租约变化时拒发和拒写。异常被旧调用捕获也不能发布降级上下文绕过保护。
- 准备期间没有向量集合/索引写请求；缺失时只返回来源信息。
- 并发的旧调用与两个新内核运行互不借用检索结果、预算或执行权限。
