# 03 回填消费者：事务归属围栏的 G1 补充方案

状态：2026-10-22 用户在收到本补充方案确认问题后明确要求“继续，直到计划开发验证”，批准按本方案实施。前一份回填边界批准继续有效；本方案仅补充其在下层持久写入能力上的缺口。

## 已验证的缺口

前案允许“复用下层消费者的归属/版本保护”。进一步沿真实写入事务核对后，发现正文版本保护不能替代运行租约保护：正文未变化时，旧执行者即使失权，部分消费者仍能写入。

已在新建临时 SQLite 上加载真实 `ChapterArtifactFactWriter.persist` 源码复现：外层检查时租约有效；进入消费者事务后撤销租约，正文保持原样；摘要写入仍成功。该探针只注入数据库和边界依赖，没有使用业务库、模型或修改旧源码。私有证据为 `.codex-local/kernel-consumer-ownership-evidence.json`。这是旧服务边界的反例，不是新内核已通过的安全验收。

| 位置 | 已有保护 | 未提供的能力 |
| --- | --- | --- |
| `runtime/artifactSync/facts/ChapterArtifactFactWriter.ts:29` | 事务内正文哈希 | 同事务检查当前运行与执行租约；事实写入还另开事务 |
| `services/state/StateService.ts:399` | 事务内 expectedChapterContent | 调用方执行租约；后续冲突写入的同级保护 |
| `runtime/ChapterArtifactDeltaService.ts:900`、:1060、:1199 | 兑现、动态、知识写入前核对正文 | 调用方运行身份与租约 |
| `characterMind/CharacterMindService.ts:156`、:224 | 生成接口支持归属回调，但章节增量入口没有传递它 | 章节消费者的事务归属注入 |
| `state/persistence/StateProposalStore.ts:118` | V2 书归属、正文版本与资源确认 | 当前执行租约；书归属与任务归属不能混用 |
| `characters/locations/CharacterLocationService.ts:21` | 书版本、正文、手动修订凭据 | 自动生产执行租约；手动修订凭据不适用于自动运行 |
| `modules/timeline/persistence/TimelineFinalizationStore.ts:43` | 正文版本和时间线提交的原子性 | 调用方执行租约 |

新内核检查点目前会核对持久租约和阶段身份，但其事务与旧消费者业务写入事务不同。执行前后各检查一次，不能回滚中间已经完成的失权写入，不能将这视为满足内核合同。

## 建议：继续保持冻结目录零修改

将消费者的必要持久写入移入 `modules/production/infrastructure/storyState/persistence/`，只消费已经保存的结构化抽取结果。不复制旧的模型抽取、生产调度、自动继续、重试或 V1 分支。

预计新增约 1000～1700 行，按下列职责拆分，每文件不超过 400 行；实现前先补临时库红灯测试。该范围明显超出前案抽取/恢复编排的 300～600 行估算，已单独确认，开始实施。

| 新文件 | 范围 |
| --- | --- |
| `ownership.ts` | 在业务事务内核对调用方持久租约、ownerKey、运行/阶段请求身份、所选正文哈希与章节归属 |
| `facts.ts` | 摘要与已发生事实；不重新抽取，不混入规划义务 |
| `snapshot.ts` | 状态快照及四类子项、对应冲突投影 |
| `payoff.ts` | 结构化兑现增量 |
| `dynamics.ts` | 阵营与关系阶段；候选身份解析继续由调用方批准的接口负责 |
| `knowledgeMind.ts` | 知识边界与思维快照 |
| `dialogue.ts` | 对话影响的到期与应用状态 |
| `resources.ts` | 已审核资源增量及其提案/版本记录，保留人工确认保护 |
| `projections.ts` | 人物位置和出场投影，保留正文证据校验 |
| `timeline.ts` | 注入事务绑定的现有时间线仓储；只提交已保存的抽取结果，不调用模型 |
| `index.ts` | 对外提供消费者组装；以同一事务完成业务写入与消费者回执 |

复用已有 schema 和可安全注入事务的底层仓储；私有映射只在必要范围移植。人物归属使用结构化 ID 或唯一身份验证，不能新增模糊文字推断。原有消费者及 V1 调用保持原样。继续使用既有检查点表，不新增业务表或依赖。

## 验收

1. 租约在外层检查后、业务事务开始前被替换，而正文相同时，全部消费者拒绝写入，业务表与回执均无变化。
2. 同事务发生正文编辑、阶段领取失效或 CAS 失败时，业务写入和回执整体回滚。
3. 业务提交之后进程退出，恢复直接读同事务回执，摘要、状态、关系、资源、思维、时间线等不重复产生副作用。
4. 两个作业使用相同正文时，回执和授权仍按运行身份隔离。
5. 保留资源待确认、人物待确认、人工编辑保护、降级时间线及局部质量债语义。
6. 服务端构建、生产回归、关键变异和导入边界通过；冻结目录差异为空。

本方案来自路线图 G1 和代码级计划 03 Task 3 的明确要求：“旧服务不满足需要时，先形成最小复制方案并等待批准”。批准不会授权业务库迁移、beta/main 合入、开关启用或发布。
