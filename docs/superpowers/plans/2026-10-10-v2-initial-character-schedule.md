# V2 拆章角色初排实施计划

> 执行方式：本会话独立开发，不委派子代理，不自动提交。

**目标：** 拆章完成即能查看逐章计划角色；旧书可显式补齐缺少的排期，保留原规划和正文。

**已确认设计：** 用户同意复用现有拆章请求返回角色 ID，不为新书新增 LLM 步骤。初排是结构化安排，不从摘要猜角色；详细任务优先覆盖初排，正文记录继续绑定最终正文。

**架构：** 初排使用 VolumePlanVersion.contentJson 的章节字段 plannedCharacterIds（缺字段表示未知，空数组表示明确不安排）。版本文档本来就是卷规划的完整来源，无需增加数据库列或写入执行层。V2 拆章选择新契约，V1 保持原契约。补齐服务独立归属角色模块，通过显式 POST 生成有限章节的 ID 列表，校验活动版本与导演归属后只更新该文档字段。

**技术：** TypeScript、Zod、Prisma SQLite、React Query。

## 全局约束

- 不新增新书调用；角色目录只传 ID、姓名和剧情定位，稳定规则和目录置于动态章节上下文之前。
- 不改 V1 执行流程，不扫描正文推测排期，不在 GET 或页面挂载时调用模型。
- 补齐最多每次 24 章，仅缺失初排且未有详细任务的章节；不覆盖已有排期。
- 不运行真实模型、不写开发数据库；数据库测试使用临时 SQLite。
- 修改按实际功能登记本地清单；UI 交互由用户验收。
