全局约束与停止条件见计划 00。

## 计划 03：应用层与适配器

**目标：** 让内核可以真正运行一个单元：
- 执行器循环调用 `decideNext`，执行阶段，写回进度；
- 定义端口；
- 用适配器把现有底层服务接到端口上；
- 新增单元进度表。

**新增内容：**

| 路径 | 职责 |
| --- | --- |
| `modules/production/application/ports.ts` | `StagePort`（每个阶段一个）、`StoryStatePort`、`UnitProgressStore`、`BudgetPort`、`Fence` |
| `modules/production/application/unitExecutor.ts` | `runUnit(request): Promise<UnitOutcome>`，只包含"决策、执行、写回"的循环 |
| `modules/production/application/workExecutor.ts` | 作品级审校与修复，结果落回各个单元 |
| `modules/production/infrastructure/stages/*.ts` | 每个阶段一个适配器，调用现有服务 |
| `modules/production/infrastructure/storyState/*.ts` | 故事状态端口的适配器，按计划 01 Task 5 的结论实现 |
| `modules/production/infrastructure/progressStore.ts` | 单元进度表的仓储 |
| `modules/production/profiles/longChapter.ts`、`shortStory.ts` | 两份配置，参数来自计划 01 |
| Prisma：`ProductionUnitRun` | 每个单元一行，记录进度、所选稿件、内容哈希和版本号。两套 schema、两个迁移目录同步新增；每个迁移只建一张表 |

**关键规则：**

- 适配器调用旧服务时，必须显式传入参数，不得落入旧代码中的 V2 分支（计划 01 Task 3 的清单）。
- 适配器不得修改旧服务。旧服务的行为不满足需要时，按停止条件 G1 停下，由我决定是否把实现复制进内核。
- `commit` 阶段经由 `ChapterLifecycleService` 写入，写入前调用 `fence()`，并校验正文版本。
- 所有调用模型的阶段先检查同一内容哈希的已有结果，存在则复用，不重复调用。
- 新表需要用户批准；只生成迁移文件，并在临时库上验证，不对开发库执行迁移。

**验收要点：**

- 临时库集成测试：一个单元从无正文走到完成；在 `draft` 之后、`repair` 之后、`commit` 之后分别模拟崩溃，重新运行后得到相同结果，且不重复调用模型。
- 用户在运行中修改正文时，旧结果不落库。
- 冻结目录的差异为空。

## 计划 04：短篇接入内核

**前置：** 计划 03 验收通过；`codex/short-story-revision-recovery` 已合入 `main`，并按合入后的代码重做计划 01 Task 4。

**目标：** `ShortStoryProductionService` 保留自己的编排（计划、片段顺序、恢复游标），但把片段的写作、审校、修复、修后核对、编辑保护全部交给内核，使用 `short_story` 配置。

**关键规则：**

- 继续满足短篇 README 中的运行时不变量：连续正文投影、人工编辑片段不被覆盖、`expectedVersion` 校验、自动修复最多一次、质量债不阻塞。
- 全篇审校与修复走内核的作品级阶段。
- 短篇专用的 Prompt 继续使用，通过阶段适配器传入，不改为长篇 Prompt。
- 开关 `PRODUCTION_KERNEL_SHORT_STORY`，默认关闭；关闭时短篇行为与改动前完全一致。

**验收要点：** 开关关闭时，短篇现有测试全部通过；开关打开时，覆盖"生成、恢复、人工编辑后重新生成、全篇审校后单次修复"四种情形的临时库测试全部通过。

## 计划 05：V2 长篇正文切换到内核（不交低阶）

**目标：** `modules/director/steps/production/chapterBatch.ts` 不再启动并等待旧的流水线作业，改为在授权范围内逐章调用内核。

**关键规则：**

- V2 内核（`modules/director`）仍然不导入 `modules/production`，由 `app/director` 的生产组装注入。
- Run 的所有权围栏、预算、问题策略快照从 Run 契约注入内核。
- 单元结果映射为 V2 的产物、质量债和停止信号，映射是纯函数，配测试。
- 已经在旧流水线上运行中的批次，继续由旧流水线完成；新批次才走内核。不迁移进行中的作业。
- 开关 `PRODUCTION_KERNEL_V2_CHAPTERS`，默认关闭。

**切换前必须完成：** 决策差异清单。用同一组夹具对比内核与旧流水线的阶段决策，列出所有差异，并经用户确认。

**验收要点：** V2 全部测试通过；临时库演练覆盖"一个批次 3 章，其中第 2 章需要修复，第 3 章运行中被用户编辑"。

## 计划 06：短篇进入 V2 计划；V2 书的手动入口接入内核

**目标：**

1. 用 V2 的"计划即数据"定义一份短篇计划：短篇方向与计划、逐段写作、全篇审校、单次修复。短篇创作由 V2 Run 管理，展示进入导演台。
2. V2 书的手动写章、修章、重新审校入口按 `Novel.directorVersion` 路由：V2 书进内核，V1 书仍走旧链路。

**关键规则：**

- 短篇的历史任务（旧工作流任务）只读保留，不转换。新开的短篇才走 V2。
- 手动入口的路由判断只看书的版本归属，不看请求参数。
- 运行记录保持只读。

**验收要点：** V1 书的手动入口行为不变（回归测试）；V2 书的手动入口在临时库上完成"写章、修章、编辑后重新审校"。
