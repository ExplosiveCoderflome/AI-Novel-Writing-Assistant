# 导演 V2 角色位置连续性

## 背景与目标

角色档案的 `currentLocation` 是基础设定，不能表达修文后的章末位置。最新一章没有某角色也不能清除其此前的位置。叙事场景切换、回忆、梦境、计划和转述不能自动搬动角色。

## 决策

- 使用统一最终正文回填的一次结构化调用，增加 `characterLocationDeltas`。模型区分时间语境、实际移动、原地出现、位置冲突；不增加角色专项 AI 调用。
- 位置模块归属 `services/novel/characters/locations/`。在现有版本化资产检查点存储位置投影，不新增数据库表，不覆盖角色基础档案，不调用 V1 导演。
- V2 必须执行位置消费者；修文候选选定且正文保存后才投影，投影完成后才能开启下一章。恢复复用原统一抽取结果并幂等写入。
- 投影只接受本书真实角色、当前正文版本、可定位原句和模型明确判定一致的当下实际位置。不明移动保留提醒，继承最后可信位置。位置争议是局部质量信息，不是全书失败。
- 带质量债务的正文保留候选位置与待核对原因，不自动提交确认位置，遵守既有质量来源守卫。
- 读取严格按章序及正文版本，按角色寻找最后有效记录。未来章、其他小说、旧正文、未成功投影均排除；未出场不会变更位置。旧数据缺失时标注基础设定/位置未知，逐章积累，不批量调用模型补历史。
- 下一章的硬事实、验收和修文共用同一位置状态及来源。位置是动态输入，不放进稳定缓存前缀，也不把档案初始位置当成不可移动的规则。真实移动需有经过，允许合理省略与上下级地点细化，由模型结合时空判断。

## 使用体现

第十章甲在牢房，第十一章乙在客栈，第十二章仍应读到甲最后确认在牢房、乙在客栈。甲的回忆或“打算去客栈”不能改成客栈。确有离开牢房的正文，修文后才能更新。

## 边界

V1 不读写此投影。人工修改角色档案仍归基础设定；若与已有正文位置不同，以相应章序的正文来源为连续性依据。证据、版本、身份守卫是确定性数据保护；空间语义和移动合理性由结构化 AI 负责。本阶段不新增地图推演或额外质量循环。
