# 自动导演重构设计（全自动 / 半自动双编排器）

状态：设计草案，待用户审阅。未开始任何实现。

日期：2026-09-30

## 1. 背景与经验

### 1.1 为什么重构

当前自动导演链路（`server/src/services/novel/director/`）约 120 个非测试文件、3.3 万行；`runtime/` 目录 38 个文件，`novelDirectorTakeover.ts` 单文件 1107 行。执行链存在循环调用：流水线 → 编排器 → 步骤模块 → 步骤运行时 → 流水线。客户端中约 12 处独立组件各自展示同一本书的导演状态。

### 1.2 已经做过一次的经验

`refactor/director-simplification` 分支上已按“瘦身”方式完成阶段 0～3（书级唯一当前任务、读取纯读、单一写入口、启动合同不可变），阶段 3 经一轮返工。该方式在旧结构上收敛，结论如下：

1. 每改一处都牵动全自动、半自动与接管三条路径，验收成本压过开发成本。台账大半篇幅在和基点对账。
2. 新增一个阶段要同时改 10 个触点（见 `docs/wiki/workflows/auto-director-stage-checklist.md`）。
3. 同一事实在任务行、Seed、运行时表、前端推断四处各存一份，出现“改好又回去”。
4. 兼容代码（`legacyContext`、旧 `directorRuntime` 读取、旧任务沿用原逻辑）是复杂度的主要来源，而它们都是“新旧共存、就地兼容”的结果。

本设计**整体替换**该方案：原阶段 4～7 作废；阶段 0～3 只作经验参考，不作为实现地基。

### 1.3 用户确认的痛点优先级

代码臃肿、状态漂移、质量门卡住全书、开发与验收成本高。另有两条补充约束：

- **灵活性**：AI 迭代很快，步骤计划必须数据化，并为 agent 式编排预留位置。
- **展示面收敛**：导演状态不能分散在十几个位置。

## 2. 目标与非目标

### 2.1 目标

- 全自动与半自动各有独立、很薄的编排器，互相不靠模式开关干扰。
- 每个事实只有一个写入口、一份存储、一个投影函数。
- 局部质量问题不再停住全书。
- 增删、合并、重排步骤只改一份声明，不改内核。
- 每本书的导演状态只有三层展示（徽标 / 导演面板 / 运行记录）。
- 新内核可独立测试，不再和旧基点做全量对账。

### 2.2 非目标

- 不改提示词、章节生成 / 审校 / 修复算法、问题目录与问题策略内容。
- 不重做**开书候选链路**（灵感、方向候选、书名确认），保持现状，仅通过转接层对接。
- 不实现 agent 编排器本身，只预留接口并用契约测试钉住。
- 不做通用插件系统，不对产物内容或章节生成算法过度抽象。
- 不在 P7 之前修改或删除旧导演代码与旧表。

## 3. 决策摘要

| 项 | 决定 |
| --- | --- |
| 与旧瘦身工作的关系 | 整体替换 |
| 全自动 / 半自动结构 | 共享事实层 + 两个薄编排器，各自独立控制流 |
| 半自动参与粒度 | 按阶段设门；规划阶段每个阶段确认一次，正文按批次确认，不逐章 |
| 模式切换 | 双向可切，仅在已保存的阶段或批次边界生效 |
| 范围 | 规划链路、正文生产循环、接管、展示层、执行面；开书候选链路保持现状 |
| 数据策略 | 新增独立事实表，新任务只走新链路，旧表不删 |
| 在途旧任务 | 冻结为只读历史；继续写作走接管，从小说资产起新 Run |
| 重启与租约过期 | 按问题策略快照的重试预算自动恢复，耗尽后转人工恢复锁（暂定，见 12 节） |
| 交付顺序 | 全自动先于半自动 |
| 展示面 | 三层：状态徽标、导演面板、运行记录 |

## 4. 事实层

**原则：进度不存进任务，而是由产物与小说资产推导。**

| 事实 | 内容 | 唯一写入口 | 可变性 |
| --- | --- | --- | --- |
| Run | 合同：范围、问题策略快照、模型配置、驱动方（全自动 / 半自动）、步骤计划版本快照 | `RunStore.open` | 创建后不可变 |
| RunControl | 状态、游标、暂停原因、版本号、租约与心跳 | `RunStore.transition(event)`，一张状态迁移表 | 唯一可变的一行 |
| ArtifactLedger | 产物类型、范围、版本、哈希、状态（草稿 / 已确认 / 用户编辑 / 已失效）、是否受保护；内容指向小说业务表，不复制 | `ArtifactLedger.record` | 只追加版本 |
| QualityDebt | 按章节的局部问题、来源、处理动作 | `QualityDebt.record` | 只追加 |

另有**事件日志**：只追加，仅用于审计与时间线展示，**不是**状态来源。事件记录每次执行使用的提示词版本与模型，用于评估 AI 升级效果。

推出的规则：

1. **进度 = 产物台账 + 章节事实的纯函数。** 不持久化“当前第几步”。游标只是缓存，丢失后可重算。
2. **展示 = 一个纯函数** `project(run, control, artifacts, debts) → DashboardView`。
3. **质量债不写入 Run 状态。** 局部问题只产生质量债行；只有明确重规划、无可用正文、安全或数据完整性故障，才能经 `transition` 暂停 Run。
4. **产物类型是开放集合**：使用“已注册类型 + schema 版本”，新增产物类型不改表结构。
5. **统一的 `open_run`**：新开书、接管已有小说、全自动 ↔ 半自动切换、冻结旧任务后继续写，全部是“关闭旧 Run，从当前资产事实起新 Run”。没有状态需要迁移。

## 5. 步骤计划与编排器

### 5.1 步骤计划是数据（依赖图）

计划是带版本的声明式依赖图，不是有序列表。每个步骤声明：

- `requires`：需要哪些类型的产物，且未失效。
- `produces`：产出哪种产物。
- `needs`：需要的模型能力（结构化输出、长上下文等），不绑定具体模型与提示词。
- `gateable`：在半自动下能否作为确认门。
- 已有新鲜产物时是否跳过。

通用函数 `readySteps(facts)` 按依赖算出当前可执行步骤。这是所有编排器共用的唯一“计划逻辑”。Run 创建时快照计划版本，在途 Run 按启动时的计划跑完，不被升级打断。

### 5.2 编排器接口

```text
next(facts, contract) -> Action
Action = run_step | open_gate | record_debt | pause | complete | fail
```

编排器只读事实，不写库、不调用模型、不直接执行。

### 5.3 内核：执行器与守卫

守卫集中所有安全规则，校验每个动作：前置产物齐全且未失效、不覆盖受保护的用户内容、不超出 Run 合同范围、用量未超预算、未触碰安全规则。非法动作被拒绝并带回原因；每个 Run 有拒绝次数预算，耗尽后暂停。

恢复不是独立逻辑：崩溃或租约过期后，重新调用 `next()` 即可，因为进度由产物推导。

### 5.4 三个编排器

| 编排器 | 状态 | 行为 |
| --- | --- | --- |
| 计划编排器（全自动） | 首期实现 | 按依赖图推进到合同范围结束；质量债只记录；仅在明确重规划、无可用正文、安全或数据完整性故障时停 |
| 门控编排器（半自动） | 第二期实现 | 每个阶段产物完成后 `open_gate` 并等待；用户编辑后产物标为 `user_edited`，下游自动失效，下一次 `next()` 重新计算 |
| Agent 编排器 | 不实现，仅预留 | 由 AI 从 `readySteps` 中选下一步；用契约测试钉住：假 agent 提交非法动作，守卫必须拒绝 |

灵活性放在“提出什么动作”，安全性锁在“能否执行”，两者分离。

## 6. 执行面

保留原则：**API 只收命令、返回轻量投影，长任务只在 Worker 中运行。**

### 6.1 命令（封闭五种）

| 命令 | 含义 |
| --- | --- |
| `open_run` | 新建 Run（开书、接管、切换、旧任务继续写都走它） |
| `resolve_gate` | 对门做决定：确认 / 编辑后确认 / 重新生成 |
| `resume` | 从人工暂停恢复；**唯一**能解除人工恢复锁的命令 |
| `handoff` | 请求切换驱动方，在已保存边界生效 |
| `cancel` | 取消 |

每个命令带幂等键与 `expectedVersion`（RunControl 版本号）；版本不匹配返回 409。

### 6.2 Worker：单一循环

```text
租约 Run → 读事实 → orchestrator.next() → 守卫校验 → 执行 → 落账 → 重复，直到暂停 / 完成 / 失败
```

- 租约挂在 Run 上，不再有命令租约与任务租约两套。
- 租约过期即由其他 Worker 重新领取，并重新调用 `next()`；不设周期性对账修复扫描。
- 读取接口只调用投影函数，结构上没有写路径。

### 6.3 由数据库兜底的不变量

- 一本书同一时间最多一个活跃 Run：部分唯一索引（`novelId`，状态为活跃）。
- 人工暂停只能由 `resume` 命令离开：写入 `RunStore.transition` 迁移表，其他路径没有这条边。

### 6.4 与章节生产的接缝

“章节批次”作为一个步骤，内部只调用 `startPipelineJob` / `resumePipelineJob`，不重写章节生成、审校、修复，也不新增第二条正文链。步骤期间 Worker 保持心跳并等待该任务结束。

## 7. 展示层

**前端只渲染，不推断。**

### 7.1 DashboardView

字段：`mode`（运行中 / 排队 / 等待确认 / 已暂停 / 已完成 / 失败 / 已取消）、`driver`、`headline`、`progress` 与 `progressSource`、质量债摘要、`availableActions`、书级来源路由（不含任务编号）、`sourceTrace`。

- `availableActions` 由状态与计划数据推导。半自动的“门”来自 `gateable` 步骤；每个产物类型在注册表中声明名称与审阅页路由，新增阶段时门和按钮自动出现。
- 两档投影同一个函数：`summary` 用于高频轮询，`detail` 是超集用于面板；前端使用不同缓存键。
- 文案在投影中按用户视角统一生成，遵守 `AGENTS.md` 的 UI 文案规则。
- 旧任务通过 `legacy/` 适配器投影为同样形状，`mode` 固定为历史，唯一动作是“从小说资产继续”。

### 7.2 三层展示

| 层 | 内容 | 取代 |
| --- | --- | --- |
| 状态徽标 | 一行：状态 + 一句话 + 一个主按钮；所有入口页只放它 | 各入口页自有状态块、导航栏状态、移动端状态卡、章节编辑器导演区 |
| 导演面板 | 每本书唯一详情面；桌面侧边抽屉，移动端全屏；固定四块：正在做什么 / 需要你做什么 / 质量债 / 时间线；诊断折叠在最后 | AI 驾驶舱、进度弹窗、任务抽屉、执行详情、投影卡片、事实体检弹窗 |
| 运行记录 | 跨书只读历史，带“需要处理”筛选，点击进入对应书的导演面板 | 运行记录 + 跟进中心 |

规则：

- 动作只出现在来源页。半自动的门在审阅对应产物的页面确认，面板只显示“去确认”并跳转。
- 浏览器通知读同一个投影，点击进入同一个导演面板。
- 简易书架与完整工作台只是书页的两种布局，使用同样的徽标与面板。
- 守卫测试：只有 `DirectorBadge` 与 `DirectorPanel` 能读取 `DashboardView`；其他文件出现导演状态展示则测试失败。

### 7.3 导演面板的视觉

用户明确不喜欢当前“执行详情”的样式，也没有指出偏好哪一个现有展示面，因此**不沿用任何现有展示面的样式**。面板的视觉与信息层级在 P4 前单独设计，需提供对比稿并经用户确认；须遵守 `AGENTS.md` 的低边框视觉规则。

## 8. 模块布局与交付顺序

新内核位于 `server/src/modules/director/`，分 `domain/`（计划、守卫、编排器）、`application/`、`infrastructure/`、`http/`、`legacy/`。**P7 之前旧导演代码不改动。** 新内核不 import 旧导演代码；旧数据只经 `legacy/` 只读适配器出现。

| 阶段 | 内容 |
| --- | --- |
| P0 | 设计定稿；盘点旧阶段并转为步骤依赖图；整理“必须继承的旧规则”（见 10 节）；确定停止边界与失效规则（见 12 节） |
| P1 | 事实层、状态迁移表、守卫、投影函数，仅用假步骤测试 |
| P2 | 计划编排器 + Worker 循环 + 规划链路步骤 |
| P3 | 正文生产步骤（对接 `startPipelineJob`）、质量债、重规划；全自动端到端 |
| P4 | 展示层：新接口，前端书级入口切换为 `DashboardView`，三层展示落地 |
| P5 | 门控编排器：半自动、用户编辑后下游失效并重算 |
| P6 | `open_run` 统一接管与切换；`legacy/` 适配器；在 `open_run` 入口打开开关 |
| P7 | 清除旧引擎（**需用户批准，且先完成可验证备份**） |

开关仅设在 `open_run` 入口一处，决定新 Run 走新内核还是旧链路；新内核内部没有新旧分支。

### 8.1 独立分支与新入口（P1～P5 的开发与测试方式）

- 在专用分支上开发，不在 `refactor/director-simplification` 上继续。
- P1～P5 期间**不修改任何现有入口**，新内核只通过独立入口访问：
  - 前端：独立路由（如 `/lab/director`、`/lab/director/:novelId`），不进导航，仅通过地址访问，用于预览徽标与导演面板。
  - 后端：独立接口前缀（如 `/api/director-next/*`），挂在 `modules/director/http`，由环境开关控制是否挂载。
  - Worker：仅在开关开启时启动，只租约新表中的 Run，不领取旧任务。
- P6 才把真实入口的开关切到新内核；`/lab` 入口在 P7 前保留为诊断与回归入口。
- 新表通过前向迁移加入（只增不删）。首次在开发库执行迁移前，按 `AGENTS.md` 先完成并核验数据库备份。

## 9. 验收

- 旧链路不动，不再与旧基点做全量对账；新模块只跑自己的测试。
- 契约测试：状态迁移表穷举；假 agent 的非法动作被守卫拒绝；在每个步骤边界模拟崩溃后重新调用 `next()` 必须幂等；投影函数是纯函数；读取接口不写库。
- 边界守卫测试：新模块不 import 旧导演代码；只有 Writer 能写事实；前端不读原始 Run 字段；只有两个组件读取 `DashboardView`。
- 界面验收由用户完成，实现侧只做代码级检查。
- 用户可见变化（三层展示、跟进中心并入运行记录）在 P4 按 README Release Notes Workflow 更新发布说明。

## 10. 必须继承的旧规则（初稿）

下列规则来自 `docs/wiki/workflows/auto-director-runtime.md` 等文档，已被验证有效，新内核必须保留。P0 时逐条核对并定稿。

**执行与安全**
- API route 不 `await` 长任务；用户动作一律转命令。
- 自动导演不是第二套章节生成系统；正文只通过 `startPipelineJob` / `resumePipelineJob` 进入统一章节 runtime。
- 章节进入下一章前必须服从 `final_content → timeline_finalization → next_chapter`，导演不得绕过时间线提交。
- 每章最多一次自动修复，运行异常重试与质量修复共享这一次预算；`heavy_repair` 只能来自明确选择的修复任务。
- 每章累计 token 超硬预算时打开 `usage_anomaly` 熔断，仅保护尚未执行的工作。
- 受保护用户内容（`protectedUserContent`）不被规划重算覆盖；已生成正文不被局部重规划覆盖。

**质量与停止**
- 局部质量问题（`local_patch_plan`、`continue_with_warning`、`patchable_obligation_gap`、`defer_and_continue` 等）只记质量债并继续。
- 只有明确的 `stop_for_replan` / `replan_required`、无可用正文、运行时安全、数据完整性故障可停全局。
- 问题策略快照在启动时冻结，运行中不被全局或本书设置修改；任务的质量优先策略下 `pause_for_manual` 必须停在已保存的章节边界。
- 重规划默认 `local_window` 作用域；`global_book` 才是整书结构不可恢复的显式判断。
- 问题动作集合沿用 `auto_retry`、`continue_with_warning`、`pause_for_manual`、`fail_task`，不可突破的安全动作由问题目录的 `enforcedAction` 执行。

**恢复与状态**
- 人工恢复锁只能由用户的显式命令清除；后台轮询、Worker 恢复、读取路径均不得清除。
- 读取路径纯读；启动合同创建后不可变。
- `workflow_completed` 只表示当前任务授权范围执行结束，不等于整本作品完成。
- 重启后不静默续跑长任务。

**规划与产品**
- 快速启动关键路径只等：精简故事基础、开篇世界切片、核心角色、3～5 章路线、下一章执行合同；完整世界手册、非开篇角色增强、远期卷骨架不占用正文关键路径。
- 滚动规划：路线窗口与章节执行合同是两个阶段，路线同步阶段不用执行期完整性校验阻断下一章；JIT 预取失败只记日志。
- 现有项目接管默认为“全书前置规划接管”，停在 `production_experience_required` 后才进入正文。
- 创作界面（阅读书架 / 完整工作台）只是显示偏好，不是权限边界，也不改变生产范围。
- 运行记录是只读的，不放置任何改变任务状态的动作。
- 语义判断（意图、质量、身份承接等）交给 AI 结构化输出；确定性逻辑只做输入校验、安全守卫与对结构化输出的后处理。

## 11. 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 部分唯一索引 | Prisma schema 无法声明部分唯一索引 | 写入迁移 SQL，并用真实 SQLite 测试验证约束 |
| 新旧并存期 | 新旧两套表、两套入口同时存在 | 开关仅在 `open_run`；新内核不依赖旧代码；P7 才清理 |
| 步骤实现复用 | 步骤要复用旧阶段里的生成逻辑，但不能依赖旧导演运行时 | P0 盘点时标明每个步骤复用的底层服务，必要时把阶段逻辑下沉为独立函数 |
| 用户可见变化 | 信息密度下降、跟进中心并入运行记录 | 诊断折叠区保留完整细节；P4 做视觉对比稿并由用户确认 |
| 在途旧任务 | 用户需手动点击“继续”触发接管 | 在 legacy 投影里以单一动作呈现，并在发布说明里说明 |

## 12. 开放问题
