# 导演 V1 / V2 共存与流程隔离

## 已确认的产品需求

用户选择原导演 V1 或新导演 V2。两套流程独立，共存不能导致相互启动、恢复、覆盖状态或重复写正文。新书默认 V2；原 V1 小说保留 V1，已有 V2 调试小说保留 V2。版本与全自动 / 按阶段确认是两个独立选择。

## 决策

采用按小说持久化版本绑定，同时启动各自执行器。环境开关只控制 V2 是否可用，不再把所有小说强制切到 V2。不开启第二套服务，也不让每次生成任意选择引擎。

小说表保存 `directorVersion`（v1 / v2 / 未绑定）和 `directorEpoch`。开书任务保存所选版本；生产任务冻结小说当前 epoch。切换版本递增 epoch，使之前的任务即使保留 queued / paused / failed 状态也无法重新执行。历史查询只读，不补写绑定。

## 隔离边界

- V1 继续使用原命令、状态、租约、恢复与编排；V2 继续使用 DirectorNext Run、Control、Artifact、Command、Event 与质量债。
- V2 内核不导入 V1。应用装配层注入通用执行权限端口，检查当前小说和任务归属。
- 开书候选服务可以复用，但 V2 候选命令不能被 V1 Worker 领取。确认后分别创建 V1 工作流或 V2 Run，不双写两套生产状态。
- 两套 Worker、陈旧任务修复、启动恢复、watchdog、Agent、通知回调、HTTP 和通用任务恢复均检查版本与 epoch。只隐藏按钮不构成隔离。
- 章节生产服务属于共享生成能力，作业必须仅有一个导演所有者。V2 作业由 V2 显式恢复；V1 watchdog 不扫描、取消或暂停 V2 作业。
- 两套流程共享已保存的小说、世界、角色和章节资产。切换时不读取对方的 Seed、游标、确认门或质量状态作为运行参数。
- 手动恢复锁继续保留；版本选择不自动恢复任务，也不调用模型。

## 版本识别与切换

显式绑定优先；未绑定历史小说有 V2 Run 则视为 V2，其余保持 V1。V2 开书候选任务是方向准备记录，不证明存在 V1 生产流程。

切换接口使用期望 epoch 和事务锁定小说行。当前 epoch 的任一生产任务、租约或正文作业未结束时拒绝切换，包括等待确认和人工恢复。切换只保存目标版本与新 epoch，不生成正文。用户在目标工作台明确授权后，从已保存资产创建新的目标版本任务。旧任务不转译、不复活；切回旧版本也不能恢复旧 epoch 的任务。

V2 不可用时，保留 V2 小说的身份，给出不可用提示，不能静默转到 V1。

## 用户入口

- 原开书界面增加导演版本选择，保存到草稿与服务端开书任务。候选任务开始后冻结版本；要换版本先结束该候选任务。
- 书架和工作台显示导演版本，来源路由按小说绑定决定。V1 使用原工作台；V2 使用新工作台。
- 小说设置提供版本选择，展示当前版本和未结束任务提示。操作成功后导航到相应工作台，不自动生产。
- 顶部将“导演 V1 / V2”和“全自动 / 按阶段确认”分别显示。
- 运行记录只读，历史记录保留其自身版本对应的来源页面。运行记录不提供切换、恢复或取消。

## 验证

使用全 schema 临时 SQLite，不连接开发库，不调用真实模型。验证 V1 与 V2 请求同进程共存、开书版本冻结、跨版本和过期 epoch 拒绝、同书切换并发、V1 租约 / 修复 / watchdog 不修改 V2 数据，以及旧任务所有列与已有正文保持不变。前端验证版本请求、草稿恢复、路由和模式标识；界面验收交给用户。

只执行增量添加字段迁移，保留 PostgreSQL 与 SQLite 对齐。不合并 beta / main，不推送，不清理旧导演或用户未提交文件。
