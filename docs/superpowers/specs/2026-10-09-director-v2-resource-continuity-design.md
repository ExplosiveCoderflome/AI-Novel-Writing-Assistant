# 导演 V2 资源回填与跨章衔接

## 目标与范围

保留统一 Delta 抽取、按正文版本恢复和分消费者提交的现有设计，补齐资源决策与后续读取。只开发资源闭环；开书交接、资料编辑、导出和通知另行处理。

1. 资源变化的处理建议由统一抽取的结构化 AI 输出给出，不增加逐资源模型核对调用。
2. 最终保留正文保存后完成必要回填，再允许下一章。恢复复用相同正文版本的抽取和已完成消费者。
3. 未决变化作为约束进入后续相关章节，不能作为已确认背包内容。排除未来章节和正文版本失效的提案。
4. V2 事实检索复用统一抽取的硬事实，使用现有章节摘要索引的逐事实分块，不复制到旧事实账本或重新抽取全文。
5. 索引异步执行；事实分块携带章节正文版本。召回时排除失效版本和当前章之后的事实。

## 边界

- V2 的编排与恢复不调用 V1 导演任务状态机。
- V1 保留原有资源校验与上下文行为；V2 的决策权限必须显式传入并校验小说归属与正文版本。
- 高风险、低置信度、缺证据、所有权或持有冲突仍须阻止自动提交。AI 的 hold 建议必须生效。
- 普通资料疑问是章节级提醒；明确质量优先人工暂停、重规划和数据完整性失败沿用现有规则。
- 静态规则、角色/资源/伏笔目录是可复用前缀；未决变化、当前状态和正文在动态尾部。不得缓存旧状态来提高命中率。
- 无数据库结构变更，不对开发数据库执行写入或迁移。测试使用依赖隔离或新建临时 SQLite。
- 在用户指定的开发主目录 `D:\code\ai` 的专用功能分支开发，不混入既有未提交文件，不推送或合并。

## 设计

### 资源处理

统一抽取在每条资源变化上提供 `reviewDecision: commit | hold`。V2 将建议交给共享状态提交服务，由内容版本、归属、证据和现有资源冲突保护最终写入。缺少建议的历史抽取按 hold 处理；V1 不消费该权限。

资源上下文在 V2 中读取当前章及之前的未决提案，按结构化角色 ID、资源归属和使用窗口裁剪。有关联正文 hash 的提案必须匹配保存正文。输出只显示待核对约束，不改 proposal 状态。

### 事实与检索

章节摘要索引在 V2 使用当前正文版本的成功抽取检查点及已写入事实核对结果，生成摘要与逐条硬事实分块。V1 沿用旧来源。新分块携带正文 hash 和章节序号，检索在融合前过滤失效/未来分块，避免异步旧索引抢占结果。

V2 结构化摘要与事实的背景标签直接从来源章节组成，不再为每块调用模型解释。正文及摘要索引只由最终事实消费者安排，避免草稿保存、通用同步与最终回填重复安排索引。异步索引失败不改变必要资源回填的完成规则。

摘要和事实写入收敛到 `runtime/artifactSync/facts/`；外部模块通过模块 facade 消费读投影。不要扩展已接近长度上限的 Delta 服务职责。

## 验收

- 正常路径只有统一增量抽取；恢复不重复抽取，不重复提交已完成资源。
- AI 明确批准且通过保护的普通消耗/丢失变化可提交；hold、高风险、低置信度、无证据或冲突不能自动提交。
- 第 N 章能收到相关前章未决变化；未来章、其他小说、无关角色和失效正文提案不能污染上下文。
- V2 硬事实可由现有章节摘要检索召回，异步旧版本分块不能进入后续写作。
- V1 默认行为、质量策略、保存后恢复和提示缓存布局回归通过。
- 真实缓存命中与成本改善留待用户下一批生成后，按调用阶段对比台账；离线测试不宣称厂商命中提升。
