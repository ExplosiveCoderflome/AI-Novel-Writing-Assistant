# 开发计划

这份路线图说明项目当前已经能帮助你完成什么、近期优先把哪些环节做稳，以及哪些能力仍处于后续评估阶段。完整的逐日变化见[版本更新说明](#/docs/release-notes)。

## 当前可用的完整主链

截至 2026-08-31，项目的核心目标仍是帮助没有小说创作经验的用户，从一个方向走到可导出的完整正文。

### 1. 找到开书方向

你可以按自己的准备程度选择入口：

- **从一个想法开始**：让 AI 补齐题材、主角优势、核心冲突与开篇承诺。
- **从热门题材雷达开始**：扫描公开榜单，勾选具体作品和市场信号，再把分析结果交给自动导演。
- **照着一本书写**：选择已完成拆书的参考作品，继续原作，或只借鉴结构、节奏与写法创作新书。
- **手动创建**：适合已经准备好书名、简介、题材和基础设定的用户。

相关说明：[热门题材雷达](#/docs/module-market-radar) · [拆书分析](#/docs/module-book-analysis) · [小说管理](#/docs/module-novels)

### 2. 由自动导演完成整书规划

自动导演可以连续推进项目设定、故事宏观规划、角色准备、卷战略、章节规划和正文生产。简易模式突出阅读、进度与继续创作，专业模式提供完整资料、章节控制、审校、恢复和导出入口。

相关说明：[自动导演完整流水线](#/docs/flow-auto-director-pipeline) · [自动导演后续操作](#/docs/module-director-follow-up)

### 3. 按章节持续生成、检查和保存

每章会经过执行合同准备、正文生成、接收检查、必要修复和保存。旧项目缺少章节目标、任务单或场景边界时，系统会先补齐当前章的执行合同，再继续写作，避免整本任务反复卡在同一检查点。

局部质量问题默认作为可见的质量债务留在章节层处理，不会自动阻断整本生产；只有明确需要重规划、正文无法安全保存、运行安全风险，或所选规则要求人工确认时，任务才会停在已保存的章节边界。

相关说明：[章节执行链](#/docs/flow-chapter-execution) · [按阶段恢复](#/docs/playbook-recovery-by-phase)

### 4. 管理写法、知识与创作资产

拆书结果、知识库、世界与角色状态、提示词模板都会参与后续生成。正文提示词支持在“正文效果实验室”中选择模型测试当前草稿，测试结果不会直接覆盖已经保存的章节。

相关说明：[提示词管理](#/docs/module-prompt-management) · [知识与 RAG 召回链](#/docs/flow-knowledge-rag) · [本书世界](#/docs/module-book-world)

### 5. 恢复长任务并导出成果

运行记录会保留自动导演、拆书、批量生成等长任务的阶段和错误原因。模型余额或配额不足、质量优先规则要求确认时，任务会保留已完成正文与恢复位置；处理模型配置或确认问题后，可以从未完成章节继续。专业创作支持按章节顺序导出整本 TXT 正文，项目资产仍可使用 Markdown 或 JSON 导出。

相关说明：[运行记录](#/docs/module-task-center) · [系统与模型设置](#/docs/module-system-settings)

## 当前开发重点

近期开发遵循以下优先顺序：

1. **稳定自动导演恢复与章节生产链**：让暂停、重试、恢复和重规划共享清晰的状态边界，优先保护已经保存的正文。
2. **提高新手完成整本书的成功率**：给出明确默认值、推荐入口和下一步操作，减少要求用户自行修复结构、节奏或角色弧线。
3. **统一运行时、提示词与任务投影契约**：先解决后端实际状态、运行记录和前端展示不一致的问题，再增加新的工作流分支。
4. **控制创作入口复杂度**：市场雷达、拆书、创作中枢和自动导演都服务于小说完成主链，不把创作中枢扩展成与成书无关的通用聊天工具。

## 后续评估方向

这些方向具有长期价值，但不会优先于主链稳定性：

- **长程上下文记忆**：让世界规则、角色状态、时间线、伏笔和写法在长篇后段仍能稳定参与生成。
- **跨书资产复用**：复用题材基底、推进模式、世界样本、角色档案和写法资产，同时保留来源与适用边界。
- **质量报告与集中返修**：把章节级质量债务汇总成可理解、可分批处理的整书报告。
- **叙事引擎工作台**：把世界、角色、势力、资源和事件做成可观察、可推演的创作资产，但必须降低而不是增加新手负担。
- **视觉改编产线**：在小说主链稳定后继续完善漫画、漫剧和短剧的角色一致性、镜头连贯与成片导出。
- **桌面版安装与自助运维**：继续简化模型供应商配置、本地知识库存储和常见错误恢复。
