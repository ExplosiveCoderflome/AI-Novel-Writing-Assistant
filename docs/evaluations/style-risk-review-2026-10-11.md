# 写法风险真实 API 评测（2026-10-11）

## 范围与结论

在 `codex/style-risk-v2` 使用项目保存的 `deepseek / deepseek-flash` 配置，调用实际登记的 Prompt 与正式服务。凭据未写入报告；没有读取、改写或保存用户小说正文，没有启动导演任务、执行迁移或重置数据。既有用量记录器追加无小说与任务归属的测试调用记录。

测试使用六段原创合成小说片段（非空白约 577～705 字）：现实日常、武侠、人物口吻重复、表层模板聚集、叙事说教与过满结局、正文指令干扰。另有三个短片段候选用于事实复验。手动预览复用其中正常文和表层问题文。规则是当前启用的 12 条全局基线，临时合同不持久化。

最终检测 v9、统一验收 v18 的六个用例均通过输出合同和来源校验；事实受控用例符合“正常候选允许、两个破坏候选拦截”的预期。手动预览的合同、编辑范围与数值保护通过，但文字质量未通过抽查：模型仍补造原文没有的笔迹和动作。该阶段暂缓 beta 集成，不能宣称 P2 完成或事实安全。

后续按用户要求将未推送功能统一集成到 beta 进行预发布验收。手动修文仍只生成待作者核对的预览，语义事实未检查的结果不能当作事实保护通过；自动章节修文仍需正式事实复验并在失败时保留原稿。本次集成不改变上述质量结论，进入 beta 不等于完成正常文误报率、自动修文质量或正式发布验收。

本轮包含失败定位、中间版本复验及最终验证，共记录 77 次调用，已报告 334,942 Token，另有 1 次传输重试没有 usage，累计是已报告下限。最终全阶段合同回归为 19 次调用、83,328 Token；该批手动修文 v3 随后被 v4 复验替代，v4 两案例共 3 次调用、11,940 Token。成本对照另 1 次调用、5,201 Token。总量包含重试与失败，不将其冒充正常每章开销，不推算货币金额。

早期 v7 同样本双轮测试出现引用拼接；v8 的人物口吻双轮合同通过，但问题数量与修文许可并不完全一致。最终 v9/v18 每例一轮，只证明当前样本的合同回归，不能宣称模型输出稳定或防过矫已经校准。

## 失败原因与修复边界

1. 统计 `ruleId` 与真实反 AI 目录 ID 同名，模型混用；渲染改为 `signalCode`，普通写法合同允许 null，仍拒绝不存在的目录规则。
2. 合并问题的指令与连续原文证据冲突，模型用省略号拼接；明确合并解释但只引用一处，保留来源校验，去掉强制凑问题数量。
3. 验收重复生成问题关联编号，模型把目录 ID 或另一个编号写进 issueCodes；模型只生成一次语义问题，程序从同次结构化 voice 项派生关联。持久合同和层次、权限、事实检查继续执行。
4. 模型遗漏 styleReview 或把概括当成表扬的证据；原始模型合同要求字段必填，开启时不能缺失报告；只记录需关注风险，无风险 observations 为空。没有新增失败吞并、语义重试或风格二次调用。
5. 手动修文的动作表达建议与禁止新增事实发生冲突；v4 明确微动作、笔迹、物件特征也是事实，没依据就删除空话。复测仍有违规，提示词纪律不构成事实证明，手动输出继续是待核对预览。
