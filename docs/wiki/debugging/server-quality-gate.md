# 服务端质量门禁与验证范围

## 背景

类型检查不能验证 Promise 生命周期、运行时循环依赖、Prompt 治理或恢复状态。发布前应同时验证这些高风险契约，且测试不能连接开发数据库或真实模型供应商。

## 当前规则

- `pnpm --filter @ai-novel/server lint` 执行 TypeScript 检查及 AST 代码规则，拒绝 `debugger`、异步 Promise executor、直接 `eval`、字符串异常和关闭类型检查的注释。规则复用项目已有 TypeScript 依赖；它是有限的错误模式检查，不声称覆盖全部编码规范。
- `pnpm --filter @ai-novel/server test:quality` 复用调用方已构建的 `server/dist`，执行代码规则及明确列出的关键回归。源码或依赖变化后须先构建；文档更新不需要重复构建。
- 门禁覆盖 Prompt 注册、HTTP 和业务模块边界、流式调用、正文并发写入、时间线、导演只读投影、进程恢复、人工暂停、章节完成策略和迁移完整性。
- 持久化边界同时验证结构与行为：编辑、时间线和状态提案的应用入口不能绕过各自存储模块；隔离 SQLite 故障注入确认正文与任务登记、时间线结果与完成标记、提案状态与历史版本分别整体回滚。只验证方法被调用不足以证明事务一致性。
- checkpoint 领取故障必须传播；并发完成的记录不能被重领。提案确认与拒绝只允许一个请求消费待审核状态。只读分卷投影不得触发版本恢复，数据库读取错误也不得伪装成缺少规划。
- Prompt 治理自动扫描 `src` 所有顶层目录，包括 `modules/app/platform`。`prompting` 与 `llm` 是实现入口，其他豁免必须精确到现有流适配文件，不能用整个业务目录绕过检查。
- Director Next 的 shared revision 契约只允许已声明的应用、HTTP 与基础设施适配器消费；domain 仍保持纯领域边界。新增消费者必须说明依赖方向，不能扩大到整个目录的白名单。
- 单章额度的共享契约仅允许明确列出的命令、端口、HTTP、恢复适配器和投影消费；domain 投影只能以 type-only 方式引用纯数据视图，不能加载校验器、额度策略或基础设施。边界检查须区分这类编译后消除的类型依赖与运行时依赖。
- 测试进程默认使用新建临时目录和隔离数据库地址；SQLite 集成用例自行建立空数据库并应用迁移。所有模型结果使用替身，不调用付费服务。
- 自行使用 Prisma 写入夹具的测试文件，必须在导入 Prisma 以前设置独立临时数据库，并在测试启动钩子中应用迁移；不能只依赖外层门禁注入环境。单独执行 `node --test` 也须隔离。固定测试 ID 的唯一约束冲突首先检查路径与重复夹具，不能删除开发库记录或重置数据库来让测试通过。
- PR 到 `beta/main`、推送 `beta` 以及桌面候选/正式打包流程都执行门禁。自动门禁不能替代 `beta` 的用户验收，也不授权发布或分支晋级。

## 失败排查

类型检查失败先修代码，再运行相关用例；依赖边界失败应检查发射后的真实 import，不能把 type-only import 当成运行时环。数据库用例失败先确认临时路径和迁移版本，禁止用重置开发数据库解决测试失败。

Prompt 消息角色或合并方式调整后，必须同时检查已有内容断言与新兼容性回归是否使用同一契约。章节 writer 将篇幅和补写约束放在首位唯一的 system 消息中，用户上下文随后传入；不能为了满足旧消息下标断言重新加入中途 system 消息。新增回归文件还须登记到门禁清单，单独执行通过不代表 CI 已覆盖。

使用 `sourceHarness` 的测试显式隔离数据库和模型适配器；生产代码增加运行时 import 后，夹具必须补齐对应装配。纯归一化规则应加载真实实现，并以手工确定的输入输出验证业务参数，而不是在替身中复制规则。出现 `Unmocked production dependency` 时先定位新增 import 与夹具边界，不应放开任意生产依赖来绕过隔离。

门禁不执行真实供应商或浏览器验收。修改交互、供应商协议或桌面打包时，要单独说明尚未执行的对应验收，不能由门禁通过推断其结果。
