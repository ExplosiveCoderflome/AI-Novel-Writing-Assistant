# 短篇结构化失败诊断

## 背景与范围

短篇规划空内容发生在 JSON 校验之前；空 stop、只有思考且额度耗尽、明确过滤与 SDK 网络失败不能统一归因于超时。诊断目标是保存足够的可观察证据，让同一创作任务可以定位和恢复；没有具体模型、端点与响应样本时，不能宣布修复某供应商的参数兼容问题。

持久诊断覆盖带 taskId 的创作意图、参考抽取及短篇 Prompt。公共结构化调用保留原错误大类和 cause，增加细分响应证据；其他业务不因此新增默认诊断记录。

## 事实源与隐私

`StructuredInvocationDiagnostic` 按调用组记录每次生成、格式修复、策略切换及配置内备用模型。记录实际模型、协议、结构化策略、阶段、序号、耗时、结束原因、内容及思考长度、可得用量、HTTP 状态、供应商错误码、Retry-After 与受限异常链元数据。格式修复独立计量，调用组的总尝试数可核对。

正文、提示词、思考原文、凭据、端点和原始错误消息不进入此表；该范围内 repair debug log 只写脱敏元数据。内存错误仍保存 cause，以供受控排查。未知字段为 null；未知错误显示未知，不按错误文案猜“网络/超时”。历史全局日志与主动打开的 AI 实况有自己的内容策略，本诊断不替代它们。

## 证据与动作

| 观测证据 | 诊断与恢复原则 |
| --- | --- |
| 无正文，正常结束或无结束原因 | 空响应。原生 JSON 可以有界降级到其他已支持格式；最终空响应停止原样重放，不能修复出空计划 |
| 无正文、有思考，finish=length/max_tokens | 思考消耗输出额度。核对实际额度和推理配置，不直接改超时 |
| 有正文，finish=length/max_tokens | 输出额度耗尽。保留未完整返回的证据，不把截断方案当成功 |
| 明确 refusal/content_filter | 显示拒绝或过滤，停止自动重放和备用模型切换 |
| HTTP 429 与 Retry-After | 有限重试且不缩短等待；超过一分钟交回源页面，等待时间到后再继续 |
| SDK 连接码、超时类型 | 区分临时网络与超时，沿用已配置且受限的重试次数 |
| 语法、schema 或 postValidate 失败 | 分别记录格式、结构或业务校验，沿用有限修复/语义重试，不伪造字段或放宽校验 |
| 没有可判定的类型或状态 | 保持 unknown，使用定位 ID 与上游样本核对 |

明确取消不自动恢复。备用模型只使用已有配置，限流等待期间不能切换到同一供应商规避等待。成功的后续尝试会消除源页历史失败摘要；任务运行时不把尚未完成的记录显示为失败。

## 定位顺序

1. 在创作页或本篇短篇页查看原因、尝试次数及诊断 ID；运行记录只用于查看与返回来源页。
2. 按任务、诊断 ID 和 invocationId 核对实际阶段、模型、策略、结束原因、长度与用量；缺失字段需要另取上游证据。
3. 若是格式修复失败，分别检查原请求和 repair 行，SDK 原因与状态不能在包装中丢失。
4. 核对恢复入口：首次生产按片段继续，修订按已保存作业继续，replan_required 必须先预览确认。诊断不是清除人工等待的命令。
5. 只有拿到实际型号的可重复样本和调用授权后，才核对推理开关、模型额度与协议参数。不把离线故障桩等同于真实服务修复。

## 验证边界

新建临时 SQLite 与离线流/SDK 故障可验证分类、异常链、用量、等待、隐私及恢复编排；不能证明真实生成质量、真实模型兼容性、PostgreSQL 实例执行或桌面 UI 体验。#184 的具体上游根因在对应样本取得前保持未确认。

相关模块：`platform/llm/diagnostics`、`llm/structuredInvoke*`、`prompting/core/promptRunner`、`modules/novel/creation-studio`、`modules/novel/short-story`。参考合同和修订保护见 [短篇工作流](../workflows/creation-studio-short-story.md)。
