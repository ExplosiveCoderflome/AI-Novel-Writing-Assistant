# 章节可靠性隔离验证

## 背景

章节执行失败可能发生在正文保存、验收缓存、预算领取、修复复审和资产提交之间。仅用正常生成测试或最终任务状态，无法判断中断后是否仍保留正文、是否重复调用模型，以及下一章是否拿到最新事实。

## 验证边界

`server/tests/novelProduction/` 直接转译当前 runtime 源码并执行真实控制流，外部依赖通过显式白名单替身提供。未声明依赖立即报错，不自动加载数据库、模型工厂或网络服务。该套件无需构建 dist，也不验证 TypeScript 类型正确性。

使用模拟保存值、调用序列、调用计数和异常结果检查可观察行为。不要复制业务算法到测试中再验证副本。资产协调器内部替身只证明协调器的返回、缓存与重入语义，不能据此声称真实数据库消费者具有幂等性。

## 已知缺陷与回归测试

目标合同尚未实现时，使用带 `KNOWN` 与问题编号的普通特征测试，精确断言当前缺陷表现。不要用整个测试函数的 TODO 容忍错误：它会同时容忍加载失败、替身错误及其他意外异常。KNOWN 测试通过仅表示缺陷仍按预期复现，不代表目标行为正确。

修复对应缺陷后，把当前行为断言替换为目标合同并删除 KNOWN 标识。不得为了测试通过保留错误产品行为。加载错误和断言错误均须产生非零退出码；对测试基础设施调整后应做内存注入验证，避免污染源码。

正常路径的精确调用序列属于当前基线；改变定稿边界后应依据新合同更新，不应为了保留旧调用顺序阻碍修复。尤其应区分正文可读、质量判定完成与连续性事实提交完成。

## 运行方式

在仓库根目录运行：

```powershell
node --test --test-reporter=spec server/tests/novelProduction/*.test.js
```

现有 `server/scripts/run-tests.cjs` 会递归发现该目录中的 `.test.js`；无需新增测试运行器。源码加载辅助文件采用 `.cjs`，不作为独立测试发现。

`artifactCheckpoint.test.js` 保留真实同步协调器、检查点读取、领取、失败标记及成功标记逻辑，仅模拟持久层与资产抽取服务。它覆盖服务实例更换后的重新领取和成功跳过；不等同于真实 Worker 重启或真实消费者事务验证。

章节同步失败测试应验证错误向上传递和直接重入后的同步行为，不规定质量状态一定回退。外层执行器是否跳过待收尾章节，需要独立测试调度与恢复路径，不能由单章函数重入推断。

## 何时扩大验证

- 涉及持久预算、Worker 租约或重启：补真实数据库适配层测试与恢复测试。
- 涉及资产部分应用：逐个消费者验证同版本幂等和旧版本拒绝。
- 涉及 Prompt 或修复选择：补保存输出回放，必要时使用明确预算的小规模模型抽样。
- 涉及共享类型或运行时结构：运行针对性类型检查，源码转译不能替代类型检查。

模拟调用次数不代表计费次数、生产 token 或真实小说质量；正常控制流通过不能代替整本完成验收。
