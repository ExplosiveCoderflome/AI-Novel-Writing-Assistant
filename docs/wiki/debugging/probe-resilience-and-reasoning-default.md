# 新增厂商默认关闭思考与探测韧性

## Background

结构化调用要求非思考输出时，系统只对做过兼容探测的模型知道该发哪个关思考参数（见《未探测厂商的思考开关》`unprobed-thinking-toggle.md`）。新建厂商默认思考开启时，未探测的新厂商会在结构化步骤里照常思考，可能耗尽输出预算。新建厂商默认自动探测本应补上这一环（见《自定义厂商默认自动探测》`auto-probe-default-on.md`），但探测本身在两类端点上站不住：请求连发会撞上按秒计的限流，一次 429 就让整场探测失败；思考模型的推理会先吃掉 128 token 的探测预算，探测只能看到截断输出。

## Decision

新增厂商默认关闭思考，同时让探测在限流与思考模型面前站得住。默认值只管新建厂商的初始选择，探测负责让这个选择在首次使用前变成线上真实发出的参数。两者缺一不可：只改默认值，未探测厂商仍发不出关思考参数；只加固探测，新厂商在探测完成前仍默认思考。

## Current Rule

- 新建厂商的思考默认关闭：创建自定义厂商（`POST /api/settings/custom-providers`）与首次配置内置厂商（`PUT /api/settings/api-keys/:provider`）在请求未带思考选择时，写 `reasoningEnabled=false`。请求显式带值时以请求为准；更新已有厂商时以已存值为准，默认值不翻动已有厂商。
- 思考开关仍只发已证实的参数：默认关闭不改变未探测厂商不猜发参数的姿态。探测探出思考控制后，关闭才变成线上参数；纯思考模型（无可用开关）不受影响，照常思考。
- 探测请求之间留间隔：同一场探测内，除第一次请求外，每次请求前等待 500ms，避免连发撞上限流。间隔可由调用方覆盖，测试用 0 间隔保持快速。
- 探测只重试瞬时失败：429 与 5xx 最多重试 2 次，退避 1s、2s；鉴权失败与 malformed 输出不重试，仍按原有分类处理（鉴权与限流不记为格式失败）。
- 探测预算 512 token：探测答案只是一段小 JSON，512 留出推理之后的回答空间，仍保持廉价。

## Failure Modes

- 探测在限流下重试耗尽后仍失败：只记探测状态为失败，不污染已存能力档案，用户可在兼容性区块手动重试。
- 端点限流窗口比探测间隔加退避更严时，探测仍可能失败：重试与间隔降低概率，不保证通过；失败时厂商仍可用，只是思考关闭不生效，需手动探测或手动配置能力档案。
- 探测结论来自小 schema，可能过度泛化：见《严格结构化格式被拒时降级》（`structured-400-mode-fallback.md`）。
