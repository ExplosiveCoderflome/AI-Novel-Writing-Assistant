# 知识文档索引的代次发布与租约

## 背景与提交边界

Embedding 成功不等于索引发布成功。向量库与本地数据库不共享事务，不能先删旧索引再尝试写新索引，也不能让暂存向量参与正常召回。

每次知识文档执行先取得租约，再为当前文档版本生成独立代次。全部新向量暂存成功后，本地事务按 `job → document` 的锁顺序完成以下操作：

1. 核对任务仍 running、尝试序号相同且租约未过期。
2. 核对文档 activeVersionId 和归档状态没有变化。
3. 只删除预先捕获的旧分块 ID，且同时限定 tenant、knowledge_document 类型和目标文档 ID。
4. 写入全部新分块元数据及代次，保存 committed 清理清单，更新文档索引状态。

事务失败回滚全部本地修改；不会删除文档原文或 KnowledgeDocumentVersion。事务成功是发布的线性化点。之后只清理已不再被本地元数据引用的旧 point ID；清理失败不回退已发布代次，也不能伪报任务全部完成。

## 暂存与读取

- 新 point 的 `indexGeneration` 与本地 metadataJson 中的同名字段一致。代次包含 job、attempt、文档版本和内容/模型信息；不同尝试使用不同 point ID 空间，陈旧执行的回滚无法删除新尝试的结果。
- Hybrid 检索先取得本地已发布代次，向 Qdrant 传入按文档限定的代次过滤，再核对返回 ID 仍存在于已提交元数据。暂存 point 即使得分更高，也不能占据召回预算。
- 历史未标记代次的分块使用 `is_empty(indexGeneration)` 兼容召回；已有索引不需要全量重建。过滤结构参考 [Qdrant 官方过滤说明](https://qdrant.tech/documentation/search/filtering/)。
- Qdrant URL、集合及鉴权在每次操作中固定；不会因处理中修改设置而把后续批次或清理发送到另一集合。
- 向量库已经收到的请求不能被客户端可靠撤销。取消/租约失效后停止发新批次，并以独立代次隔离可能迟到的暂存写入，不能把这种保证称为外部存储的分布式事务。

## 任务、取消与恢复

- `RagIndexJob.runAfter` 在 queued 时表示执行时间，在 running 时表示租约截止。租约为 90 秒，每 15 秒续期；不增加数据库字段。
- 领取任务采用事务和条件更新，同一知识文档不能同时有两个有效执行。每次轮询只恢复过期 running 任务，不能接管仍有有效租约的任务。
- 尝试序号作为 fencing token。取消、被新请求取代、租约过期后，旧执行不能发布、续租或改写新执行的结束状态。
- 文档更新、重建、归档/恢复请求会使该文档旧的 running 请求失效；相反类型的 queued 请求也会取消。源版本改变后不能按旧快照继续写入。
- 发布前失败：回滚该次暂存代次，保留旧本地索引和 embedding 检查点。暂存回滚失败时标记需要人工检查并停止自动重试，即使任务仍有尝试次数。
- 发布后旧 point 清理失败：文档的已发布索引仍可检索，任务保留 cleanupPending 和确切旧 ID。重试读取 committed 清单，仅清理，不重新 embedding 或插入重复分块。
- 发布确认丢失时，恢复路径读取 committed 清单，而不是删除新代次或重新插入。
- 需要暂存回滚或旧 point 清理的结束记录不能被“清空记录”删除；记录删除按读取时的状态、payload 与更新时间做条件比较，防止并发恢复后误删。

## 范围与回滚

该发布路径只用于 knowledge_document。其他小说资产继续使用原有写入流程。本次不新增数据库 schema，不迁移文档、版本或真实集合；代次字段是内部可选 payload/metadata 契约。

尚未在真实数据执行此版本时，可以直接回滚源码。实际发布过新代次后，不应直接切回忽略代次的旧读路径：它可能读到尚未完成清理的暂存/旧 point。应保留代次读过滤，或在获得具体数据操作授权后先核对并完成相应文档的待办清理，再回滚。禁止以删除集合或全量重建作为默认回滚步骤。

验证使用临时 SQLite 和 mock Qdrant，覆盖事务中插入失败、部分向量写入、取消、过期租约、双 worker、归档/恢复竞争、丢失提交确认及清理/回滚故障。真实 Qdrant、PostgreSQL 和 UI/安装验收需要单独集成验证；源码中的锁顺序不能代替这些环境的实际测试。

## 安装回滚边界

安装备份必须同时保留一个已经验证的代次兼容程序。常规程序回滚使用该程序，保留当前数据库、模型配置、原文与外部索引，不自动恢复忽略代次的旧读取逻辑。原始安装文件仍留档；未经单独核对发布状态和外部索引，不把它当作自动回滚目标。新增加法数据库列也必须先在副本中验证该兼容程序仍可读取和保存旧字段。

公开 retrieve 入口把普通资产与知识文档分开查询，再合并结果；混合与全局检索测试应经过该入口，不能把私有文档分支当作混合入口。没有已发布元数据的文档分支应在请求 embedding 前返回，普通资产检索仍可继续。
