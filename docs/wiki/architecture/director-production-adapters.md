# 新导演生产适配的业务边界

## Background

新导演负责授权范围、运行控制、依赖与产物台账；小说业务服务负责生成与内容保存。把旧导演阶段当作业务服务复用，会引入第二套暂停、恢复和进度控制，使运行事实无法保持单一来源。

## Decision

步骤处理器使用模块内部定义的服务端口，由外部装配注入实际业务服务。处理器不导入旧导演阶段、运行时或编排器，也不引入产品提示词。结构化生成仍使用现有 Prompt Registry。

## Current Rule

- 实际业务服务装配属于 `app/director`，不进入步骤或应用内核。明确开篇授权按 AI 卷排序定位，续写按起始章节所属卷定位。未来章节缺少映射时，命令盘点保持只读并允许排队；Worker 使用冻结的目标章数和模型先补齐近期路线，再严格定位目标卷。初始只细化起始章，后续滚动与 JIT 仍由章节生产链负责。新导演全书终点固定为合同授权范围，禁止被可变小说默认章数扩展。
- 已有路线的生产就绪判定与新窗口产物保持一致：从授权起点连续且章序唯一，最低 3 章、目标 5 章，短授权范围相应缩小；只对实际连续窗口落账。目录存在不能代表授权范围准备完成，远期章节不能抵消起始章缺口。窗口服务生成的节奏板必须直接读取落账，不能再次生成而改变章节路线关系；只做规划时仍由独立节奏板与整卷目录步骤负责。
- 新导演业务作业身份存入独立 `directorNext` payload，不使用旧工作流任务 ID。结构化问题决定与作业一起保存，跨崩溃恢复保留；内容闭合验证必须使用当前正文哈希。自动恢复使用条件更新保护人工暂停；显式恢复与决定清除属于用户命令事务，不能放入后台轮询。

- 启动创作输入存入不可变 Run 合同，与启动命令同事务保存；恢复及驾驶方式切换不得重建模型、质量策略、章节范围。世界跳过保存明确禁用合同，后续生成关闭世界上下文；复用模式不能隐式生成。章节质量处理仅映射既有 AI 结构化决定，缺少决定时暴露能力问题，禁止按文案兜底。

- 正文批次完成必须以授权范围内逐章的已保存正文和生产闭合证明为依据，不能仅凭作业状态。恢复必须使用持久化业务作业身份；启动到绑定保存之间的崩溃窗口由底层去重处理。人工恢复状态禁止自动续跑，租约由外层 Worker 续期，避免两套执行生命周期。

- 导演租约和正文执行租约的期限不同。恢复 Worker 取得导演租约时，正文租约仍可能由已退出的进程持有；批次适配器必须在等待期间再次请求条件调度。底层自动恢复以有效租约、人工恢复锁和取消状态为原子写入条件，有效执行租约下不得把作业重新设为排队。不得以新作业替代原作业来规避租约，已经闭合的章节继续按保存事实跳过。

- 已有角色阵容保守保护并复用；空阵容才允许生成，候选必须追加保存，应用前再次拒绝已有角色，不删除关系或重置旧候选状态。此检查不是跨进程锁，仍需单活跃运行与业务写入协调。失败后保留已有角色供盘点复用，不能清库重试。

- 输入读取器接收 `StepContext`，以当前 Run 的持久化输入解析故事想法和模型选项。不得在恢复时重新读取可变的书级模型默认值。
- `story_macro` 将模型提供商、模型和温度原样交给故事宏观服务。输入快照初始化尚未完成时，不应注册到默认 Worker。
- 书级创作约定生成属于小说业务服务，而非导演编排。独立服务复用现有注册 Prompt 与上下文，只返回草稿；旧导演保持进度跟踪和保存，新导演适配器调用同一服务并在保存成功后返回台账引用。旧标准化导出保留兼容转发，禁止复制另一套生成或输出整理逻辑。
- `book_contract` 的保存记录必须有有效 ID 且属于当前小说；不能对生成失败、保存失败或跨书结果落账。生成调用的小说和运行身份由当前 `StepContext` 覆盖，不能信任遗留输入中的旧身份。
- 返回产物引用的前提是业务服务完成保存；步骤不能自行写控制状态，台账由执行器统一记录。
- `world_setup` 通过现有世界网关读取或生成；已有世界不重新生成，缺少作者来源时保守保护。只有取得保存的世界切片才落账。显式跳过世界需要独立持久化合同，不能通过空世界伪造完成。
- `volume_strategy` 依次生成策略、审查策略和生成卷骨架，仅将最终保存结果记为产物。保存时关闭章节执行同步；分卷路线规划不要求全部章节已有执行合同。中间草稿不作为完成产物。
- 节奏板适配按当前运行的结构化目标卷执行，检查工作区小说归属和目标卷存在。保存前后必须有对应目标卷的非空节奏板；不能用其他卷的已有结果充当完成。保存关闭章节执行同步，台账引用包含卷 ID，内容哈希只覆盖目标节奏板，避免无关卷更新影响该产物。输入初始化负责将授权范围绑定到目标卷，不得默认第一卷或用正文关键词选择。
- 桩测试验证适配协议；真实业务服务的类型兼容检查验证接口可接入；两者都不能代替真实 AI、数据库和完整生产联调。
- 章节细化通过可选 `onChapterTaskSheetQuality` 回调保留原 AI 评估与门禁结果，旧调用没有回调时保持原返回值和拒绝方式。回调不是第二次审校，也不得改写 AI 结论。新处理器以 `task_sheet` 模式生成指定范围的完整合同，结构不完整仍失败；结构可用的语义提醒由结构化问题决策端口处理，不能从错误文本推断重规划。该端口的真实装配是启用生产 Worker 的前置条件。
- 步骤返回多条质量债与显式停止信号，执行器统一记录。质量事实和停止事件先于产物台账写入，避免产物让步骤在恢复时被跳过而丢失停止决定；写入停止信号前仍须通过领域守卫。完成优先下人工暂停建议降为质量债；质量优先只有明确 `pause_for_manual` 决定才进入人工恢复状态。恢复读取持久化事实，后台轮询不得清除暂停。
- 执行合同同步复用全书路线同步服务，窗口是合同检查范围，不是写入范围。窗口内必须有完整任务单与场景计划，其他章节可留待 JIT；固定保留正文和禁用删除。同步后从真实章节表读取合同，核对目标 ID/顺序、合同内容和执行参数，同时核对窗口外既有正文保留。只有核对通过才能对保存的窗口合同落账；同步摘要或未保存的规划不能冒充真实执行合同。正文保护异常属于数据完整性停止，禁止自动用重写或清空来修复。
- 卷拆章适配显式调用 `chapter_list/full_volume`，只选择持久化输入指定的卷，复用底层按节奏段续接及相邻卷校准。开始前需有目标节奏板；生成和保存后都需有目标卷非空章节列表，服务的 `chapter_list_partial` 状态不能作为完整产物落账。引用包含卷 ID，哈希只覆盖保存的目标卷章节规划；后续章节执行合同同步属于独立步骤，拆章保存不得隐式触发。
