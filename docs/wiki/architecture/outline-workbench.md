# 独立大纲工作台边界

## 背景

写作新手需要先把想法整理成总纲、卷章、人物草案、伏笔和固定设定，再决定是否开书。如果直接复用 `Novel` 或卷生产文档，大纲会在尚未开书时依赖小说 ID，并可能触发卷同步、人物创建或正文生产，形成多个权威来源。

AI 生成和文本导入也不能直接覆盖用户正在编辑的大纲。用户需要先看建议、来源和影响，再确认哪些内容成为正式版本。

## 决策

独立大纲是独立于小说生产链的规划资产，由 `OutlineProject`、不可变 `OutlineRevision` 和待确认 `OutlineProposal` 组成。A1 只负责大纲的创建、编辑、版本、提案与导入导出；开书交接属于 A2；工作台入口仅导航到独立的确认预览，A1 保存和采纳不触发小说生产。

当前文档只由已保存修订决定。手动保存、AI 采纳、导入确认和历史恢复都创建新修订，不能更新或删除既有修订。AI 调用和导入解析必须先形成候选，不能直接推进项目当前版本。A2 开书必须携带用户选定的 revisionId，历史修订详情通过修订详情接口单独读取，不能用列表摘要或项目当前 document 替代。

## 当前规则

### 资产与版本边界

- 大纲项目不要求 `novelId`，不得写入 `Novel.outline`、`Novel.structuredOutline`、`VolumePlanDocument` 或正式人物、章节、伏笔台账。
- `OutlineProject.currentVersion` 是并发控制版本，`currentRevisionId` 指向当前不可变文档。写操作必须校验 `expectedVersion`，过期保存或提案不得覆盖新内容。
- 恢复旧版时以旧文档为内容、以当前修订为父版本创建新修订，保留中间历史。
- 节点身份使用稳定 ID，章序只负责展示；跨节点关系不得依赖标题或“第几章”。

### AI 提案边界

- 初始生成、修改建议和导入解析都使用 Prompt Registry 中的结构化 Prompt；模型调用放在数据库事务外。
- 初始生成先保存为 `initial_generation` 提案。采纳时由服务端分配稳定节点 ID、重建卷章关系并校验完整文档，不能把它当作普通字段更新操作处理。
- 修改提案记录 `baseVersion`。采纳时从基线文档复制候选，只应用选中的结构化操作，并检查依赖、节点类型、引用闭合和必填字段。
- 桌面提案面板按操作展示前后内容、理由、影响和依赖。前端在缺失依赖时禁用“采纳所选”，服务端仍必须重新校验完整组合；前端提示不能替代领域校验。
- AI 输出中的 `clientRef` 只用于候选内部关联，不是持久节点 ID。部分采纳后的原提案不得重复执行剩余操作。

### 导入来源与确认边界

- Markdown/TXT 的结构理解由 AI 完成，标题或关键词规则只能作为模型证据，不能成为静默分类或丢弃原文的兜底路径。
- 每个带来源的解析节点都要返回稳定 `nodeId`、原文起止位置和原文片段。必须能用 `sourceText.slice(start, end) === fragment` 验证对应关系。
- 来源区间按各自文本分块定位，避免相同片段在其他分块中被错误匹配。无法匹配的片段进入显式的未匹配列表，不得计入已覆盖内容。
- 覆盖字符数按区间并集计算，不能累加重叠片段后把同一原文重复计数。未分类、未匹配和未覆盖内容必须在确认前可见。
- 导入预览绑定用户、原文和短期 token，确认时才创建项目或新修订。确认页可调整标题、章节所属卷和节点引用；服务端只应用这些允许编辑的字段，保留原候选的其他内容与稳定节点 ID。
- 导入确认后的卷章节列表必须由章节所属卷重新派生，人物出场、伏笔埋设/回收和固定设定范围必须校验目标类型，不能只检查引用 ID 存在。JSON 是无损往返格式，Markdown 主要用于阅读，不承诺无损回导。

### 前端边界

- 桌面端通过独立 `/outlines` 路由进入列表和工作台，不改小说内已有“大纲/结构大纲”的含义。
- 手机端不暴露复杂编辑、提案采纳和导入确认，只保留电脑端使用提示或只读概要。
- 按大纲开书的桌面入口只对已保存且无本地未保存编辑的修订开放；服务端绑定查询失败时禁用入口或显示错误，不能按“尚未绑定”继续创建。预览和确认共用阶段化合同中的篇幅、卷预算及优化提议字段；创建请求保留同一幂等键以支持网络重试。
- 导入确认区需要让用户按节点核对来源片段，而不只展示解析节点数量。
- 历史区允许选择任意两版调用确定性差异查询，并以起始版本为恢复来源。恢复始终创建新修订，不能用旧快照覆盖当前修订指针或删除中间历史。

## 失败模式

- **初始提案点击采纳但没有新修订：** 检查是否错误进入普通 `operations` 分支，并验证候选 `clientRef` 到稳定 ID 的映射及卷章引用。
- **导入覆盖率超过原文或节点证据错位：** 检查是否直接累加重叠区间、是否跨分块搜索相同文本，以及覆盖记录是否绑定最终 `nodeId`。
- **AI 输出缺少来源却显示解析成功：** 不得编造偏移或用相似文本替代；应进入未匹配列表并保留人工确认。
- **并发保存覆盖新内容：** 检查事务内版本条件和提案基线，不能用事务外读取到的旧版本直接更新当前指针。
- **独立大纲触发小说生产：** 检查模块依赖方向；A1 不应调用 Novel、卷工作区持久化、自动导演或章节执行服务。

## A2 桌面交接与小说侧投影

- 所有开书请求/响应类型直接引用 `shared/types/outlineOpenBook.ts`，客户端不得维护另一份近似字段；卷预算为 nodeId→章数，预览返回 chapterQuota/from/to。
- 未绑定为 GET 200/null；404 是项目不存在，不能吞掉后开放创建。绑定优先于修订深链验证，重复进入只给原书导航。
- 确认采用已经预览的输入及 requestHash；输入改变会使确认失效，同一次失败重试沿用原幂等键。每卷章数、全书区间和保留内容必须显式确认。
- 小说只读 workspace 可选附带 `outlineBinding` 及已保存的宏观准备，直接复用权威绑定服务；无绑定书不读源修订，不初始化规划，不触发模型。
- A2 的宏观/书约/世界/卷节奏/章节路线门均有已保存结果审阅入口；确认身份来自服务端当前 reviewContexts，URL 不承载控制版本或资源身份。
- “准备第N章”的步骤授权明确排除正文生产者；“开始写第N章”只提交 N–N，固定 assisted，不能被通用多章/全自动表单替代。
- 计划来自 binding.plannedPayoffs，独立分组、不计实际台账统计。实际来源读取须接受 outline_plan 并保留原文证据，不能把合法来源读成损坏。
- 新版差异只展示来源文档变更；采用修订及运行规划不重绑。历史来源阅读显示冻结字段，不把当前编辑页误标成采用的旧版。

- 绑定书的后续正文导航统一进入单章确认区，不显示通用多章建议；导演切换驱动入口隐藏，保留既有恢复/预算/人物确认入口。资料索引恢复仅调用 retry-setup，不重新建书或启动正文。
