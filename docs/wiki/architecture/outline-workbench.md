# 独立大纲工作台边界

## 背景

写作新手需要先把想法整理成总纲、卷章、人物草案、伏笔和固定设定，再决定是否开书。如果直接复用 `Novel` 或卷生产文档，大纲会在尚未开书时依赖小说 ID，并可能触发卷同步、人物创建或正文生产，形成多个权威来源。

AI 生成和文本导入也不能直接覆盖用户正在编辑的大纲。用户需要先看建议、来源和影响，再确认哪些内容成为正式版本。

## 决策

独立大纲是独立于小说生产链的规划资产，由 `OutlineProject`、不可变 `OutlineRevision` 和待确认 `OutlineProposal` 组成。A1 只负责大纲的创建、编辑、版本、提案与导入导出；开书交接属于 A2；工作台入口仅导航到独立的确认预览，A1 保存和采纳不触发小说生产。

当前文档只由已保存修订决定。手动保存、AI 采纳、导入确认和历史恢复都创建新修订，不能更新或删除既有修订。AI 调用和导入解析必须先形成候选，不能直接推进项目当前版本。A2 开书必须携带用户选定的 revisionId，历史修订详情通过修订详情接口单独读取，不能用列表摘要或项目当前 document 替代。

## 当前规则

### 资产与版本边界

- 大纲项目不要求 `novelId`，不得写入 `Novel.outline`、`Novel.structuredOutline`、`VolumePlanDocument` 或正式人物、章节、伏笔台账。
- `OutlineProject.currentVersion` 是并发控制版本，`currentRevisionId` 指向当前不可变文档。写操作必须校验 `expectedVersion`，过期保存或提案不得覆盖新内容。
- 恢复旧版时以旧文档为内容、以当前修订为父版本创建新修订，保留中间历史。
- 节点身份使用稳定 ID，章序只负责展示；跨节点关系不得依赖标题或“第几章”。

### AI 提案边界

- 初始生成、修改建议和导入解析都使用 Prompt Registry 中的结构化 Prompt；模型调用放在数据库事务外。
- 初始生成先保存为 `initial_generation` 提案。采纳时由服务端分配稳定节点 ID、重建卷章关系并校验完整文档，不能把它当作普通字段更新操作处理。
- 修改提案记录 `baseVersion`。采纳时从基线文档复制候选，只应用选中的结构化操作，并检查依赖、节点类型、引用闭合和必填字段。
- 桌面提案面板按操作展示前后内容、理由、影响和依赖。前端在缺失依赖时禁用“采纳所选”，服务端仍必须重新校验完整组合；前端提示不能替代领域校验。
- AI 输出中的 `clientRef` 只用于候选内部关联，不是持久节点 ID。部分采纳后的原提案不得重复执行剩余操作。
- `dependsOn` 只能引用同一提案中的其他 `operationId`，禁止填卷/章节等节点 ID；生成后与采纳前都由服务端结构化校验，循环依赖、重复操作编号、缺少依赖勾选均拒绝。
- 新增章节必须使用 `add_node` + `nodeType=chapter`，并在 `fields.volumeNodeId` 填写已有卷 `nodeId` 或同提案新建卷的 `clientRef`；禁止用 `update_fields` 改 `chapterNodeIds` 表达增章或调序。
- 可恢复的提案结构问题映射为面向用户的中文 `400`（冲突类仍用 `409`）；真实内部故障保持 `500`。不得静默丢依赖、猜测所属卷，或把所有失败一律改成 `400`。采纳事务保持全有或全无，失败不得部分写入。
- 初始生成路径（默认约 3 卷 10 章）与交互完善提案校验分离；五卷不是固定默认，也不因交互校验改动初始生成策略。

### 人物调整的多角色审阅

人物联动以项目、已保存版本和人物节点 ID 确定共同基线。快照含大纲、选中人物相对父修订的文字改动，以及绑定作品中有正文的章纲节点 ID。人物审阅先确定动机和保留项，卷章审阅检查行动因果，伏笔审阅利用前两步判断线索铺垫和揭晓顺序。没有显式人物引用的旧大纲仍可用，审阅可以结合剧情文字判断关联。

三份结果经过相同的字段、引用和依赖校验后才形成待审提案。同一节点的互补字段归为一个勾选项，同一字段的矛盾改法需先统一。保留说明不产生写操作。只有作者采纳的项目进入一个新修订。采纳时重读版本和已有正文的章节，已绑定小说的采用版本、章节计划及正文由各自工作流维护。调整待审提案时带回原建议及作者反馈，原建议在作者决定前仍可查看。

#### 对话、提案与修订

共用对话组件从适配器读取轮次，发送作者输入和所讨论的结果标识，按需结束仍在运行的一轮。接入模块提供结果状态、追问条件和审阅内容。整纲讨论按项目隔离，人物讨论按项目和人物的稳定 ID 隔离。浏览器记住上次使用的讨论范围，消息及采纳状态以服务端为准。其他工作台可以复用 `components/agentConversation/AgentConversation`、`shared/types/agentConversation/turn` 和服务端 `modules/agentConversation`，自行定义资源范围、权限、模型和成果的写入规则。

- 从想法起草和打开已有大纲均进入整纲对话。开场问题只填入编辑框，由作者发送。整纲对话使用 `/api/outlines/:id/conversation`，由注册提示词 `outline.workbench_dialogue` 结合保存稿、提案和历史选择讨论、完整初稿或逐项修改。解释和澄清只写回复。早期整纲提案可在同一记录中查看并继续讨论。
- 采纳完整初稿会生成整份大纲的新修订，已有内容时须在采纳按钮明确说明替换范围。编辑提案相对保存稿描述完整变更，作者可勾选操作，总纲文字通过其稳定节点 ID 编辑。
- 接收消息时先持久化。相同请求标识和内容可安全重送。每个讨论范围同时只运行一轮，离开页面后服务端可以继续生成。进程中断时可在工作台结束该轮并重新发送。迟到的模型结果须通过轮次状态检查。
- 追问携带上一份提案标识。模型看到完整的上一版建议、关联讨论中最近的作者要求和答复，以及当前保存的大纲快照。对话上下文最多取 12,000 个字符，历史页保留全部轮次。解释性答复保留原提案。新方案生成成功才替代同一修订下的上一份待审方案；替代状态、提案和答复在同一事务中提交。
- 草稿和候选不直接进入修订。作者在工作台逐项采纳时仍校验基准版本、依赖和已有正文。历史可查看实际采纳的项目，早期部分采纳记录若缺少逐项凭据，只展示整体状态。大纲版本变化后可发起重审，模型按最新快照及旧版的采纳状态给出新建议。

#### 运行中回复的预览

整纲和人物讨论沿用 LLM 实况中的模型增量事件。每轮调用使用独立的 `itemKey`，服务端按轮次订阅，投影出面向作者的 `replyText`。最后一位人物联动审阅者输出综合回复。`reasoning_delta` 单独按审阅阶段显示，即使请求策略关闭思考，也应展示厂商实际返回的片段。仅有 `usage_updated` 中的思考 token 时，界面显示用量；请求开关和 token 数都不能用来推断思考原文。提示词、审阅草稿和未经校验的操作不进入对话预览。

前端通过与导演正文预览共用的 SSE 快照订阅接收消息，使用与创作中枢相同的 Markdown 组件渲染。订阅地址经过项目、人物范围及轮次校验。重连读取本进程最新的临时预览，页面离开仅解除订阅。思考预览沿用模型实况完成后十分钟的进程内保留期，重启即失效。后续模型调用只带作者消息、正式答复和关联提案。持久化的轮次记录负责恢复和最终状态，只有提案及轮次的提交事务完成后才展示可采纳的修改。若模型以整段返回或修复后才得到可读内容，则展示已验证的回复。

#### 试点接入合同

在现有应用 API 鉴权下使用 `/api/outlines/:id/character-impact`。外部工具应只接入读取上下文和提交待审结果两项能力，作者在大纲工作台决定采纳。此版本沿用应用级授权，没有独立的第三方身份或按角色分配的凭据。

| 请求 | 用途 |
| --- | --- |
| `GET /conversation?characterId=…` | 读取该人物跨修订的讨论、提案标识和处理状态。 |
| `POST /conversation/turns` | 提交人物、当前修订、要求、请求标识和可选的上一提案标识。返回轮次标识，工作台随后读取结果。 |
| `POST /conversation/interrupt` | 明确结束指定人物的一轮生成并阻止结果发布。 |
| `GET /context?characterId=…&baseVersion=…` | 取得同版快照。保留返回的节点 ID，已有正文只返回标识。 |
| `POST /generate` | 工作台按人物、卷章、伏笔顺序调用规划模型。提交 `characterId`、`baseVersion`、`requestText`。带上同人物、同版本的 `priorProposalId` 可继续完善待审建议。 |
| `POST /proposals` | 外部工具直接提交下面的结构，不触发模型调用。相同版本内重送同一份结果会返回同一条提案。 |
| `GET /proposals?characterId=…&baseVersion=…` | 列出该人物和版本的待审结果。重新进入人物节点或点击“刷新对话”均可读取。 |

例如，同一版本中人物节点为 `shen`、后续卷节点为 `v2`，外部工具可提交以下内容。真实调用应使用快照中的标识。

```json
{
  "characterId": "shen",
  "baseVersion": 1,
  "requestText": "让沈禾开始查证账册，但仍救师父。",
  "reviews": {
    "character": {"changes": [{"nodeId": "shen", "field": "motivation", "value": "查清账册来历，同时报答救命之恩", "reason": "区分怀疑与报恩", "dependsOnNodeIds": [], "risks": []}], "retained": []},
    "plot": {"changes": [{"nodeId": "v2", "field": "summary", "value": "师徒同行逃城，沈禾暗中查账", "reason": "让动机落实为行动", "dependsOnNodeIds": ["shen"], "risks": []}], "retained": []},
    "payoff": {"changes": [], "retained": []}
  }
}
```

人物审阅可改选中人物的作用、目标、动机、冲突、秘密和成长方向。卷章审阅可改卷纲和章纲的叙事字段。伏笔审阅可改铺垫、回收描述和章节结尾钩子。正文、排序、人物名和固定设定均不在本接口的可写范围。无须改动时可以只提交保留说明。过期版本返回 409，范围或依赖不成立返回 400。正式合同见 `shared/types/outlineCharacterImpact.ts`。

### 导入来源与确认边界

- Markdown/TXT 的结构理解由 AI 完成，标题或关键词规则只能作为模型证据，不能成为静默分类或丢弃原文的兜底路径。
- 每个带来源的解析节点都要返回稳定 `nodeId`、原文起止位置和原文片段。必须能用 `sourceText.slice(start, end) === fragment` 验证对应关系。
- 来源区间按各自文本分块定位，避免相同片段在其他分块中被错误匹配。无法匹配的片段进入显式的未匹配列表，不得计入已覆盖内容。
- 覆盖字符数按区间并集计算，不能累加重叠片段后把同一原文重复计数。未分类、未匹配和未覆盖内容必须在确认前可见。
- 导入预览绑定用户、原文和短期 token，确认时才创建项目或新修订。确认页可调整标题、章节所属卷和节点引用；服务端只应用这些允许编辑的字段，保留原候选的其他内容与稳定节点 ID。
- 导入确认后的卷章节列表必须由章节所属卷重新派生，人物出场、伏笔埋设/回收和固定设定范围必须校验目标类型，不能只检查引用 ID 存在。JSON 是无损往返格式，Markdown 主要用于阅读，不承诺无损回导。

### 前端边界

- 桌面端通过独立 `/outlines` 路由进入列表和工作台，不改小说内已有“大纲/结构大纲”的含义。
- 手机端不暴露复杂编辑、提案采纳和导入确认，只保留电脑端使用提示或只读概要。
- 按大纲开书的桌面入口只对已保存且无本地未保存编辑的修订开放；服务端绑定查询失败时禁用入口或显示错误，不能按“尚未绑定”继续创建。预览和确认共用阶段化合同中的篇幅、卷预算及优化提议字段；创建请求保留同一幂等键以支持网络重试。
- 导入确认区需要让用户按节点核对来源片段，而不只展示解析节点数量。
- 历史区允许选择任意两版调用确定性差异查询，并以起始版本为恢复来源。恢复始终创建新修订，不能用旧快照覆盖当前修订指针或删除中间历史。

## 作者的编辑与审阅路径

- 目录按章节自身的 `volumeNodeId` 归卷，卷和章各按 `order` 排序。手动添加章节时，同时更新新章节的归属和所属卷的章节列表，随同一份草稿保存。搜索保留卷名作为章节上下文。来自开书检查的 `nodeId` 和关联内容链接都选择同一个稳定节点，重名、改名不影响定位。
- 编辑器按节点类型提供字段。即使旧文档省略了人物动机、章节目的等可选字段，作者也能补填。节点关系来自文档中的显式引用，双向展示，作者可沿着人物、卷章和伏笔往返核对。
- 同一大纲内切换节点共用一份草稿。第一次手改固定基准修订，后台刷新不得覆盖草稿。发现版本冲突时保留输入，作者决定何时载入新版。生成、采纳与版本恢复使用已保存修订。
- “从一个想法开始”进入初版生成，空白大纲进入编辑。打开入口或切换视图不调用模型。宽屏并排展示目录、编辑与审阅，较窄时切换视图，保存和采纳均在源大纲完成。

## 失败模式

- **初始提案点击采纳但没有新修订：** 检查是否错误进入普通 `operations` 分支，并验证候选 `clientRef` 到稳定 ID 的映射及卷章引用。
- **导入覆盖率超过原文或节点证据错位：** 检查是否直接累加重叠区间、是否跨分块搜索相同文本，以及覆盖记录是否绑定最终 `nodeId`。
- **AI 输出缺少来源却显示解析成功：** 不得编造偏移或用相似文本替代；应进入未匹配列表并保留人工确认。
- **并发保存覆盖新内容：** 检查事务内版本条件和提案基线，不能用事务外读取到的旧版本直接更新当前指针。
- **独立大纲触发小说生产：** 检查模块依赖方向；A1 不应调用 Novel、卷工作区持久化、自动导演或章节执行服务。

## A2 桌面交接与小说侧投影

- 所有开书请求/响应类型直接引用 `shared/types/outlineOpenBook.ts`，客户端不得维护另一份近似字段；卷预算为 nodeId→章数，预览返回 chapterQuota/from/to。
- 未绑定为 GET 200/null；404 是项目不存在，不能吞掉后开放创建。绑定优先于修订深链验证，重复进入只给原书导航。
- 确认采用已经预览的输入及 requestHash；输入改变会使确认失效，同一次失败重试沿用原幂等键。每卷章数、全书区间和保留内容必须显式确认。
- 小说只读 workspace 可选附带 `outlineBinding` 及已保存的宏观准备，直接复用权威绑定服务；无绑定书不读源修订，不初始化规划，不触发模型。
- A2 的宏观/书约/世界/卷节奏/章节路线门均有已保存结果审阅入口；确认身份来自服务端当前 reviewContexts，URL 不承载控制版本或资源身份。
- “准备第N章”的步骤授权明确排除正文生产者；“开始写第N章”只提交 N–N，固定 assisted，不能被通用多章/全自动表单替代。
- 计划来自 binding.plannedPayoffs，独立分组、不计实际台账统计。实际来源读取须接受 outline_plan 并保留原文证据，不能把合法来源读成损坏。
- 新版差异只展示来源文档变更；采用修订及运行规划不重绑。历史来源阅读显示冻结字段，不把当前编辑页误标成采用的旧版。

- 绑定书的后续正文导航统一进入单章确认区，不显示通用多章建议；导演切换驱动入口隐藏，保留既有恢复/预算/人物确认入口。资料索引恢复仅调用 retry-setup，不重新建书或启动正文。

- 只有总纲的开书在启动时没有 targetVolumeId；战略保存后使用绑定的 runtimeVolumes 章序槽位定位待确认卷，不能因启动快照未含新卷而失去审阅入口。缺失或重叠槽位应报完整性错误，禁止随便选第一行。

- 开书结构错误展示把协议字段和稳定引用转换为节点中文标题，并按错误中第一个明确引用定位编辑入口。nodeId深链仅选择源编辑节点，不承载运行控制版本或生成授权。
