# 正文生产内核：运行进度、提交与恢复

## 背景与归属

同一章节可能经历自动批次、手动生成或重新审校。章节 ID 不能独自标识一次生产，跨作业共用阶段结果会错误复用模型配置、问题策略或选稿。`ProductionUnitRun` 以调用方注入的 `ownerKey + chapterId` 唯一，记录该次运行的配置快照、进度及恢复制品；正文最终来源仍是 Chapter。

内核不解析导演任务或工作流身份。调用方拥有作业范围、控制状态和持久租约，并把这些核对注入 `Fence` 与仓储事务内的 `assertOwnership`。app 层负责组装；领域不接触数据库。

## 阶段领取与恢复

1. 加载或创建运行，核对书/章节/顺序与全部快照；同作业改变模型、问题策略或配置必须拒绝。
2. 通过版本 CAS 保存 activeStage、activeRequestKey 和实际输入描述。并发领取只有一方成功。
3. 真实调用前持久预约预算，长操作前后及保存前核对所有权和编辑保护。
4. 阶段结果、制品及回执与领域进度一起 CAS 保存；已完成阶段恢复时直接复用。

请求身份包含作业、章节、阶段、正文哈希、完整实际输入指纹、Prompt 版本、模型与配置快照。正文哈希相同不能单独授权结果复用。模型快照只接受白名单字段，不包含 API 密钥。

远端已执行但进程尚未保存结果的窗口不能保证物理请求严格一次。active 领取没有可确认的持久结果时返回 `unknown`，禁止自动重发。恢复端口只读取已有结果；不能把“查询结果”实现成新的生成调用。已知无变化/修复失败用结构化阶段结果保留原稿和债务；未知调用结果不能伪造为已完成。

回填的只读输入也必须持久化。摘要、角色或兑现回填会改变下一次读取的账本，重新准备输入可能产生另一个请求身份。统一抽取输入随阶段保存；严格兑现复核和时间线输入先写独立检查点，再领取模型请求。恢复模式下的模型检查点查询不得创建新领取或预约额度。

恢复读取区分三种模型状态：成功回执可复用，running 且无结果表示未知，缺失或明确释放为 ready 表示尚未发送。最后一种只允许保存 pending 边界、解除外层领取；恢复读取本身不能发模型请求。预算明确拒绝的请求保留 `deferredDescriptor`，显式追加预算后复用完整原始输入，避免前序消费者改变账本后重复抽取。

## 正式准备的子请求与规划提交

正式准备可能包含连续性核对、执行合同细化、语义审查和章计划。外围前后检查不能保护旧服务内部的模型和业务事务；这些能力应提供只读来源/请求准备、注册 Prompt 执行和调用方事务提交端口。默认原生调用与新调用方共用规划规则，不复制整套规划引擎。

准备阶段的领取保护原始正文及来源版本，不能借用要求已选稿/已提交正文的回填权限。各个子请求保存完整输入、有效模型身份和结果；已保存结果可复用，未知模型结果不得因换 worker 重发。业务提交与成功回执同事务，回执还保存提交后的章节及卷来源版本。

后续步骤使用提交回执推进来源版本，不能重新读取人工改动后的卷工作区并将其接受为原请求的新输入。恢复优先读取已经成功的业务回执；不能为了重建外层 prepare 结果，再次执行已提交的合同或章计划。原生有效章计划仍按执行合同指纹复用。

前文时间线只读核对当前正文的兼容检查点；缺失时返回具体来源页和章节，不能由本章准备补写授权范围外的前文。`getVolumes({hydrateCanonical:false})` 仍可能补建卷记录，不是纯读取接口；正式准备必须使用显式只读入口。上下文组装的 RAG 等外部依赖也应沿真实调用逐项核对，不能仅根据函数名称假定没有外部请求。

## 原生检索与空账本的读取边界

上下文读取也可能付费或写入：embedding/重排直接发送 HTTP，ensureCollection 可能创建索引，空伏笔账本可能触发模型同步。外围 Chat 预算不能保护这些效应，因此正式准备安装并发隔离的 RAG 执行端口及伏笔账本只读范围；普通旧调用保持原行为。

检索先保存配置与来源版本，再按每次实际 HTTP 请求领取、预约及记录结果。重试和自适应拆分有独立身份；已保存物理结果可用于重建外层上下文，未知结果不能自动重发。配置与请求许可使用捕获副本，调用方修改内存对象不能扩大窗口或替换模型。来源、正文或租约改变时禁止发布；失权后的实际用量仍需记账。

正式正文准备只 GET 校验向量集合维度与过滤索引，不负责修复索引。未就绪返回知识库来源页，不隐式关闭检索。空账本按未同步的真实读取结果返回，不在准备阶段调用 syncLedger；抽取与写回留在已授权 reconcile 事务边界。下层兼容降级不能清除执行范围已锁存的保护失败。

## 正文和阶段回执的原子性

`PrismaUnitProgressStore` 的更新在事务里复核调用方持久所有权及运行版本。commit 还在同一事务里调用 `ProductionChapterLifecycleService`：核对非空选稿哈希、章节归属、expectedContent 与 expectedUpdatedAt，再保存正文与生命周期状态。

正文版本冲突、失权或运行 CAS 失败时，该事务中的正文与回执整体回滚。不能用“先查询版本，再调用无条件更新”替代这个约束。候选稿只存在运行中的制品里，选定之前不写 Chapter。

事务不包括任何模型请求。故事状态回填独立运行；每个消费者需要自己的内容版本围栏和幂等检查点，不能因为正文 commit 成功就宣称回填完成。`pending` 保持可恢复；`failed` 不能投影成完成。

最终报告属于选中稿的发布边界。原稿/候选评估不直接发布正式报告；回填成功或明确降级后，所选 accept/verify 的报告、审校问题/冲突、章节 approved/reviewed 与 reconcile 回执必须在同一事务发布。审校不可用保留空评分与质量债；不能把兼容传输中的零分当作真实质量分数。CAS 重放不重复写报告，报告写入失败则整笔发布回滚。

章节编辑和阅读入口以 `riskFlags.qualityLoop` 作为当前质量债来源。新内核终态发布必须把选中稿评估、真实修复已用/允许次数及未解决代码写入同一合同；不能只在私有 productionKernel 字段保存一份 UI 无法读取的债务。新评估通过时替换旧质量投影，保留其他风险字段，避免历史重规划标记继续阻塞已通过的当前正文。运行内的阶段债务仍是恢复事实，不靠报告数量反推当前质量债。

局部补丁结果的原文空白也属于版本身份。只用 trim 判断结果是否为空，不得将 trim 后的文本作为候选；否则补丁范围外的首尾空白会被改写，完全无变化的补丁也可能被误判为新候选并额外复验。

旧服务中“正文未变”与“执行者仍有写权限”不是同一件事。相同正文可以跨运行复用，但旧租约不能据此继续写正史。真正的消费者事务必须核对当前运行、阶段请求和持久租约；外围 Fence 与另一个事务里的检查点保护不能替代它。新增适配器时必须沿每个业务写入事务验证，不能只检查调用入口。

业务消费者通过 `PrismaArtifactCheckpointStore.applyConsumer` 在同事务提交业务行与成功回执；事务前后复核调用方持久租约、运行/阶段、所选稿与当前正文，并持有相应锁直到提交。回执键还包含运行、作业与阶段请求身份；替换执行租约可以恢复同作业的成功回执，正文相同不能授权跨作业复用。

资源提案的待确认规则使用既有纯验证器，正式资源、事件与完整规范状态版本一起提交。位置/出场仅接受本书结构化身份和可定位正文证据。摘要、已发生事实、兼容抽取投影与 RAG 入队也共享事务，不能仅返回未持久化的异步任务意图。

严格兑现对账必须分别保存模型结果和事务提交回执。账本未提交时保持 pending；遗漏项保留并标记 stale，书级来源替换与冲突投影由同事务完成。不能把模型返回成功当作故事状态已同步。

时间线的模型抽取与持久写入分开：只对已提交的选稿抽取，把保存的 gate 交给绑定 tx 的现有时间线仓储和服务，避免隐式再次抽取。报告、锚点/事件、兼容检查点与内核回执共同提交，降级保留其质量含义。

三个哈希合同必须明确区分：内核是完整原文的 SHA-256；既有事实/位置/出场投影是折叠空白后的 SHA-256 前 24 位；时间线兼容检查点是 trim 后的 SHA-1。内核围栏不能降低为归一化身份，兼容读取也不能直接使用内核哈希。

## 人工质量暂停

质量优先保留可用正文后再暂停。内核先提交最终选稿及质量债，再持久化绑定该正文哈希的 `qualityPause`，然后返回来源页人工恢复状态；资产回填留待恢复继续。

轮询、工作进程重启和普通重入都不能确认暂停。来源页显式命令完成运行归属、控制状态及正文核对后，通过版本 CAS 保存确认动作。继续执行时复用原策略快照，不能通过改成完成优先或新建作业来绕过暂停。

来源页确认与导演控制恢复、幂等命令记录共享已有事务。事务失败不留下部分确认；人工改稿或书 epoch 变化则拒绝确认。未知模型领取不会因显式恢复或取消而被清除。取消旧运行只结束其控制权限，书已被新运行接管也能取消，不触及新运行或正文。

## 来源页追加章节预算

预算账本保留原生未命中缓存输入加输出的计量口径；只有明确报告且不超过输入量的缓存命中才扣减。总量与分项的差额作为未分类消耗计入；历史仅总量回执不因重放更丰富的遥测而降费。同一物理请求身份下，未知调用各自占用预留，其他已知付费用量仍累加。已发生的用量可在取消后记录。

明确未发送的预算拒绝保存下一步所需额度。来源页只读该拒绝及最新账本；追加额度必须匹配真实 ProductionUnitRun、章节及计量口径，并高于当前上限与已用量加下一步预留。迟到用量须在授权时重新计算。兼容传输中的 `jobId` 为真实 ProductionUnitRun ID，不需要创建旧 GenerationJob。

拒绝状态解除、不可变授权事件、控制恢复与命令记录共享事务；重放不会重复授权。单章授权优先，后续章节授权作为未单独授权章节的默认额度，跨进程恢复后仍有效。冻结契约和已有用量不被改写；调用方内存对象变化也不能扩大已捕获预算。真实执行仍要求新租约、正确版本及每次请求围栏。

## 共用安全工具

长篇内核与短篇只共享 `modules/production/common/index.ts` 的约定和确定性工具。安全补丁必须在同一原文定位全部锚点，确认唯一且不重叠，再倒序应用；失败返回完整原文，避免替换结果被后续补丁再次匹配。

质量债保留来源模块原始结构：长篇的归因、根因、义务和尝试次数，与短篇的原始文字债务可以无损并存。不能据债务文字推测重规划范围。局部质量项默认继续；结构化全局重规划、无可用正文或运行/完整性失败可中断，明确的人工暂停策略必须保留。

上下文预算比较完整输入估算、输出预留与安全余量。默认 UTF-8 字节估算偏保守，不是供应商精确 token 计量；未知窗口不能当作无限。实际用量以观测记录为准，未知值保留 null，取消或失权后仍应记录已经发生的用量。

只读 Prompt 预检必须经过正式的覆盖、模板、上下文选择及结构化输出提示。原生服务私有请求构造的隔离只拥有字段组装；审校和安全补丁应用仍由原服务执行。补丁许可与 runtime 必须随描述保存，不能在执行时重新从实时状态推导另一份许可。

主模型、备用模型及原生格式纠错的配置分别核对。有效模型配置身份使用白名单摘要，不能将凭据或原始端点存入运行描述。窗口来自明确的 provider/model 元数据；未知窗口或原生协议没有可执行输出上限时拒绝发送，不能把输出额度当作输入窗口。

批次模型绑定还保存完整契约哈希、六类原生任务的有效配置摘要、fallback 和窗口。捕获过程只读解析设置，提交时复核 epoch、契约与当前 worker 租约；恢复读取原绑定，不重新接受实时配置。装配层将冻结窗口/fallback 交给 Prompt 预检，并在每次物理请求安装当前配置核对。窗口源由装配层显式提供，默认后台配置见 `app/director/productionKernel/modelPolicy/README.md`；空配置不推测任何模型窗口。

用户可调整的任务输出额度必须进入实际模型参数。只让设置页显示较大数值，却让服务内部默认 maxTokens 覆盖它，会造成“配置已保存但仍被旧值截断”。新任务将路由数值捕获进阶段 profile，并以并发隔离范围同时约束预检和实际 SDK；恢复沿用已保存 profile，设置调整不扩大旧任务权限。配置核对读取全局原值，不能被正在执行阶段的额度范围污染。

每次物理请求都以其完整当前消息、响应格式、工具及模型构造参数检查预算。JSON 纠错会增加消息，不能继续使用初次请求的预约值。SDK 调用前核对初次有效消息与预检身份，模型/端点漂移及检查失败保持锁存；底层捕获异常不能发布不符合快照的结果。

阶段额度不是物理请求额度。文本流、空稿重试、结构化修复等每一次物理请求都必须进入持久预约和围栏；底层服务捕获异常后也不能清除额度或失权失败。统一审校会安装自己的共用重试作用域，调用方必须向该作用域注入冻结策略和持久存储，不能只在外层包另一份额度后假定它会被继承。

物理账本以调用请求身份幂等预留，实际观察只替换对应请求的额度。使用量缺失保持未知并继续计入预留；只有发生在请求前的明确类型拒绝可以释放，缺少观察本身不是证明。迟到观察仍恢复记账，取消/失权后的观察只记录已经发生的事实，不恢复执行权限。原生审校重试必须串接外层物理围栏，存储异常保持锁存，防止异常被兼容降级吞掉。

## 维护边界

完成率与来源页批次确认必须按持久实现选择读取。新内核完成事实来自当前原文、所选/提交哈希、阶段回执和终态引用；不能因没有旧 GenerationJob 就丢失进度，也不能因 approved 标签单独跳过。当前章节来自真实阶段领取，暂停或结束时不显示陈旧的运行阶段；这些读取没有确认暂停、恢复或补写的权限。

新表与适配能力不等于入口已经切换。V2 长篇、短篇和手动入口各有独立接入与验收；V1 行为冻结。旧服务的保存、隐式重试或版本专属能力必须逐项检查，不能仅包装函数就宣称已经满足新内核的预算和围栏合同。

V2 长篇 productionComposition 已安装持久实现分派，默认开关关闭。原生写稿、审校、回填及 RAG 开启/空账本的临时库链路已有集成验证；这些传输替身证明接口合同，不能替代真实页面、实际模型和部署环境的验收。完整接入验收与规则追踪以计划 05 的逐项证据为准。
