# 小说 AI 用量与调用日志边界

## Background

整本小说会经历开书、规划、多批次正文、审校、修文和模型重试。只显示当前运行或正文作业计数，无法解释全书消耗；直接把任务、作业和调用台账合计相加，则可能把同一物理调用重复计算。用户需要先看到本书已记录的总消耗，再按章节与步骤追溯。

## Decision

书级日志以 `LlmInvocationUsageRecord` 的唯一 invocationId 为统计事实源，通过只读投影展示。业务任务计数仍负责原来的任务和安全预算，不能成为书级日志的第二份加数。日志查询不产生模型调用，不修改任务、正文、章节预算或历史数据。

## Current Rule

适用范围：`/novels/:id/ai-usage`、`GET /api/director-next/novels/:novelId/usage` 及平台书级查询服务。

1. 查询本小说跨运行、跨批次的全部已记录物理调用。没有导演 runId 的手动调用也可以归属本书。
2. 开书时 novelId 尚未建立的记录，只在其 workflowTaskId 或 generationJobId 明确关联本书、且记录 novelId 为 null 时纳入。记录显式归属其他书时不能被任务关联覆盖。
3. 全书 `summary` 不受筛选和明细分页影响；`filteredSummary` 覆盖完整筛选范围，不仅当前页。章节分组包含书级规划和未归属章节的调用，避免将它们强行记入某一章。
4. 基础输入、输出、总计仅汇总已返回数值。全未知返回 null，真实零保持 0。未知用量与部分返回分别保留覆盖数量，不宣称已完整计费。
5. 缓存命中与未命中属于输入；缓存创建属于未命中。命中、未命中不能在总用量外重复相加。书级只合计有效已报告缓存，并显示报告覆盖数；无效缓存不污染合法基础 Token。
6. 未记录的历史调用无法从旧累计任务字段推回逐次消耗，不自动回填、不估算。最早记录时间只是可见台账的起点，不证明更早没有消耗，也不保证台账写入失败前后所有调用均完整。
7. 数据库 groupBy 汇总，明细使用 startedAt/id 倒序游标与最多 100 条分页。游标绑定小说及章节、步骤、厂商、模型、调用状态；换书或换筛选时必须重新从第一页读取。游标不是授权凭据，小说归属查询始终独立执行。
8. 最新页可每 15 秒刷新；展开多页后停止自动轮询，显式刷新返回最新页。汇总和明细都是读取时的事实视图，持续生成中不承诺跨多次分页请求的冻结快照。
9. 页面只展示计数和调用身份，不展示完整输入正文、提示词内容、模型密钥或连接信息。失败调用是逐次调用状态，不能据此推断整本导演失败。
10. 用量页属于本书上下文，桌面布局沿用导演台的专注内容区：隐藏固定全局侧栏，顶部菜单按需打开。不能通过改写用户侧栏偏好实现隐藏，否则离开日志页会影响其他页面。书架入口仅跟随新导演小说来源，不给未挂载新导演查询的环境展示无效入口。

## Failure Modes

- 全书数字比旧任务数字小：先检查台账启用时间、写入失败诊断、厂商 usage 缺失和小说归属，不能自动把旧任务累计补加进去。
- 筛选一章后顶端总量不变：这是全书总量；当前筛选的调用数与已报告 Token 在日志列表上方展示。
- 缓存覆盖不完整：已报告部分仍可展示，必须保留覆盖数量，不能把未知调用当作缓存未命中或零。
- 开书消耗漏出本书：检查工作流是否保存本书关联，以及调用记录是否保留 workflowTaskId；不能用书名、提示词片段或时间接近猜测归属。
- 显式其他书的记录被本书任务吸入：这是数据归属错误，禁止扩大 OR 条件掩盖。
