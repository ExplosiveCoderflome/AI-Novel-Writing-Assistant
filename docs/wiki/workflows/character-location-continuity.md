# 导演 V2 角色位置连续性

## 背景与决策

世界地点目录定义舞台，角色档案提供基础位置，叙事场景描述当前视角所在；这三者不能相互替代。最新章节未出现某角色，也不表示该角色来到当前场景。

导演 V2 的动态位置归属 `services/novel/characters/locations/`。统一最终正文抽取提供结构化位置变化，独立消费者生成版本化投影。不得为每个角色新增抽取或审校调用，不按关键词推断移动，不覆盖 `Character.currentLocation` 基础档案，也不借用 V1 导演编排。

## 当前规则

1. 最终候选选定、保存正文之后，必要资产回填包含 `character_locations`；完成后才允许下一章。恢复复用成功抽取，只补未完成消费者，位置投影按小说、章节、正文 hash 幂等保存。
2. `characterLocationDeltas` 每角色只提交一条章末位置。模型判断移动类型、故事时间语境、一致性及证据；现实位置与回忆、梦境、移动计划、转述分开。合理移动与上下级地点细化不等同于瞬移。
3. 确定性投影验证本书角色 ID 与名称、当前正文版本和可定位原句。重复角色结果不采用“最后一条胜出”。当下实际行动且模型明确判定一致，才能更新确认位置。
4. 带质量债务的正文只保存候选位置与待核对信息，不自动更新确认位置。位置疑点属于局部指导，不能单独停止整书；正文版本及投影结构不一致属于完整性问题，必须报告恢复错误。
5. 章前读取按故事章序逆序分页，逐角色找最后有效记录；不按数据库写入时间确定故事位置。未出场继承最后确认位置。当前章、未来章、其他书、旧正文和未成功投影均不得输入。
6. 缺少历史投影时标注基础设定或未知，逐章积累；不得自动批量 AI 重读历史正文来补资料。基础档案是缺记录时的参考，不应伪称来自正文。
7. 写作硬事实、验收和修文共用位置与原句来源。位置是动态请求内容，不能加入书级稳定缓存。空间判断复用既有验收/局部修复机制，按照当前问题策略保留质量债务或显式人工暂停。

## 示例

第十章甲被押入牢房，第十一章只写乙到客栈。第十二章章前状态仍为甲在牢房（来源第十章）、乙在客栈（来源第十一章）。甲“梦到客栈”或“计划逃去客栈”不更新位置。正文写出可信离开过程，且最终版本的移动有证据，才更新位置。

## 版本与缓存边界

位置投影使用 `ChapterArtifactSyncCheckpoint` 的专属类型 `character_location_projection:v1` 与 `director_v2` 模式；它是统一抽取的可验证读侧投影，不能成为第二套 AI 事实抽取系统。历史抽取没有位置数组时按空变化兼容，恢复不得为补此字段重跑模型。

每条来源需匹配当前保存正文 hash。作者重写旧章后，该章旧位置投影失效；按角色继续寻找更早有效位置。此保护并不证明后续所有故事决策仍与重写后的剧情兼容，跨章改写后的计划调整仍属于相应规划/修复流程。

`artifactSync/contracts` 是公共正文版本/错误契约入口，不导入抽取或恢复编排。位置模块通过它避免循环依赖，其他模块通过位置 facade 消费。不要把动态位置缓存进 `BatchContextCache` 的稳定小说资料。

## 失败排查

- 角色瞬移：检查实际输入 `character_hard_facts` 的来源章与证据，再核对统一抽取的时间语境、一致性判断及位置投影。
- 未出场角色位置消失：检查是否错误使用“最后一章全部人物状态”覆盖逐角色继承。
- 修文后读到旧位置：核对投影 hash、来源章序和正文原句，不能复用过期投影。
- 重启后重复付费：检查成功抽取检查点及必要消费者恢复，不能为了位置新增调用。
- 位置待核对：查看候选与原句，保留最后可信位置，不把候选当成已发生移动。

## 验证边界

临时 SQLite 与针对测试验证跨章继承、身份/版本守卫、债务来源、分页、恢复和缓存布局；真实模型对移动语义的判断及实际缓存命中率需要后续生成日志验证，不能由代码测试宣称百分百可靠。
