# 章节资产 Delta 抽取可靠性

## Background

章节正文完成后，系统会从一次统一的结构化调用中提取摘要、硬事实、角色状态、资源和伏笔变化。该调用服务于后续章节上下文，不应成为正文生产的阻塞点。

## Current Rule

- 首轮抽取优先保留会影响下一章的核心变化，输入上下文按角色、状态、资源和伏笔窗口裁剪。
- 输入上下文预算由 Prompt Budget Profile 控制，输出上限由抽取调用配置控制。输出上限是完整结构的保护边界，不是要求模型写满的目标；结构化校验关注 JSON 结构和关键枚举，不因普通字段长度略超就重复整章调用。
- 同一 `contentHash` 的抽取检查点失败后只允许有限重试；达到上限后按降级结果继续章节链路，后续再由补偿同步处理。
- `adaptive` 和 `deferred` 模式遇到同一正文版本的运行中检查点时记录降级边界并继续，不得重新执行正文验收或局部修复；`strict` 模式仍须等待资产完成边界。
- 资产抽取失败属于章节级资料债务，除非正文不可用或存在数据安全风险，不得阻断全书自动导演。

## Failure Modes

- 输出 token 达到上限且 JSON 不完整：优先缩短资产列表或进入补偿抽取，不重复发送同一大请求。
- Schema 字段轻微超长：保留结构化结果，使用确定性裁剪或归一化；只有关键字段缺失、类型错误或枚举非法才判定失败。
- 同一正文版本反复失败：检查模型输出预算和 schema 复杂度，禁止通过无限重试掩盖问题。
- 服务重启遗留 `running` 检查点：自适应链路按资料债务继续，后续补偿同步接管；不能将其归类为正文生成失败或消耗章节修复预算。

## 紧凑输出与事实保护

统一抽取覆盖多个消费维度，不能把同一事件在摘要、资源用途、伏笔说明和角色心智中各复述一遍。Prompt 使用紧凑 JSON 示例，要求无排版缩进、单项说明使用短句、证据优先保留一条足够的正文摘录。没有变化时数组为空，未知可选字段省略；这些是生成指导，不新增会触发整次重试的严格长度校验，也不在收到结果后按数量截断重要变化。

压缩不能损失持有人与所有者的区别、人物伤势和误判、保护秘密、资源不可用条件、时间窗口及风险等级。`readerKnows=false` 等非默认值必须显式输出，不能靠省略字段获得错误的默认状态。角色与关系状态的短摘要、资源短摘要用于后续上下文，即使 Schema 允许省略，也应保留有效变化的衔接信息。

人物名单可能包含当前目标和状态，每次仍从最新数据构建。将其放在章号和章节目标之前，只提供内容确实相同时的前缀复用机会，不能声明为不可变书级事实。正文、上一状态、账本与角色对话影响仍逐请求更新。静态 Schema 骨架的厂商缓存边界不扩展到这些动态材料。

Prompt 变更后的首轮命中率、JSON 完整率和实际输出长度需要从后续真实调用验证。测试可证明字段合同和前缀布局，不能证明模型必然遵守紧凑输出或厂商必然命中。
