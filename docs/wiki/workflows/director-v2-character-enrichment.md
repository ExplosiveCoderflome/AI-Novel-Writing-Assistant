# 导演 V2 角色延后补全

## 背景

开书先建立可用阵容，再在正文批次结束后补齐角色资料。此前补全依赖 V1 任务的启动配置，纯 V2 运行可能漏触发；重新初始化思维也可能覆盖正文回填的新状态。

## 决策

V2 从自己的成功正文作业触发独立后台任务，复用通用角色服务和持久化副作用队列。它只补缺项，不成为下一章的必经门禁；V1 保留自己的启动规则。

## 当前规则

- 读取正文作业中的 V2 运行身份，并核对小说版本、执行代次、运行合同和最终资源边界。失败、取消、未完成资源回填的正文不能触发可选模型调用。
- 一份已应用阵容在一个执行代次只安排一次补全。重复完成事件、服务重启均复用同一个队列记录。
- 使用所属 V2 运行冻结的模型设置；只处理该阵容的角色，不沿用 V1 Seed 或当前全局模型默认值。
- 后续正文运行中先等待；开关关闭时先等待。等待释放租约并延后调度，不计为调用失败，不消费重试次数。
- 外显资料只补空白。生成期间作者补写的字段优先；角色位置、背包、关系变化和正文事实仍由最终资源回填负责。
- 思维初始化只处理没有当前快照的角色，提交时再次检查。已有章节思维不得由初始设定重置。
- 后台任务续期租约；失去租约、切换版本或替换阵容后停止旧写入。真实生成失败由队列按退避重试，最多三次，不暂停正文主流程。
- 复用现有注册 Prompt 的固定规则及书级前缀，只发送补全所需资料；不加入完整历史正文，不重复正文资源提取。实际缓存命中取决于厂商和输入，不能承诺固定命中率。
- 补全调用归入本小说和对应 V2 运行的 AI 用量日志，保留输入、输出及缓存命中记录；不重新打开已闭合的正文用量。

## 示例

第 1—3 章最终修复并回填后，补全缺失的稳定体态、穿着和说话特征。作者已写清的样貌保留；第一章回填出的思维保留。若用户已开始第 4—6 章，补全等待该批次结束，不争抢正文工作。

## 失败模式

- 没有补全任务：先检查正文作业是否成功、当前正文资源边界是否完整，以及是否存在已应用阵容。旧历史记录不会自动批量补跑。
- 队列等待：核对是否有正文作业正在排队或运行、V2 开关是否开启；不要通过反复生成正文来催促补全。
- 任务已过期：核对版本、代次、阵容和运行取消状态；不要取消归属检查让旧任务写入新流程。
- 缓存偏低：结合用量日志判断角色变化的必要输入和固定前缀，不通过删掉当前正史来换命中率。
