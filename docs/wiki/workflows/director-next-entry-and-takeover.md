# 导演入口、接管与历史边界

## 背景与决定

用户的小说内容是创作的事实来源。历史任务的启动输入可能过期或缺失，不能决定接管起点。新导演先读取业务表和已保存版本，补齐规划；正文由用户另行授权章节范围。

## 当前规则

新旧引擎不能共享书级“当前任务”判定。开关开启时，旧工作流 auto-director、旧导演 current 和 book-automation 查询返回成功的空当前态和新来源地址，在进入旧查询或投影服务前结束。否则历史运行记录会被编辑页当成当前任务，触发旧接管容器、恢复提示或生产方式选择，即使命令端已拒绝写入也仍会新旧混显。

空当前态不是任务完成或任务删除。旧记录各列保留，历史查询仍只读；只有新接口依据 DirectorNextRunControl 判定当前 Run。客户端驾驶舱读取契约允许空响应，不能构造虚假的旧运行状态代替它。关闭开关时原当前查询保留。

- 开关 `DIRECTOR_NEXT_ENABLED` 默认关闭，在应用入口装配新 HTTP 门面、生产处理器及 Worker。配置切换需要重启服务，新内核不判断历史任务来源。
- 启用时历史导演命令入口拒绝写入，提供小说来源路由；旧导演 Worker、旧正文恢复初始化及其自动恢复 watchdog 不启动。其他恢复服务保持自身职责。历史表不通过“冻结”写回状态或迁移 Seed。
- 历史投影只读旧任务的标题、状态、进度和错误，固定为历史，只提供来源导航。历史任务不会变成新 Run 的控制行。
- 创作工作室确认长篇方向时，入口适配器创建小说业务记录，使用已选模型启动新 Run；默认仅规划并采用阶段确认。用户选择正文范围前不能启动正文。
- 开书使用确认记录推导稳定内部小说 id，重复提交复用小说及命令。HTTP 小说创建 schema 不接受内部 id。创建与 Run 启动之间发生中断，可从同一小说重试，不创建第二本书。
- 接管读取故事规划、创作约定、关联世界、角色、卷版本、章节路线和已保存正文。只登记实际存在的内容；不完整但有内容的规划过期且受保护，不能被当成空白覆盖。
- 正文逐章登记保护范围，已有未收尾正文不能进入自动重写范围。正文生成作业仍负责跳过当前内容已完成的章节。
- 批次 scope 包含授权起止章节，指定卷也参与 scope。不同范围的“批次已完成”不能满足新的批次；切换模式保留原 scope 和模型、策略、范围快照。
- 新工作台的内容读取不读取历史任务 Seed，不触发兼容数据补写，角色目录不设旧书架的展示数量上限。
- 运行记录只读；启动、确认、恢复、取消与模式切换均在小说导演台进行。

## 恢复与停止

小说列表、详情和创建响应由同一 HTTP 投影补齐创作来源地址，持久化的简易/专业显示偏好不能覆盖它。手动建书保持 manual_create 资料记录，完成后依据来源打开小说导演台；开书准备记录不是新的正文授权。空正文预览的创作入口也依据同一来源导航。

编辑页的 AI 接管按钮在新来源有效时只打开导演台，不加载旧接管诊断、设置和启动命令。只有后端明确返回空来源（新导演未启用）时才加载旧界面。来源未知、读取失败或指向其他小说时，提供重新读取，不能把错误视为使用旧编排的许可。入口检查必须覆盖已存在小说的详情、空正文预览与缓存场景，不能仅验证列表卡片。

启用新导演时，冻结边界必须覆盖所有旧编排的 HTTP 写入口：导演命令、旧工作流继续/生产方式选择/标题修复、运行记录中的旧导演重试/取消/归档，以及跟进与通知回调。只封住主命令接口会留下可以再次写旧命令或解除旧暂停的旁路。原开书未关联小说的 bootstrap 可创建或更新开书准备记录，候选失败显式恢复只走 opening-retry；关联小说后不得再用 bootstrap 重置该任务。手动创作 lane 与资料编辑保持独立，不能将它们冒充自动导演恢复。

冻结接口返回 409 和可读取的来源路由，不改变旧记录，也不隐式启动新 Run。用户在小说导演台看到资产与范围后，明确提交 open_run 或新恢复命令。调用实际 app 装配的隔离数据库测试必须证明被拒绝操作没有新增旧命令，且旧任务所有列不变；仅测试独立 router 不足以证明挂载顺序正确。

正文作业的 `directorNext` 快照表示新导演拥有它，运行记录中的来源导航必须返回小说导演台，不能返回旧工作台的通用流水线恢复入口。运行记录的 retry/cancel/archive 对新导演所属作业以及关联旧自动导演任务的历史作业均拒绝；普通手动章节作业保持自身来源。通用流水线重试不能替代导演恢复：它可能创建不带新运行身份的作业，也无法核验确认门、暂停原因和授权范围。新导演通过自己的恢复事务及保存绑定继续同一业务作业。

人工暂停只能由显式恢复命令解除。明确重规划的正文作业需先保存晚于暂停时间的卷路线；恢复清除当前停止信号，并保留问题历史及已处理游标。取消只请求停止归属该 Run 的作业，不能取消其他创作或清空正文。

切换方式必须在保存边界；未收尾的正文批次不允许通过换模式绕过恢复。Worker 的失败额度在显式恢复后重新计数，累计 Token 授权不重置。

租约拥有者可以继续领取自身的运行中 Run；其他 Worker 仍需等待租约过期。不能仅查询过期租约，否则每个保存边界都会产生一次租约时长的无效等待。等待确认的 Run 不参与 Worker 领取，避免占用候选名额。

恢复验证应覆盖两个独立进程和真实临时持久化：在产物提交后退出，另一个 Worker 应先尊重有效租约，再根据台账跳过已保存产物并推进后续步骤。内存中抛出异常再继续只能证明同一进程的处理，不足以证明跨进程恢复。人工暂停不属于租约恢复候选，历史旧任务与正文不得因新 Worker 启动而变化。

## 正文的单章用量边界

新导演正文作业以 `GenerationJob.totalTokens` 为累计事实，在 payload 的 `directorNext.chapterUsage` 保存单章起始计数与已观测用量。章节首次调用前必须持久化基线；恢复同章不得重置基线，否则重复重试会绕过硬预算。计数倒退、无效计数或身份错位直接按数据完整性风险暂停，不再调用 AI 判断这一确定性安全问题。基线无法确认已保存时不得调用生成。

单章预算为 80,000 Tokens。在章节调用、运行重试及保存闭合边界检查；超限保留已保存正文与完成进度，使用锁定的 `runtime.token_budget_exceeded` 决定停止后续滚动规划和章节调用。新导演从作业的结构化决定投影为运行时人工恢复，显式恢复同一未完成章节仍受原累计用量约束；已闭合章节可在显式授权后跳过并继续下一章。既有生成、审校、修复、保存和时间线算法不被用量检查打断。

该保护不依赖旧导演熔断或旧工作流用量台账。计数只覆盖供应商报告并由统一跟踪保存的 Tokens；不保证供应商未报告的用量。整次 Run 的可选总预算与单章硬预算是不同约束。

## 滚动正文的进度与恢复

新导演正文作业的总章数来自授权区间，完成数量来自该区间内当前正文哈希对应的生产闭合事实。未创建的远期章节不能计为已完成；已保存的 completedCount 不能用于跳过缺少闭合事实的章节。恢复时先重算并保存事实进度，全范围闭合后完成进度为 1。

整书与有限章节范围都按授权终点滚动补齐路线，有限范围不能因为使用 `auto_to_execution` 就只执行启动时已有的章节。恢复可能发生在正文已闭合、后续路线尚未创建之间：必须定位最早未闭合章，补齐其路线再继续。跨过目录缺口时按章序插入下一章，不跳到更远的已有目录；已经闭合的后续章节保持跳过，不能在补写前章后重新插回生成队列。这些规则避免进度超过 100%、空范围被误记成功及已有正文被再次生成。

正文首次准备与后续滚动都复用 ChapterRouteWindowService。授权正文时，首次目录步骤只要求最低 3 章、目标 5 章的连续路线，短范围按剩余章数缩小；不等待目标卷全部章节任务。只做规划则生成完整目标卷目录。正文从第一章启动时只准备一个初始卷骨架，后续卷由滚动服务按冻结目标补齐；全书策略和目标章数仍保留。路线窗口的可用数必须从授权起始章连续计算，较远章节不能掩盖当前章缺口。适配器另外核验已保存的本书、目标卷和连续章序，不用返回计数代替产物事实。

## 通用恢复接口的冻结

开启新导演入口后，`tasks/recovery-candidates/:kind/:id/resume` 同样属于历史恢复旁路。旧导演工作流、旧导演所属正文作业和新导演正文作业都必须返回对应来源入口，不能通过通用恢复接口排队旧命令或清除人工恢复锁。未关联小说的原开书恢复使用 `opening-retry`；新导演正文恢复使用导演台显式命令。

不指定创作上下文的 `resume-all` 在入口切换后拒绝执行，防止一次批量操作混合领取历史导演和新正文作业。其他非导演任务的单项接口保持既有行为；冻结在 app 层安装，不向新领域内核引入历史判断。

全局待恢复对话框仅列出中断位置和来源导航，不提供单项或批量恢复。恢复候选的来源投影由 app 装配注入已鉴权的任务查询路由；启用新导演时，有小说的自动导演记录及其正文作业进入新导演台，未关联小说的开书记录进入原开书页。关闭开关时保留原查询投影；其他任务来源不变。来源查询只读取身份和归属，不能修补历史 Seed、启动 Run 或解除人工暂停。测试必须同时核验真实 app 返回的路由和数据库所有列不变。

## 验证与投放边界

临时 SQLite 演练创建完整业务 schema，覆盖新开书、已有小说接管、切换、历史投影及默认规划范围；检查旧任务所有列、正文、台账与同书单活跃约束。前端使用类型及投影契约检查，交互和视觉由用户验收。

真实数据首次启用前需明确授权和可验证备份。计划 09 的旧引擎删除还要求 01～08 验收、beta 稳定一个发布周期及单独批准；入口切换不等于满足删除条件。

开书交接后的原任务只代表候选与方向确认完成。任务投影以持久化的新导演来源、opening_complete 及成功状态识别该范围，显示“开书方向已确认”和单个开书步骤；不能沿用旧主流程的成功状态来把后续规划、正文和质量收尾全部标为完成。新 Run 独立报告实际授权范围进度，开书投影不得读取或推断其完成情况。

## 创作空间与运行权限

用户要求保留原开书界面，因此书架和首页长篇开书入口使用 `/novels/auto-director`。开书前候选生成、修改和确认由 app 层 `director/opening` 适配器放行，保留原控件、注册 Prompt 与候选保存格式；确认选定方向后调用新导演 `open_run`，不能调用旧小说生产确认链。创作工作室仍保留独立入口，但不能替代用户选择的开书界面。

这一例外只适用于未关联小说的开书任务，以及本适配器创建小说的幂等确认；已关联小说的旧生产任务保持冻结。不开启旧 Worker，仅执行当前明确请求接受的命令 ID。确认后必须保存新导演的明确来源路由，客户端和运行记录不得把新导演路由转换成旧编辑页。进程中断的开书命令恢复仍需单独验收，不能扩大为扫描旧生产任务。边界说明见 `server/src/app/director/opening/README.md`。

目录、正文和导演台的宽度由用户通过分隔线分配，宽度偏好仅保存在浏览器。这样阅读较长的规划、正文或导演表单时可以扩展对应区域，而不需要切换生产方式。布局调整和收起辅助区均不能改变章节授权范围、确认门或运行模式；窄屏按实际容器宽度上下排列。组件由 `components/layout/resizableWorkspace` 承载，设计约束见 `docs/design/product-ui-design-system.md`。

## 相关模块

- `app/director/`：入口装配、业务资产读取、新书交接、业务作业控制。
- `modules/director/application/assetInference.ts`：纯资产保护登记。
- `modules/director/legacy/`：只读历史投影；只能由 HTTP 层使用。
- `components/directorNext/`：导演状态、授权表单与来源操作。

这些边界影响开书、章节生产、恢复及前端投影，不改变 Prompt 注册和 AI 质量判断算法。
