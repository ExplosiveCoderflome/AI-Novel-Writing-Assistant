# 导演 V2 角色计划出场与正文出场

## 背景与决策

人物被列入章节任务不等于实际出场，正文提到名字也不等于人物到场。若把这几种信息混为一谈，就会产生错误的出场次数、人物缺席和位置推断。V2 因此保留计划与正文两条证据链，并复用章节生产已有的结构化产物，避免专门重扫全书角色带来的 Token 消耗。

## 建立时机

1. V2 拆章的同一次模型请求同时输出 `plannedCharacterIds`，覆盖该次生成的章节。该初排与章节标题、摘要一起保存；详细任务生成时将它作为可调整的安排，并以最新有效的章节 StoryPlan 参与者覆盖初排。
2. 正文完成检查、局部修复并保存后，统一资源提取同时输出角色出场，不增加专项模型调用。
3. 按运行模式处理新人物身份，再消费资源与出场记录，完成后进入下一章。半自动在人物确认边界等待；全自动可暂缓不确定身份，继续创作。
4. 全自动暂缓的人物日后被确认时，读取同一最终正文版本的持久化提取结果，在身份确认事务内补绑出场。无需重写正文或再次提取。

## 信息语义

| 信息 | 来源与含义 |
| --- | --- |
| 计划出场 | 最新有效非 stale 章节计划的参与者优先，否则采用活动卷规划中的角色 ID 初排；空名单是明确不安排，缺字段是未知 |
| 实际出场 present | 本章当前故事时刻实际行动或对话，计入首次、最近及出场章数 |
| 仅被提及 mention | 转述、传闻或未来计划，不计入实际出场 |
| 回忆 flashback / 梦境 dream | 单独展示，不改变实际出场统计，也不据此更新现实位置 |
| 未核对 untracked | 缺少当前版本的完整提取、证据无效或人物身份未解决，不能当作缺席 |

同一角色一章可以有多种类型，每种最多保留一条摘要与短证据。统计按章节计数，不按摘录数量计数。“首次有记录的出场”不保证就是历史正文中的真正首次出场。

只在正文存在且覆盖完整时提示“计划出场但未确认实际出场”。这属于可核对提醒，不暂停全自动创作，不进入重新规划错误。

## 版本、恢复与边界

- 出场写入验证小说归属、运行批次、执行世代、运行控制状态和最终正文哈希。其他小说角色或无法核对的证据不会成为有效记录。
- 正文版本与投影绑定；正文编辑后不沿用旧版本。失败恢复复用同一提取结果，消费者重复执行不会累加重复事件。
- 确认新角色前不伪造 ID；身份确认后绑定真实 ID，保留原正文证据。未知身份不能因过滤掉了候选而被标为完整覆盖。
- 历史章节不因打开角色页自动补扫。旧 V1 名字片段记录仍属于其他变化记录，不用于推断 V2 的语义化出场统计。
- 模块入口属于应用服务组合；V2 领域内核不直接依赖旧导演服务。V1 保留原有动态与时间线写入，V2 不再调用旧正文名字扫描。

## 缓存与成本

规则、结构化示例和稳定角色/资源目录放在可复用前缀。章节正文、人物状态和位置仍位于动态尾部，身份名单变化时如实更新。新增出场字段会增加少量结构化输出；它消除了额外扫描需求，但不能承诺厂商缓存每次命中或总 Token 绝对不增加。

## 前端展示与读取

角色资料页提供计划章节和完整出场时间线；阅读中的角色侧栏遵守“读到本章 / 最新状态”边界，避免默认泄露未来剧情。每条记录可以返回来源章节并展开正文依据。角色页定期刷新，手动确认候选后立即失效对应出场查询缓存。

出场示意图与文字记录复用出场接口及页面已有的章节规划，用计划/正文两条章节轴表达差异，不增加请求。每页最多展示 24 个已建或已规划章节，保留没有事件的章节，不能压缩成连续出场的假象；图内横向滚动避免撑宽工作台。正文节点可同时包含实际出场、提及、回忆与梦境，用符号及文字标签共同区分。未核对和待写正文有独立标记，不画成确认缺席。

开书规划完成但尚未创建正式 Chapter 时，出场接口返回空数组是正常的数据阶段，不能据此隐藏全部示意图。前端将 VolumePlanDocument 中的章节补为规划节点，按结构化角色 ID 显示初排；缺字段才标注“出场安排待生成”，空数组不标成待生成。标题或简介提到角色不能作为出场依据。规划节点使用 plan ID 导航到章节规划，不冒充正式 chapter ID；正式章节建立后按真实 ID 或章节序号去重。所有节点仍先应用阅读边界，再显示数量、标题和分页。

分页先应用阅读边界，再计算范围。读到本章时默认显示靠近该章的一段；最新状态默认靠近最近有记录的章节，无事件时靠近最早计划出场。切换角色或阅读范围重置区间，手动选择的区间在同范围刷新时保留。点击节点只触发已有章节导航，不写资源或调用模型。

读取接口为只读 GET，不创建或修复记录，不运行全体角色动态重建。历史正文的实际记录不能藏在阅读请求或轮询中补扫。

## 初排版本与旧书补齐

完整卷规划由活动 `VolumePlanVersion.contentJson` 承载。`plannedCharacterIds` 只属于规划文档，不写入 StoryPlan 或旧角色时间线，不通过 Chapter 创建来模拟排期。版本归一化、草稿转换、拆章块合并和断点保存必须保留此字段。拆章 V2 使用单独的 v10 契约，验证每个 ID 来自本书目录；V1 保留 v9 的三字段契约和输出预算。重新拆分某段时，新的结构化安排替换该段初排，不能沿用重排前的名单。

新书无需专项排期调用。固定拆章规则和按 ID 稳定排序的精简角色目录前置，节奏段标识、章节数量、终章要求和动态上下文置于尾部；人物状态变化不修改目录前缀。初排增加少量输出成本，厂商真实缓存仍需要通过用量日志观测。

已有规划但缺少初排的书，通过角色时间线中的显式“补齐角色出场安排”发起 POST，使用顶部选择的模型。每次最多 24 章，剩余范围由用户继续补齐。只传角色身份目录、既有卷/章节摘要及相邻已排名单，不传全文；仅生成角色 ID，不重新拆章、扩写任务或启动正文。已排期、已准备详细任务及已有正文的章节不在补齐范围。

补齐时须先结束本书创作。同进程并发重复点击在模型调用前拒绝，无缺口直接返回；生成期间若导演归属、运行控制、活动版本或原规划内容变化，则旧结果不能写入。写入只修改活动版本的缺失字段，保留标题、摘要、合同与正文，界面随后失效规划和出场查询缓存。该写操作不触发旧导演事件回填。用量带小说与当前批次归属，可在本书 AI 用量中查看。

## 全员时间线

左侧角色组中的“角色时间线”打开全员矩阵，角色为行、章节为列。计划出场细框与实际出场实心条位于同格的上下两层；提及、回忆、梦境继续独立标记。条带仅填充有实际出场的章节，不能连接首末出场间的空章。角色列固定，章节在图内横滚，沿用 24 章分页；点击姓名进入资料，点击格子按真实/规划 ID 导航。

全员接口 `GET /api/director-next/novels/:novelId/character-appearances` 在一次读取中按小说批量加载角色、章节、有效计划及出场检查点，章节元信息只传一次。每章只校验一次正文哈希、解析一次检查点；不逐角色重新读全文。单人接口与全员接口共用 `readChapters`，保持正文版本、覆盖状态和最新有效计划规则一致。接口只返回该小说已保存角色的事件与计划参与者 ID，不引入新的语义判断。

全员视图的出场查询沿用 `director-character-appearances` 缓存前缀，挂载期间每 10 秒刷新，人物确认后的前缀失效同样生效。尚无正文时沿用规划占位；读取失败有独立错误和重试入口，不能显示成全员缺席。此全书概览不替代阅读侧栏的防剧透边界。
