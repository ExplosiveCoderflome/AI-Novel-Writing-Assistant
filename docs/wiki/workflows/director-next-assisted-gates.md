# 导演半自动确认与恢复边界

## 背景与决定

新手需要按阶段确认创作结果，不能被迫逐章审核；自动与半自动共享资产事实，但使用独立编排器。门由声明计划的 `gateable` 决定，正文仅在批次收尾确认。非门控步骤的保存结果自动登记为已确认，避免半自动等待一个不存在的确认入口。

## 当前规则

- 门控编排器只读事实，先处理显式停止，再打开待确认门，再选择依赖已确认的步骤。质量债不会阻止继续。
- 授权范围限制本次可执行步骤，不能把范围外的上游草稿视为已确认。半自动下游仍要求其依赖已确认；范围外的门不会在本次自动打开，因此缺少确认时暂停并等待用户处理，不能为完成局部范围而跳过确认。
- 确认、编辑后确认、重新生成与控制版本、幂等命令在同一数据库事务提交。读取已保存编辑内容也属于该事务，客户端不能指定内容哈希来伪造保存。
- 编辑后确认新增 `user_edited` 版本并保护内容。失效范围直接使用声明计划的 `downstreamArtifactTypes`，限定同书同 scope；正文 `chapter_draft` 永远排除。
- 下游用户编辑资产可以过期，但保护标记不能清除。过期且受保护意味着需要用户在对应资产页核对调整，守卫仍禁止自动覆盖。
- 重新生成不能覆盖受保护内容；版本冲突返回 409，资产读取失败会同时回滚门控状态和命令。
- 门控审阅必须留在 `/lab/director/:novelId?review=<产物类型>`。角色、卷纲、章节任务与场景、同步后的执行计划、批次正文均由新工作台呈现，不能跳到旧小说编辑页或借用旧导演确认状态。复用保存业务表和底层服务不等于允许复用旧导演界面。应用装配注册地址，投影按已保存合同解析编码后的书 ID；前端消费 `availableActions.target`，不自行根据原始 Run 拼装状态或确认地址。
- 确认地址只携带 `review=<产物类型>`；本次授权的 `from/to`、已保存卷/章身份和 Run/控制版本放在工作台接口的 `reviewContexts`，不能把它们编码成 URL 工作流状态。上下文仅由本书当前待确认门和不可变合同解析，不能依赖上次阅读章或前端存储；刷新页面仍能定位。章节任务使用 `VolumeChapterPlan.id` 与所属 `volumeId`；执行计划和正文使用 `Chapter.id`，不可混用。缺失、重复或与指定卷冲突时明确拒绝，不能选择第一条记录。确认上下文异常单独说明原因，不隐藏已有正文；正文审阅仍限制本次授权范围。
- “去确认”只负责打开本阶段结果。`DirectorPanel` 核对当前投影的审阅目标与地址相同、上下文 Run/控制版本一致且完整保存资产可读后，才提供确认命令。短地址不能用来绕过版本检查；缓存的上一次门或另一个 Run 的结果不得用于确认。默认故事页、其他阶段、读取失败或身份无效不能显示确认操作。资源工作台只读保存资产，不消费 `DashboardView` 的导演状态。旧地址的额外身份和范围参数会被移除，内容仍按后台保存上下文定位；包括非法数字在内的额外参数不能决定授权范围。
- 切换创作方式只能发生在保存边界，保留启动、模型、策略和章节范围快照；正文批次仍在执行或等待恢复时拒绝切换。暂停事项作为事实保留，新编排器不能通过换模式绕过暂停。

切换入口必须来自后端 `availableActions` 中的 `handoff`，包含目标方式和操作文案。没有在执行的步骤且没有未处理停止信号时，排队、阶段保存后的运行态和待确认态可以提供该动作；人工暂停和终态不提供切换。不能只在待确认态显示按钮：全自动运行不会打开确认门，这会使双向切换退化为单向。前端只消费投影，实际命令仍在事务内检查控制版本、保存边界及正文作业收尾状态；页面显示后如新步骤已开始，拒绝该请求而不修改合同或台账。步骤执行中的拒绝和切回原方式都要用真实仓储验证，保留同书单活跃约束。

正文批次的“编辑后确认”也必须满足生产闭合边界：授权范围内所有章节的当前内容哈希具有成功的资产同步记录，并通过统一的章节完成策略。仅有非空正文、完成状态标签或旧版本同步记录均不够。确认读端口在门控事务中核验这些事实，只对已保存正文计算产物哈希，不生成、修复或隐式提交时间线。这样编辑后的确认与正文批次正常完成使用同一判断，不会绕过 final_content → timeline_finalization 的顺序。

## 显式恢复

确认门是持久化保存边界。进程在门打开后或等待期间退出，重新读取控制态仍为 `waiting_gate`，Worker 不领取该 Run，投影和事实读取不能增加版本或事件。编辑后确认事务提交后退出，重启按新的 `user_edited` 版本及下游 `stale` 事实重新计算；已保存的用户编辑和正文不能因进程重建而重复生成。原执行租约仍有效时其他 Worker 必须等待，不能用恢复门控为理由抢占租约。确认命令的重放仅返回原结果，不重复失效或新增编辑版本。

运行中断与质量暂停有不同来源。完成优先只放行局部质量问题；数据库、生成作业等运行问题仍可要求人工恢复。`StopSignal.source` 保存这一差别，旧的无来源质量信号仍遵循质量优先规则。

只有用户恢复命令可以在同一事务中解除正文作业的人工等待、记录已处理问题游标并追加 `stop_signal_cleared`。问题历史保留，轮询和 Worker 重启不能解除等待。取消后旧执行者的错误不能再次把 Run 改为失败或暂停。

正文作业尚未绑定时，显式恢复会核对授权起始章的规划任务和场景。若台账宣称该资产完成但保存字段缺失，只将本 scope 的任务单及声明依赖闭包标记失效，使编排器重新准备并再次提供确认。正文、其他范围以及受保护修改不能被覆盖；受保护的当前产物缺失时拒绝恢复并回滚事务。读取与 Worker 轮询不能执行此协调。规划与执行存在独立保存边界：新导演生成、保存、读取与同步规划时不能把尚未准备的 Chapter 空字段反向灌入 VolumeChapterPlan；明确同步后执行侧才拥有该合同。旧入口的默认兼容读取行为保持独立。

## 章节进度与后续授权

阶段台账完成比例表示规划与编排步骤，不是已写章节比例。正文范围进入投影后，主进度使用本次授权范围内通过统一章节完成策略的数量：当前内容必须具有对应的成功资产同步边界，仅有正文、完成标签或旧正文的同步记录不能计为完成。阶段比例保留在运行诊断中，避免新手将十步编排误解为十章正文。

`app/director/projections/productionProgress.ts` 通过本 Run 的 `chapter_batch_job` 事件读取固定作业，核验书、Run 和范围归属，再用 `currentItemKey` 对应实际 Chapter 身份。处理阶段来自结构化 `currentStage`，不能解析展示标签或猜测下一章。人工等待、暂停、确认和终态不能沿用旧的运行阶段。缺少当前章时只说明批次准备或收尾，不虚构章号；归属不一致明确拒绝读取。该端口只读，不确认阶段、不恢复作业、不修改正文。

纯投影提供 `chapterProgress`、`nextActionGuidance` 和 `nextLaunchRange`。只有 `DirectorPanel` 与 `DirectorBadge` 消费这些导演展示字段，小说页只转交投影及授权表单渲染函数。章节完成、门确认、人工恢复和失败分别说明用户下一步，不能用通用“继续推进”掩盖等待操作。

终态的后续范围建议来自冻结的全书目标与已保存正文，选首个无正文位置、最多三章，并在遇到已有正文时停止。它是用户授权表单的默认值，不是自动延长合同或 AI 意图路由。初次无 Run 的接管入口仍默认仅规划；本次范围完成后的表单默认显示建议正文范围，用户点击“提交并生成”才创建新授权。新 Run 仍冻结模型、范围、确认方式和问题策略；旧 Run 的授权终点保持不变。全书目标范围均有正文时引导阅读检查，不能把“有保存正文”宣称为全书通过质量验收。

## 相关模块

- `modules/director/domain/gateOrchestrator.ts`：纯编排。
- `modules/director/application/gateService.ts`：版本及失效策略。
- `modules/director/infrastructure/commands/`：原子确认与恢复。
- `app/director/savedContent.ts`：业务资产读取和正文恢复装配。
- `app/director/projections/confirmationRoutes.ts`：确认入口的业务资产身份解析，不生成、不同步、不修改选择范围。
- `app/director/projections/productionProgress.ts`：正文进度与后续范围的只读业务事实装配。
- `pages/directorNext/workspace/review.ts` 与 `ReviewDetail.tsx`：保存资产的身份校验和审阅呈现；不是导演状态推断或旧编辑器封装。

本规则影响规划产物、章节批次、任务状态和前端恢复投影，不改变章节生成 Prompt 或质量判断算法。
