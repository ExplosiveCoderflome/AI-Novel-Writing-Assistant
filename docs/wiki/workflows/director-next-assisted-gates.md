# 导演半自动确认与恢复边界

## 背景与决定

新手需要按阶段确认创作结果，不能被迫逐章审核；自动与半自动共享资产事实，但使用独立编排器。门由声明计划的 `gateable` 决定，正文仅在批次收尾确认。非门控步骤的保存结果自动登记为已确认，避免半自动等待一个不存在的确认入口。

## 当前规则

- 门控编排器只读事实，先处理显式停止，再打开待确认门，再选择依赖已确认的步骤。质量债不会阻止继续。
- 授权范围限制本次可执行步骤，不能把范围外的上游草稿视为已确认。半自动下游仍要求其依赖已确认；范围外的门不会在本次自动打开，因此缺少确认时暂停并等待用户处理，不能为完成局部范围而跳过确认。
- 确认、编辑后确认、重新生成与控制版本、幂等命令在同一数据库事务提交。读取已保存编辑内容也属于该事务，客户端不能指定内容哈希来伪造保存。
- 角色阵容与卷纲的“保存修改并继续”提交字段、编辑时的原值和新值。服务端检查当前书、待确认阶段、运行版本及字段原值，在同一事务中保存业务资料并登记修订。任一字段冲突会回滚整批修改，导演停在原确认阶段。直接接受已有内容使用普通确认，避免把生成稿误标为作者手改。
- 卷纲局部修订仅更新选中字段、对应卷的关系表记录及派生视图。保留版本中的章节、扩展字段和作者独立维护的大纲。角色阵容修订在确认门处理，写作中途调整角色沿用从下一未完成章节生效的入口。
- 编辑后确认新增 `user_edited` 版本并保护内容。失效范围直接使用声明计划的 `downstreamArtifactTypes`，限定同书同 scope；正文 `chapter_draft` 永远排除。
- 下游用户编辑资产可以过期，但保护标记不能清除。过期且受保护意味着需要用户在对应资产页核对调整，守卫仍禁止自动覆盖。
- 若待执行步骤自身的产物过期且受保护，并且该步骤声明为可审阅、在授权范围内且前置依赖满足，自动和半自动都打开保存结果确认门。自动模式在这里要求确认是内容保护边界，不会切换合同中的创作方式。确认事务重新读取业务表，新增受保护的 `user_edited` 版本并保留旧账本；读取失败则整体回滚。不能仅将旧哈希改为已确认，也不能自动重新生成。
- 非门控产物或覆盖其他受保护产物的冲突仍安全暂停，不能为消除拒绝而清除保护。原始守卫原因保留在事件中，来源页说明具体阶段与下一步；已有“拒绝次数耗尽”记录在显式恢复后仍按保存事实重新编排。
- 有效正文范围的节奏准备与拆章可以声明 `preservesInChapterRange`：这是一条只追加缺失路线的写入合同，不是覆盖授权。生产适配器通过事务内最新规划合并，保留已有任务、节奏、章序及正文，只创建缺少的路线和空章节；旧保护标记保留。用户显式恢复旧暂停后可以继续安全补缺，不必对一个不可审阅的拆章步骤反复确认。无章节范围的整卷重生成、其他未声明保留的资产仍由保护守卫拒绝；质量优先、运行安全与数据完整性暂停不受此合同影响。
- 路线补缺需要同时保留完整规划版本与关系表事实：关系表真实列接收最新任务与场景编辑，版本专有的卷钩子、节奏归属、章节独占事件、出入状态及写法约定保留版本值。关系表映射中的这些 `null` 只是占位；不能将其作为清空指令，否则恢复虽然通过，前文的生产约束仍会丢失。
- 重新生成不能覆盖受保护内容；版本冲突返回 409，资产读取失败会同时回滚门控状态和命令。
- 门控审阅必须留在 `/lab/director/:novelId?review=<产物类型>`。角色、卷纲、章节任务与场景、同步后的执行计划、批次正文均由新工作台呈现，不能跳到旧小说编辑页或借用旧导演确认状态。复用保存业务表和底层服务不等于允许复用旧导演界面。应用装配注册地址，投影按已保存合同解析编码后的书 ID；前端消费 `availableActions.target`，不自行根据原始 Run 拼装状态或确认地址。
- 确认地址只携带 `review=<产物类型>`；本次授权的 `from/to`、已保存卷/章身份和 Run/控制版本放在工作台接口的 `reviewContexts`，不能把它们编码成 URL 工作流状态。上下文仅由本书当前待确认门和不可变合同解析，不能依赖上次阅读章或前端存储；刷新页面仍能定位。章节任务使用 `VolumeChapterPlan.id` 与所属 `volumeId`；执行计划和正文使用 `Chapter.id`，不可混用。缺失、重复或与指定卷冲突时明确拒绝，不能选择第一条记录。确认上下文异常单独说明原因，不隐藏已有正文；正文审阅仍限制本次授权范围。
- “去确认”只负责打开本阶段结果。`DirectorPanel` 核对当前投影的审阅目标与地址相同、上下文 Run/控制版本一致且完整保存资产可读后，才提供确认命令。短地址不能用来绕过版本检查；缓存的上一次门或另一个 Run 的结果不得用于确认。默认故事页、其他阶段、读取失败或身份无效不能显示确认操作。资源工作台只读保存资产，不消费 `DashboardView` 的导演状态。旧地址的额外身份和范围参数会被移除，内容仍按后台保存上下文定位；包括非法数字在内的额外参数不能决定授权范围。
- 当前门确认结束后，`reviewContexts` 不再包含该阶段，但浏览器可以仍停留在审阅地址。无待确认上下文表示正常的不可确认状态，应以中性提示引导用户查看已保存内容和导演台下一步，不等同于生成失败，也不能据此恢复确认权限。上下文读取异常、重复或归属错误，以及开放门的保存资产缺失仍显示错误；两者必须由结构化字段区分，不能通过错误文案匹配决定样式。
- 确认章的任务、场景、目标字数与需避免事项以当前卷的 `VolumeChapterPlan` 为准。工作台审阅与导演同步执行计划按同一规则读取，保留卷纲版本中的写法、节奏归属和其他章的资料。普通确认在提交事务里再次检查任务与场景。确有缺项时，只能在当前门的有效控制版本上显式重生成，命令仍保护作者内容。
- 当前卷章节计划按书与授权章序唯一定位，不用 `active` 单一状态代替当前性判断。正常规划卷的 `active`、大纲开书的 `chapter_list_partial` / `chapter_list_generated` 及其受支持的 partial 基态可读写；归档卷等其他状态排除。缺失、重复或选卷冲突仍是事实完整性错误，确认事务回滚；不能为了可读性把归档卷重新激活或猜选第一条计划。
- 切换创作方式只能发生在保存边界，保留启动、模型、策略和章节范围快照；正文批次仍在执行或等待恢复时拒绝切换。暂停事项作为事实保留，新编排器不能通过换模式绕过暂停。

切换入口必须来自后端 `availableActions` 中的 `handoff`，包含目标方式和操作文案。没有在执行的步骤且没有未处理停止信号时，排队、阶段保存后的运行态和待确认态可以提供该动作；人工暂停和终态不提供切换。不能只在待确认态显示按钮：全自动运行不会打开确认门，这会使双向切换退化为单向。前端只消费投影，实际命令仍在事务内检查控制版本、保存边界及正文作业收尾状态；页面显示后如新步骤已开始，拒绝该请求而不修改合同或台账。步骤执行中的拒绝和切回原方式都要用真实仓储验证，保留同书单活跃约束。

正文批次的“编辑后确认”也必须满足生产闭合边界：授权范围内所有章节的当前内容哈希具有成功的资产同步记录，并通过统一的章节完成策略。仅有非空正文、完成状态标签或旧版本同步记录均不够。确认读端口在门控事务中核验这些事实，只对已保存正文计算产物哈希，不生成、修复或隐式提交时间线。这样编辑后的确认与正文批次正常完成使用同一判断，不会绕过 final_content → timeline_finalization 的顺序。

## 人工修订与重生成

### 确认结果的交接依据

阶段规划和后续正文可以分属不同运行。正文启动表单优先读取本书当前导演归属下、最近一次全书创作运行的故事输入，保留题材选择时确认的方向及作者后续手改。穿插手动单章作业时仍沿用全书方向。缺少运行快照的旧书依次使用宏观规划保存的故事输入和小说简介。

接手续写范围时，整批任务的复用以连续章序和每章完整的任务、场景为依据。执行合同还须逐章与这些要求相符。单章的就绪状态不能代表后续章节。写手、审校和修文共用的章节任务上下文包含按顺序保存的场景卡，覆盖入场、出场、目标、阻力、转折、情绪、读者收获、字数及场景边界。排查“保存了但没写进去”时，须比对写手模型实际收到的上下文。

按阶段确认的执行合同是整批写手的输入。正式开写每章前，生产作业按章序核对完整批次的章 ID、任务、场景、字数、冲突、揭示和避写项，与导演确认时的摘要一致才复用。旧批次执行器和生产内核都须遵守这个边界。时间线和章节规划仍可读取前章成稿，但写前 JIT 不得因连续性审阅再次生成已确认的任务或场景。章节规划和局部重规划可以更新 StoryPlan，但不能用派生的任务、场景回写本批确认字段。恢复旧作业时，只有整批卷规划与确认摘要匹配，且执行副本的差异能从当时保存的 StoryPlan 精确还原，才能在事务中重建副本。遇到其他差异须返回导演台核对版本。

正文确认请求和章节任务修订共用 `shared/types/director/revision` 中的提交契约。HTTP 层校验请求，应用命令从确认端口取同一组可提交字段。分卷步骤只读取已确认的人物字段，开书合同只记录已选的问题策略；这两处共享依赖各限一个纯类型导入。

旧计划的派生文本由 Planner 按写入时的规则比对。章节生产准备入口把比对函数传给导演仓储，供旧批次执行器和原生生产内核共用。确认版本、整批摘要和条件写入仍由导演仓储在同一恢复事务内核验，避免跨模块取得持久化服务或各自维护一套文本投影。

完稿交付把书名和章节分隔线作为外层排版，逐章原样写入确认的正文。导出校验应比较完整文件，覆盖缩进、空段及原稿换行符。只匹配修改过的一句，无法发现其他段落的格式丢失。

### 角色阵容讨论与分卷交接

作者在角色阵容确认页选择一位角色。讨论范围由小说、运行、等待确认的控制版本及角色 ID 共同确定。助手按本次运行冻结的模型读取选定的开书方向、阵容和这位角色的关系，并把当前编辑稿作为讨论对象。每轮提案与回复一起保存，重新打开同一确认阶段仍能追问。角色只允许修改性格、故事作用和行动目标。解释类回复可以没有修改项。

角色抽屉的「与 AI 编辑角色资料」在原抽屉内向左展开。保存后回到角色档案，已有草稿时离开须先确认。讨论范围只绑定本书和角色 ID，阵容确认前后均可浏览历史。助手只能产生字段级建议，手改和采纳都先进入编辑稿。独立保存核对原值，使用和后续章节调整相同的导演执行边界。保存只更新档案及相关索引，作者仍在阵容页确认后继续。姓名可在建立卷章规划和写正文前修改，需校验本书重名。已有大纲绑定、卷章规划或正文时保留姓名，以维持已有文本与身份的对应。状态、行动目标和成长弧继续走按章节生效的调整入口。

开书兼容层会在实际规划开始前保存初始化占位卷及其派生大纲。姓名保护复用占位卷判定，并核对卷资料和大纲仍是系统生成的初始内容。作者编辑过的大纲或卷纲继续保护。编辑稿改名后，在保存区展示原名、新名和使用新名的范围，提醒作者核对已保存资料中的旧名。

勾选建议会将所选字段填入编辑稿，作者可以继续手改或切换到其他角色，最后一次确认整套阵容。采纳时逐字段比较提案原文与当前编辑稿，防止旧建议覆盖刚写下的内容。确认时复用现有编辑事务，校验角色归属、控制版本和业务原值，写入角色、保护修订并继续导演。只讨论后接受原稿走普通确认。关闭时放弃的是本次未保存的编辑，已发送的讨论仍可重新打开。

本轮分卷策略、评议和骨架生成读取该运行角色确认命令中实际修改的字段，再从角色资料读取其现值。把这些字段附在分卷的必需书级上下文中，常规人物摘要的人数上限不会排除作者刚修改的配角。排查采纳未生效时，依次核对编辑稿里的选项、确认命令中的角色及字段，以及分卷输入的已确认设定。

### 卷纲讨论与拆章交接

卷纲确认审阅整套分卷。作者可以切换分卷，逐项选择本卷故事、读者期待、高潮和下卷引线的建议，也可以只提问。每卷使用独立的讨论记录。会话身份包含小说、运行、确认门控制版本、活动卷纲版本和卷 ID，同名卷也能区分。已有提案只可在所属会话追问。模型读取所选卷当前编辑稿、上卷结尾以及下卷的故事和读者期待，以便解释改法如何承前启后。

角色和卷纲共用讨论的版本校验、提案存储和逐字段采纳规则。采纳只更新本地编辑稿。服务端在开始讨论和发布回复前都校验保存的原值，提案记录每项建议对应的编辑稿原文。表单在切卷时保留各卷修改，过期建议不能覆盖手改。卷纲编辑器确认时提交打开时的活动规划版本，包括讨论后直接确认原稿的情况。版本变动或任一提交项的原值冲突会回滚确认，保留待确认状态。

保存时同步活动版本中的卷字段及存在的分卷关系行，兼容只保存活动版本的旧书。确认后，导演仍按运行授权选择目标卷，生成节奏板和章节路线时从保存的卷纲读取故事、读者期待、高潮与下卷引线。讨论中选了哪一卷、提案中还有哪些未采纳项，都不会重新指定拆章目标。

### 逐章讨论与正文交接

“章节任务与场景”覆盖运行合同授权的连续章序，每章须有唯一的规划行。会话以小说、运行、控制版本、活动规划版本和 `VolumeChapterPlan.id` 定位。模型读取所选章的编辑稿和场景约束，返回章节字段或带场景标识的字段建议。每项建议保留提出时的原值，切章后可以继续追问，采纳后仍可手改。场景标题或位置可以变化，采纳地址由场景标识和字段名确定。

作者可以直接确认原稿，也可以一起提交多章修改。门控命令校验当前授权、活动版本和各章原值，并在同一事务中更新规划行、版本文档和门控状态。任一章冲突则整批回滚。旧版单章命令仍定位授权起始章。

有正文授权时，“确认本批章节并继续写正文”同时批准这批写作要求。命令结果保存整批确认稿的指纹，包含规划版本、章身份以及会同步到正文的任务、场景和执行参数。执行同步按真实章节逐一核对，整批相符才承接此次批准。同步前若计划发生变化，工作台会展示执行计划供复核。重新生成会使先前的批准失效。仅获规划授权的运行以规划为终点。

### 本批正文讨论与下一批授权

修订稿在角色回填前已保存。如果新正文触发人物确认，导演仍停在本批正文确认门，作者可以在原弹窗处理候选，再次提交同一批修订和授权。处理人物本身不触发续写，弹窗保留段落选择与命令重试依据。执行中暂停的角色确认则从导演台恢复，两个入口按当前任务给出下一步。

正文讨论使用当前待确认批次中的 `Chapter.id`。会话同时绑定作品、运行、控制版本和所选章原始正文的 SHA-256。每个非空段落以章内序号定位，即使相邻两段文字相同也可以分别采纳。模型读取该章编辑稿、章节任务和会话历史，提供段落替换及理由。采纳和撤回只改本次编辑稿，切换章节保留各自的选择，未修改段落的缩进、空行和换行符沿用原文。

确认请求包含按章序排列的全批身份、读到的正文指纹和有修改的章节正文。服务端在短事务中核对待确认阶段、运行归属和整批版本，保存修改及同步任务，再按章序同步章节资料。若同步失败，保存的正文可继续核对，导演停在本批确认；重试同一稿件复用已保存结果。最终确认事务再次核对全部正文和完成凭据，防止同步期间的其他编辑被悄悄确认。正文指纹依据原始字串，资料同步沿用其既有内容哈希规则。

“只确认本批”结束当前授权。“确认并继续写”明确展示下一批章号，将这段范围随命令提交，服务端在最终事务中复核仍可写入。当前批次确认和下一批运行入队共用一份幂等回执，下一批继承本书创作设置，按自己的授权范围准备规划和写作。整书目标内均有正文时只提供收尾确认。

### 全书完稿检查与交付

检查意见按当前章节的原文引句定位。若模型标错段号，只有引句在全章唯一匹配时才可纠正段号。原段无法匹配且引句缺失或匹配多段时，保留未检查状态供重试，避免把作者带到错误的修改位置。

正文批次只确认该次授权范围。全书交付入口由完整章序、已保存正文、章节收尾状态和当前导演活动共同决定。普通 V2 长篇写完后，来源页和章节书架都指向本书的完稿检查；原稿修订项目按自己的活动目录交付。

作者启动检查后，按章读取完整当前稿、全书开篇与结尾、分布在全书的摘要、邻章首尾和仍待核对的历史审校线索。每个问题必须给出本章段号和可以在该段定位的原句。空问题列表是一份完成的结果；未检查、请求失败和原句不匹配都保留待检查状态。每章结果绑定实际检查输入及提示词版本，重新打开时复用相同版本的结果。正文或参考材料变化会使受影响章节重新进入检查。检查和讨论均由作者发起，不占用导演运行，也不改变生产审校结论。

讨论以作品、章节、检查版本和问题定位。作者可以保留原稿或逐项采纳段落替换。全书检查齐备后才接受最终确认；在同一事务里核验整书版本、保存所有选定章节及其同步任务，并记录交付稿指纹。确认一章中的修改不会将相关历史审校问题标记为已解决。导出核对书名、简介、导演归属代次、目标、章序、标题和原文，使用同一次读取的内容生成文件。任一交付内容变化都需重新确认；相同确认请求可重试，也可以重新下载已确认版本。TXT 只使用已保存正文，章节资料回填沿用手工保存队列。

### 阶段重生成

章节任务和卷战略的“重新生成本阶段”提供选填的人工修正建议。命令事务保存 `gate_regeneration_requested`，重启或显式恢复仍能读取该请求；处理器只在同 scope、同产物阶段消费建议，阶段成功后失效。章节任务的主动重生成绕过完整合同复用，未填写建议也重新生成；自动恢复仍可复用已保存的合同。保存的场景字段以 JSON 字符串读取，复用前必须解析为场景对象。

执行计划阶段提供“重新同步执行计划”。已有角色阵容和已闭合正文没有重生成入口：当前适配器只盘点或观察这些内容，不能把失效台账当作重新写作能力，也不能覆盖受保护的作者内容。

显式重生成开启新的尝试序列，但不提高冻结的自动重试上限。每个阶段独立使用该上限：前面阶段恢复成功并保存后，其历史失败不会让后续阶段首次失败就过早暂停。异常捕获与进程中断共用持久化计数，重启不会重置当前未完成阶段的额度。自动尝试结束的暂停说明展示最近执行失败的具体原因，并保留显式恢复入口；刷新、轮询与后台恢复不能自动解除暂停。

## 显式恢复

卷规划的存在不能代替卷战略的完整性。接管旧小说时，只有卷与有效战略同时存在才能复用战略产物；已有卷但缺战略时，只补齐战略资料，不重跑骨架或章节。业务层在事务外生成建议，保存时核对活动版本及规划快照，只更新战略与就绪状态，保留旧版扩展字段、作者标注、归档卷和正文。并发的完整战略优先复用，陈旧生成结果拒绝保存。

历史任务可能已经把不完整卷规划记成受保护的完成产物。节奏板准备必须再次核验实际保存的战略，用户显式恢复后可走同一补缺入口继续；不通过清除保护标记或改写失败历史绕过守卫。读取、轮询和 Worker 重启仍不能解除人工暂停，作者明确重生成与安全补缺保持不同授权边界。

确认门是持久化保存边界。进程在门打开后或等待期间退出，重新读取控制态仍为 `waiting_gate`，Worker 不领取该 Run，投影和事实读取不能增加版本或事件。编辑后确认事务提交后退出，重启按新的 `user_edited` 版本及下游 `stale` 事实重新计算；已保存的用户编辑和正文不能因进程重建而重复生成。原执行租约仍有效时其他 Worker 必须等待，不能用恢复门控为理由抢占租约。确认命令的重放仅返回原结果，不重复失效或新增编辑版本。

运行中断与质量暂停有不同来源。完成优先只放行局部质量问题；数据库、生成作业等运行问题仍可要求人工恢复。`StopSignal.source` 保存这一差别，旧的无来源质量信号仍遵循质量优先规则。

只有用户恢复命令可以在同一事务中解除正文作业的人工等待、记录已处理问题游标并追加 `stop_signal_cleared`。问题历史保留，轮询和 Worker 重启不能解除等待。取消后旧执行者的错误不能再次把 Run 改为失败或暂停。

正文作业尚未绑定时，显式恢复会核对授权起始章的规划任务和场景。若台账宣称该资产完成但保存字段缺失，只将本 scope 的任务单及声明依赖闭包标记失效，使编排器重新准备并再次提供确认。正文、其他范围以及受保护修改不能被覆盖；受保护的当前产物缺失时拒绝恢复并回滚事务。读取与 Worker 轮询不能执行此协调。规划与执行存在独立保存边界：新导演生成、保存、读取与同步规划时不能把尚未准备的 Chapter 空字段反向灌入 VolumeChapterPlan；明确同步后执行侧才拥有该合同。旧入口的默认兼容读取行为保持独立。

## 章节进度与后续授权

阶段台账完成比例表示规划与编排步骤，不是已写章节比例。正文范围进入投影后，主进度使用本次授权范围内通过统一章节完成策略的数量：当前内容必须具有对应的成功资产同步边界，仅有正文、完成标签或旧正文的同步记录不能计为完成。阶段比例保留在运行诊断中，避免新手将十步编排误解为十章正文。

`app/director/projections/productionProgress.ts` 通过本 Run 的 `chapter_batch_job` 事件读取固定作业，核验书、Run 和范围归属，再用 `currentItemKey` 对应实际 Chapter 身份。处理阶段来自结构化 `currentStage`，不能解析展示标签或猜测下一章。人工等待、暂停、确认和终态不能沿用旧的运行阶段。缺少当前章时只说明批次准备或收尾，不虚构章号；归属不一致明确拒绝读取。该端口只读，不确认阶段、不恢复作业、不修改正文。

纯投影提供 `chapterProgress`、`nextActionGuidance` 和 `nextLaunchRange`。只有 `DirectorPanel` 与 `DirectorBadge` 消费这些导演展示字段，小说页只转交投影及授权表单渲染函数。章节完成、门确认、人工恢复和失败分别说明用户下一步，不能用通用“继续推进”掩盖等待操作。

本批正文确认页与终态授权表单共用后续范围建议。系统根据冻结的全书目标和已保存正文，从首个空缺起建议最多三章，遇到已有正文即停止。绑定原稿大纲的运行一次建议一章。用户可在本批确认时一并授权，或在终态表单选定范围后点击“提交并生成”。初次无 Run 的接管入口默认仅规划。每份新合同独立冻结模型、范围、确认方式和问题策略。全书目标范围内均有正文时，引导作者阅读检查。

## 相关模块

- `modules/director/domain/gateOrchestrator.ts`：纯编排。
- `modules/director/application/gateService.ts`：版本及失效策略。
- `modules/director/infrastructure/commands/`：原子确认与恢复。
- `app/director/savedContent.ts`：业务资产读取和正文恢复装配。
- `app/director/projections/confirmationRoutes.ts`：确认入口的业务资产身份解析，不生成、不同步、不修改选择范围。
- `app/director/projections/productionProgress.ts`：正文进度与后续范围的只读业务事实装配。
- `pages/directorNext/workspace/review.ts` 与 `ReviewDetail.tsx`：保存资产的身份校验和审阅呈现；不是导演状态推断或旧编辑器封装。

本规则影响规划产物、章节批次、任务状态和前端恢复投影，不改变章节生成 Prompt 或质量判断算法。
