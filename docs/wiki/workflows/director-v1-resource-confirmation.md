# 导演 V1 的自动资源确认边界

## 背景

角色资源账本影响后续正文可使用的物品、能力、线索和约束。“解开麻绳”等变化可能被抽取为资源失去；单纯按失去、消耗、销毁或底牌事件要求人工确认，会使全自动创作长期积累待确认资源，后续正文仍引用旧事实。

正文资产抽取的风险判断与最终确认是两个边界。低风险表示抽取模型对变化的风险评估，不能代替正文版本、执行归属和当前账本的一致性检查。

## 决策

V1 全书自动模式在每个正文作业成功、资产同步完成后，调用 AI 核验本作业章节范围内的待确认资源。这个步骤先于质量提醒分支和下一章推进，包含最后一章。半自动、手动正文生产和 V2 不进入这一 V1 自动确认流程。

AI 核验使用已保存正文、资源提议中的证据、相关角色、对应资源账本及书级约束，明确选择可确认的提议 ID。不得把空 ID、未知 ID 或低置信度结果解释为整批批准。

## 当前规则

1. 权限来自持久化的 V1 任务、全书自动运行模式、成功正文作业的任务归属，以及小说当前导演版本与执行代次。页面参数或小说最近的一项任务不能替代这些条件。
2. 只核验当前作业范围内、来自章节后台同步、处于待确认状态的角色资源提议。人工提议、未绑定章节的提议和其他章节的提议不随此步骤确认。
3. 资源提议的正文摘要身份必须与当前保存正文匹配。事务内再次核对完整正文、归属和待确认状态，防止 AI 调用期间发生手工修改或版本切换。
4. AI 核验可信且无冲突时，资源失去、消耗、损坏、销毁和底牌事件可自动确认。正文局部质量提醒保留其来源标记；它不等于每条资源事实都不可信，AI 可单独核验明确的事实。
5. 原提议高风险、低置信度、无证据、持有者或所有者冲突、可见性回退、不可逆状态错误复用，以及旧章节试图覆盖新章节账本状态，不能自动入账。
6. 用户保护的章节内容不进入自动核验。人工恢复锁不得由此流程解除。
7. 按任务与正文版本保存核验检查点，避免重启或恢复后重复计费。没有待核验提议时不调用 AI。模型核验失败保留提议，自动重试受检查点预算约束。

## 失败处理

AI 核验失败、决定暂缓、要求人工核对或仅确认部分提议，都作为资源层待处理事项保留。它们不把已保存章节改成失败，也不自动阻断全书执行。

正文版本变化、导演执行代次失效或写入失败属于完整性问题，必须拒绝确认。不能为了消除 UI 中的待确认状态，批量调用人工确认接口绕过这些保护。

既有历史提议保留原状态；打开页面是只读操作。历史补核验应通过明确的创作命令、原保存正文和相同的一致性规则处理，不能在 GET 或前端轮询中入账。

## 相关模块

- `server/src/services/novel/director/automation/resources/`：V1 归属检查、章节边界与核验检查点。
- `DirectorStateProposalResolutionService`：结构化 AI 决策、确定提议 ID、记录自动处理事件。
- `server/src/prompting/prompts/novel/directorStateProposalResolution.prompts.ts`：唯一的产品级核验 Prompt。
- `StateCommitService` 与 `CharacterResourceValidationService`：事务内确认、资源账本冲突与保留的风险保护。
- `docs/wiki/workflows/auto-director-candidate-auto-confirm.md`：角色候选确认是另一项能力，不能替代资源事实核验。
