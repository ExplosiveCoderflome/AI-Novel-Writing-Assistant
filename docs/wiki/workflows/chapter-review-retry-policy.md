# 章节检查重试策略

## 背景与决策

章节检查可能先修报告格式，再纠正引用，随后切换协议或模型。如果每一层独立允许一次重试，单章仍会出现多次额外调用；这类调用也不能当作多次有效正文修复。因此以章节为单位限制额外检查请求，并让作者决定次数耗尽后的行为。

## 当前规则

- 全局及本书问题处理偏好中的 `chapterReviewRetryPolicy` 包含 `maxRetries`（0–20）及 `onExhausted`（继续或人工暂停）。它与流程运行的 0/1 次自动恢复、正文局部修文额度分别计数。
- 初审和修文后的首次复验属于正常请求，不计入重试。其余格式修复、证据纠正、协议重发、备用模型和网络重试共用本章额度；设为 N 时，发生一次局部修文的检查主链至多是两次正常检查加 N 次额外请求。正文续写与资料同步不在这个数字中。
- V2 启动时把本书有效配置写入运行合同，再进入作业快照。修改设置只影响后续任务。历史快照缺字段时沿用原有质量策略：默认一次额外检查，质量优先暂停，完成优先继续；不得恢复时读取新的全局配置覆盖历史选择。
- 同一作业、同一章节保存正常检查预约、累计重试次数和未完成检查。正文或候选变化不能重新开始计数。比较更新保护并发预约；进程退出不归还已预约次数。
- 每次请求仍先核验取消和 Token 预算。重试次数与用量上限是独立约束，满足次数不能绕过用量暂停，已有消耗不可清账。
- 继续时保留可信正文和质量债，报告不可用不能生成合格分数。复验失败不能据虚构分数采纳候选。暂停使用现有 pending-manual-recovery 和源页恢复入口；后台轮询不得清除暂停。
- 用户明确选择耗尽后暂停时，V2 StopSignal 使用 `source=retry_policy`，Guard 还须验证冻结合同中的同一选择。完成优先模式的普通质量信号仍不可暂停。数据完整性、持久化、无可用正文和明确全局重规划不受跳过偏好放行。

## 证据与纠正边界

报告结构正确不代表正文证据正确。JSON 修复必须获得当前检查的完整正文来源，不能只根据 Schema 补出引文。语义纠正携带原始任务、最新报告与错误，不叠加整个历史对话。额度耗尽说明检查未完成，不能据此认定正文严重跑偏，更不能把每次纠正都记为正文重写。

AI 已明确分类的非 `voice` 问题不消费写法专用的 `layer/styleRuleId/canAutoRewrite`。接收层删除这些无关元数据，保留问题类别、严重性、证据和修复指令；不能为了纠正无关层次字段重发整份报告。`voice` 的层次约束、未知类别校验和候选正文证据校验仍须严格执行。这属于结构化结果后处理，不能据问题文本重新分类或把无效证据变成通过。

用量分析须区分规划、正文、初审、局部修文、复验和额外报告纠正。章节规划调用携带小说和章节身份，全书/分段规划不猜测章节归属；历史调用不回填或重置。单章用量边界仍由作业检查点与规划批次账本决定，不能直接将“没有 chapterId”解释为未计费或预算漏计。

## 失败排查

- 设置保存后未生效：核对全局/本书覆盖、V2 运行合同、作业 issuePolicySnapshot，不能仅检查前端表单。
- 重启后仍能继续重复调用：核对作业标识和 `chapter_review_retry_budget:v1`，不能改用候选正文 hash 作为额度身份。
- 预约记录损坏或写入失败：必须在发出请求前停止，不能降级为质量债后继续。
- 自定义暂停变成“拒绝次数耗尽”：核对 batch outcome、StopSignal 来源、FactsLoader 和 Guard 是否共同接受冻结策略。
