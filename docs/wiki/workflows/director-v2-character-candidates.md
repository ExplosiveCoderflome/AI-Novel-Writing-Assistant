# 导演 V2 正文人物候选与运行模式

## 背景

开书阵容不是小说的固定人物上限。正文可能引入新人物或说明既有人物别名；直接照搬 V1 的确认逻辑会额外重建全阵容，既增加用量，也可能改变已有角色资料。身份识别需要 AI，保存与恢复需要确定的事实边界。

## 决策

身份判断合并在最终正文的章节资源提取中，返回新增、关联、暂缓或忽略建议、已有角色 ID 和正文证据。应用层只做归属、引用与证据校验，不通过名字相似度决定人物身份。

| 本次运行方式 | 角色候选行为 |
| --- | --- |
| 全自动 | 执行证据有效的新增、关联或忽略建议；身份不确定或校验不足的候选保留待处理，不中断后续章节。 |
| 按阶段确认 | 在章末集中展示候选，作者选择新增、关联已有角色或忽略；保存选择后显式继续。 |

模式只读取持久运行合同，不读取全局模型栏、开书默认值或下一轮表单；不因出现候选切换运行模式。候选确认不是章节质量失败。

## 时序与恢复

1. 最终修复完成，正文和最终结果检查点保存。
2. 复用同一份章节资源提取，先确认人物身份。
3. 将已确认身份绑定到本章结构化引用，再执行位置、资源、关系和信息等回填。
4. 必要回填完成后才关闭章节并进入下一章。

半自动等待沿用正文作业的待手工恢复状态。页面保存候选选择不会自动启动下一章；只有来源页的显式继续命令可以恢复。恢复前再次核对正文版本和全部候选处理结果，恢复后复用定稿和提取结果，不重写正文、不重做身份扫描。

一份候选记录按运行、章节和最终正文哈希持久化。角色建档、关联与处理记录同事务完成；并发和重复请求不会重复建角。切换导演代次、替换当前运行、修改正文或引用其他书角色时拒绝旧写入。

## 用量与缓存

- 不新增候选专用模型调用，不调用 V1 全阵容动态重建，也不因新人物重跑已生成章节。
- 身份输出只携带最小资料；完整人物外显、思维等补全仍是独立能力。
- 提取保留固定规则和稳定书级前缀，角色名单有真实新增时才变化；状态和正文按章更新，不能为了缓存省掉新人物。
- 老提取结果缺少身份建议时默认为暂缓，不重新花费 Tokens 换取自动确认权限。厂商返回的实际缓存命中仍以 AI 用量页为准。

## 前端和隔离

本书导演台展示“正文发现的人物”、建议和正文依据；新增人物显示在角色目录。候选确认接口独立于内核命令，运行记录继续只读。V2 候选使用独立状态标记，V1 自动队列和旧确认入口不能消费；保留 V1 原来的候选流程。

全自动留下的存疑候选在本轮处理结束后可人工确认。同一本书、同一导演代次的后续批次继续展示这些候选，确认时仍核对来源正文；旧半自动批次的确认门禁不继承到新运行。该操作补充身份资料，不补跑历史整套回填，也不恢复旧任务。历史已完成正文不会因启用本能力而自动重跑。
