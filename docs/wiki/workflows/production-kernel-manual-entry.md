# V2正文的手动生产与审校

## 背景

自动生产完成的章节仍需人工编辑、局部修章和重新审校。如果手动入口继续运行另一套生产编排，候选核对、质量债和预算语义会再次分叉。手动操作也不能借用已经结束的自动任务租约。

## 决定与当前规则

应用层根据作品的持久导演归属分流，V1保留原入口。启用正文新流程的V2作品通过现有命令创建独立单章计划，使用相同worker、租约、书代次与ProductionUnitRun。新手动作业的scope包含自己的runId；重入同一任务复用阶段结果，另一次显式操作不能复用前一次的完成证明。

手动写章只对空正文执行；修章读取当前已保存正文，使用统一长篇配置、问题策略、安全补丁和候选事实核对；重新审校禁用修补，保留当前正文。人工编辑仍使用原编辑服务的版本保存和同步义务；未保存内容不进入正式审校报告。

手动授权允许处理启动前已经存在的人工正文，不允许覆盖任务期间的新编辑。提交和回填继续核对原始正文及版本，候选在通过复验与选稿前不发布。所有带模型请求的阶段仍使用冻结配置、完整请求预检和持久预算。

## 来源页与运行记录

正文来源入口保留既有JSON和SSE协议。SSE结束时只返回选中并保存的正文及审校上下文；检查或回填未完成时不能把候选当作完成结果。断开页面只结束等待，任务仍可在本书工作台查看并处理。运行记录保持只读，确认、取消和恢复从来源页执行。

灰度沿用默认关闭的正文内核开关；已经创建的手动内核任务按保存契约恢复，不因之后关闭灰度而进入旧流水线。资料检索设置独立保留。

## 常见失败

- 没有本作业进度却直接显示完成：检查是否复用了其他作业的终态引用，或重复手动操作使用了相同scope。
- 候选复验在发请求前报数组缺失：预检必须从初审服务返回值取`assessment`，与实际复验输入一致；不能把整个服务结果当作评估对象。
- 作品切换过导演版本后长期排队：手动运行必须保存当前书epoch，不能隐含假设为0。
- 审校期间发生编辑：保留新正文，旧任务不得写回或发布其报告；从当前保存版本重新开始。
