# 模型兼容性与结构化调用合同

## 背景与决策

同一模型名在原厂和转发服务上可能具有不同接口能力。模型名称只能提供默认值，不能证明某个网关支持原生 JSON 或思考参数。能力档案按厂商、完整模型名和可选主机隔离，通过现有 `appSetting` 保存，无需新增数据库迁移。

影响范围为 LLM factory、结构化调用及修复、思考流采集、模型路由和模型设置页；不改变章节质量政策、导演检查点或任务恢复规则。

## 当前规则

1. 解析优先级为用户覆盖、探测结果、内置默认、保守提示约束 JSON。同级优先使用精确主机，未指定主机的覆盖可以适用于该厂商与模型的各端点。
2. `resolveLLMClientOptions` 先加载档案，再使用能力适配参数；兼容用的同步查询读取进程缓存。外部数据库写入需重启进程才能清除已加载的缓存，设置页操作在当前进程立即生效。
3. 结构化调用按档案顺序尝试，通常为 `json_schema → json_object → tool_calling → prompt_only`，已失败模式跳过。内部保留 `prompt_json` 名称以兼容原调用接口。顶层数组继续走提示约束方式。
4. 每个结果必须经过现有 Zod 解析。工具模式读取流式工具参数，提示与工具模式默认复用一次格式修复，并提供校验错误。业务语义校验仍属于 Prompt Runner。
5. 明确不支持参数、空原生结果或格式错误可形成端点能力失败记录。鉴权、限流、取消、网络故障及输出额度耗尽不能证明模式不受支持；仍遵守原有请求额度、传输重试与取消规则。
6. Spark MaaS 默认使用提示约束 JSON。只有探测或用户明确覆盖才能启用原生方式；遇到明确的结构化传输拒绝必须降级。
7. 思考控制由档案中的控制提示转换为参数。`vendor/` 仅在家族识别时去除。只有内置 DeepSeek 厂商且使用官方端点（或未指定端点而使用官方默认值）时，才能按模型名赋予 DeepSeek 家族与思考开关；自定义厂商或中转地址必须依赖探测或用户覆盖，不能因模型名相同而发送 `thinking` 和 `reasoning_effort`。禁用思考的验证要求返回可用 JSON 且思考文本接近零，不能仅凭 HTTP 200 判定支持。
8. LangChain 可能丢弃厂商的扩展思考字段。探测保留原始流增量，同时检查 `reasoning_content`、`reasoning`、`reasoning_details` 和 `<think>`；不能把字段未透传误当成关闭成功。
9. 自定义厂商或覆盖内置默认主机的端点，在没有探测或用户覆盖档案时，结构化调用必须关闭请求级思考，不能以“尚未确认支持开关”为由继承默认开启。策略要求关闭与端点能否接受关闭参数是两件事：未知控制协议时省略思考参数，不猜测厂商字段；这不保证网关自身默认开启的思考已被关闭。探测或用户覆盖仍优先决定控制能力，普通文本调用保留原有思考设置。

## 模型输出上限

`maxOutputTokens` 与能力档案一同保存，按厂商、完整模型名、主机隔离。设置页切换模型后可分别保存，留空删除上限。该值作为正文、结构化及修复请求的输出额度，覆盖历史步骤默认值与结构化保守默认值，避免被 8K 默认值截断。生产链已捕获的任务额度仍是授权边界，最终额度取其与模型上限的较小值。未配置时完整保留旧预算行为；清空输出上限不清除其他能力覆盖。

## 探测与人工覆盖

### 与生产预检的合同

Prompt Registry 渲染负责补齐结构化输出提示；带有注册 Prompt 元信息的调用必须保留该完整消息序列，兼容适配不能在冻结后追加 schema 消息。否则首次物理请求会被生产快照围栏拒绝，不能通过关闭围栏解决。预检与调用必须共用策略序列及协议参数构造，将工具定义、工具选择和 JSON 响应格式计入输入预算；新增能力模式时须同时验证生产准备、JSON 纠错与断点复用场景。

配置身份冻结的是实际调用参数，包括模型、端点摘要、鉴权方式、思考控制、输出上限与预检过的具体策略。能力档案的失败模式属于调用观察，不单独加入配置哈希：一次原生模式拒绝可以更新观察并继续使用预检过的其他模式；如果观察导致实际调用参数改变或要求使用未预检的模式，原有围栏仍须拒绝。

真实请求必须显式启用。设置页提供手动探测及保存／切换模型时自动探测，后者默认关闭；开启会检查当前模型。探测先试 `json_object`，再试 `json_schema`、工具调用，并检查提示输出。缓存按调用时的优先顺序保存成功模式。鉴权、限流或服务故障不会覆盖已有档案。

未知服务若在无控制参数时返回思考文本，可通过禁用候选参数后比较响应来学习控制提示；没有正面证据时保持未确认。用户覆盖独立保存，重探不能静默覆盖用户选择。设置页覆盖适用于有明确服务商接口说明的自定义连接。

探测异步执行，状态与最近结果保存在设置中，不进入应用启动链。CLI 运行前构建服务端，再执行 `pnpm --filter @ai-novel/server compat:check --allow-network`；不传该参数只显示用法。命令使用数据库与环境中的厂商配置，不输出密钥。

## 验证与故障诊断

- 单元测试使用内存设置和固定流响应，不调用真实厂商、不写应用能力设置。
- 原生模式失败时，检查实际端点与档案的主机键、失败模式、诊断中的实际策略；不要仅根据模型名增加业务分支。
- 思考关闭失败时，检查实际请求参数与原始流中的思考字段，避免只观察正文。
- 暂时的连接故障应保留既有能力；重新探测成功可清除探测档案的旧失败模式，用户覆盖仍优先。
