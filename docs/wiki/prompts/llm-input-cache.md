# 模型输入缓存统计

## Background

相同前缀的模型输入可以复用供应商缓存。缓存只改变处理成本与延迟，不代表模型跳过生成，也不能用命中量抵扣章节真实用量预算。

## Current Rule

- 共享统计结构位于 `shared/types/llmUsage.ts`；平台 `platform/llm/usage` 归一化厂商数据，`llm/usageTracking` 保留业务计数入口。
- 命中与未命中均包含于输入总量；创建缓存属于未命中，不在合计之外再次相加。
- 原生 Anthropic input 不含读取/创建量，标准 SDK input 已归一化。读取 raw metadata 时不能给 SDK 总输入重复加缓存。
- 显式零与字段缺失有不同意义：未提供为 null；非法、冲突或输入不匹配使缓存统计不可用，保留合法的基础总量。
- 同一流的累计 usage 只合并，不求和；不同请求才求和。任一请求没有缓存报告，汇总不能伪造完整覆盖。
- 字符长度和相同前缀仅能辅助分析，不是真实缓存命中统计。
- 审校结果缓存与供应商输入缓存是两种机制。审校结果复用必须同时匹配正文 hash 和完整请求身份（提示词版本、有效合同、模型与参数、修文复验基线）；不能因正文不变就忽略请求身份。改变合同后沿用旧结论会掩盖真实缺口，不能作为省 Tokens 的手段。
- 修文复验的候选身份与核对清单都属于实际输入。历史证据不进入核对清单；证据校验失败沿用 acceptance_gate_unavailable，不能进入成功结果缓存，也不能为提高命中率沿用旧审校。版本切换的首次调用与随后同版本复验应分开观察。

## Failure Modes

- SDK 先返回基础 usage，raw metadata 才有缓存字段：归一化必须合并同次响应的信息，不能读到基础 usage 后直接忽略其余来源。
- 最后流帧省略缓存明细：在输入总量一致时保留同次调用早先返回的明细；输入变化/来源冲突时标为无效。
- 只有便宜的缓存输入但总量仍过预算：预算沿用真实输入输出总量，恢复须从创作来源页显式执行。

## 持久化与归属

调用台账独立于旧导演表，通过组合层与正文 worker 显式记录新导演 runId。失败无 usage 仍保留请求身份，查询不得将未知或部分覆盖展示为完整合计。实况与持久化台账分工：实况短期多尝试合计，台账长期逐次排查；均不代替安全预算。台账仅新调用有数据，不推算历史。

## 只读展示

导演台与运行记录仅按 runId 查询台账，不触发模型或改变任务。只显示命中/未命中两项，保留既有基本用量。浏览器旧快照缺字段显示未记录，不当作零；活动会话缺数据显示统计中，结束后厂商无报告显示未提供，非法报告显示统计不可用。未知覆盖用普通提示，不是任务失败。

本书独立 AI 用量页按小说汇总跨批次调用，输入、输出、总计与缓存已报告部分分开展示；缓存覆盖数必须同时显示。这一部分统计合同不替代 run 级完整缓存合同，不与旧任务计数相加。参见 [小说 AI 用量与调用日志边界](../workflows/novel-ai-usage.md)。

## 上下文布局

正文/验收先渲染显式书级或卷级材料，再附本章任务与状态。reuseScope 缺省 request，文风规则基于结构化来源声明 book，但每次从当前合同渲染；角色位置、场景、义务以及检索混合内容必须逐章更新。正文篇幅/补写要求保持 System 角色且位于静态规则后。高级模板不重排，动态示例留尾部，静态 JSON 骨架只有资产明确声明时前置。布局只操作预算已选中的材料，不能改变丢弃或压缩政策。

## 厂商请求边界与回退

已注册资产声明稳定边界；静态骨架插入成功时边界延伸到该消息，动态示例或自定义模板不继承。Claude 转换保留各系统文本块与相邻用户文本块，避免合并后把正文误缓存或丢失骨架标记。百炼兼容 SDK 只改标记消息的内容块，保持其角色、其他消息与调用次数。

资产抽取和伏笔校准的边界可延伸到独立的书级资料消息。原始消息下标以资产 render 结果为准；运行器插入静态骨架后，位于插入点之后的声明同步后移。按消息身份确认实际插入，不能仅因 placement 声明就偏移，否则动态示例或高级模板会标错缓存对象。

资源目录与当前状态分开：目录稳定排序并每次读取，持有者、所有者、状态、知识边界、限制和窗口放在动态段。角色目标和伤势不属于身份目录；正文也不属于稳定目录。整体校准的全书和分卷规划前置，最新正文、状态、冲突与审校问题在后。修改身份、增删资产或修改规划仍应改变前缀，不能为命中率继续读取旧资料。

官方 HTTPS 端点和已核验模型才添加短 TTL cache_control，默认停用开关为 LLM_EXPLICIT_CACHE_ENABLED=false；未知通道/模型保持原样。厂商 400 直接报告，不能为缓存参数增加模型重试。缓存创建可能具有额外计费，避免长 TTL 或额外预热请求。正文、验收、资产 delta、伏笔对账、章节规划、局部补丁和重规划窗口决策使用此布局；角色状态/账本/正文始终按请求更新。

## 规划与修复的可复用资料

### 分阶段判断收益

不得用整条章节链的单一命中率判定正常或异常。首次调用、Prompt 版本切换、模型/通道变化应与重复调用分开观察；供应商是否保留对应前缀仍由供应商决定。

| 阶段 | 可复用材料 | 必须变化的材料 | 优先判断 |
| --- | --- | --- | --- |
| 章节规划 | 作品约定、卷级目标、静态输出合同 | 本章任务、人物状态、近期实际结果 | 是否减少无关输入并保留因果接续 |
| 正文 | 文风、世界硬规则、作品约定 | 上章尾段、当前场景、知识边界、本章事件 | 正文可读性与必要未命中量，不强求统一比例 |
| 验收 | 检查标准、同章任务与约定 | 原稿或候选正文 | 重复检查的前缀复用与验收次数 |
| 修文 | 表达规则、作品约定、编辑边界 | 问题证据、AI 指令和修改对象 | 候选采纳与是否避免无效复验 |
| 资产抽取 | 抽取规则、静态输出合同、确实未变化的人物资料 | 正文、最新状态、资源和伏笔账本 | 结果完整、证据可追溯、无重复解释 |
| JSON 修复 | 有限格式规则 | 不完整或不合法结果 | 减少发生次数，而非追求高命中 |

比较相同阶段、相同 Prompt 版本和同一模型/通道的连续请求时，同时观察输入命中 Tokens、输入未命中 Tokens、输出 Tokens、调用次数和每章总用量。不能为了比例好看增加冗余上下文、模型预热或不必要的修文/验收；必要的新剧情上下文未命中是正常成本，减少调用可能降低总命中率但改善总消耗。

章节规划仅把结构化来源明确的小说简介、书级 framing、故事模式、作品圣经声明为 book。写法引擎混合内容、章节职责、伏笔、卷窗口和状态缺省 request，不能为增加命中而冻结。预算选择先执行，渲染再将选中的 book/volume 材料前置；选中内容可能随预算变化，不能保证相邻调用整段命中。

局部补丁按“静态规则和骨架 → 书级资料 → 同章合同、状态及完整正文 → 本次修复重点、问题和自定义追加约束”组织。修复重点保持 System 角色，补充问题和自定义约束仍为 Human；只有本次指令变化时，同章资料与正文前缀可继续复用。预算选择不变，已选中的问题和约束完整传递，不能丢弃或冻结来增加命中。只前置静态骨架，不把高级模板或动态示例误标为静态；显式缓存标记仍只覆盖已有静态边界，不给动态正文添加标记。

正文、验收和修文共用的 production foundation 由小说题材与故事模式设置生成，属于 book 范围，置于逐章任务之前。每次从当前作品设置重新渲染，修改题材或故事模式必须改变前缀；章节职责、知识边界、人物状态和当前里程碑不得混入该块。

审校以合同中的行动、代价、结束态和正文证据为依据。普通表达提升与必须即时修复的缺口分别用 riskTags 和 repairDirectives 表达，AI 负责此判断，不能按问题关键词放行。章节已有未决选择、代价或具体下一步时，不为强化钩子强加追兵或新场景；合同明确指定的动作与载体仍必须兑现。怀疑或含糊警告不能自动等同于秘密泄露，有真实信息冲突时仍须报告。

静态验收示例使用有依据的接收结果与后续提醒，避免示例引导每章补写结尾；Schema 与正文质量检查保持不变，模型必须按本次证据选择接收、修复或暂停。补丁先核对证据，不把无需修改的正文强行扩写；信息歧义确需修复时，应修正含义而非只改标点。这些 Prompt 判断的收益须通过新生成的候选采纳、质量提醒、调用次数及真实命中/未命中 Tokens 验证。

局部补丁的书级合同基线和文风属于必需、禁止摘要的 book 块；当前阶段里程碑独立为 request 块，不得混入书级前缀。相关世界规则和保护秘密属于必需、禁止摘要的动态块，即使缺少状态目标也必须保留秘密。每次调用读取当前资料，修改合同或文风后前缀随之更新，不能冻结资料来追求命中率。

这些安全块可能增加单次修文输入，但能防止补丁因遗漏世界约束、文风或保密条件而被重新验收拒绝。优化成效应同时观察实际输入、命中/未命中、修文次数及候选采纳；不能只追求更高命中百分比。减少无效调用也可能让总体命中率降低，不代表实际成本变高。

## 重规划输入的无损共享

重规划快照拆分为书级合同与世界规则基线，以及人物、当前处境、叙事状态与时间线。每次决策读取当前快照，资料修改立即生效；投影只用于 Prompt，不能替换存储快照。

同一伏笔可能同时出现在 pending、urgent 和 overdue 列表。完全相同的记录在 `payoffStates` 中保存一次，各列表用从 0 开始的索引保留成员、顺序和归属。比较完整字段值，同 ID 的不同事实、状态或时间版本不得合并。静态规则必须说明还原方法；测试须验证全量往返一致与尾部秘密保留，不能靠关键词挑选事实。

状态、审校、账本摘要、章节目标和秘密使用 required/allowSummary=false 的上下文块，计入 estimatedInputTokens。可选预算不足时这些块仍完整发送：预算不是事实截断许可。模型侧安全预算继续使用厂商实际输入输出总量；缓存命中不能抵扣安全计数。

## 开发库统计表的诊断

实况已有缓存字段而运行记录没有逐次调用时，先检查 `LlmInvocationUsageRecord` 是否存在及是否产生持久化错误。缺表会阻止台账写入，但不会改变供应商缓存命中。

补建前核对当前 DATABASE_URL，使用 SQLite 在线备份纳入 WAL，并校验备份可打开、大小与 quick_check。只执行已审查的用量表增量迁移，在事务内记录与迁移文件一致的 checksum；避免把未知的其他待执行迁移一起部署。检查正文和作业内容、业务表数量保持一致。台账从后续调用开始积累，不伪造或倒填旧历史；空记录也不能解释为旧调用缓存命中为零。
