提示词管理用于查看和维护产品级 AI 任务使用的提示词资产。它适合开发者、调试者和需要理解任务行为的高级用户。普通写作用户不需要频繁进入此页面，创作主链应通过自动导演、小说与章节工作台推进。

<Info>
  提示词管理只影响提示词本身，不涉及模型厂商配置、API Key 或模型路由。模型相关设置请在 [系统设置](/system-settings) 中完成。
</Info>

## 适合什么时候打开

提示词管理不是日常创作入口。以下场景才需要进入：

- 想了解某类 AI 任务如何组织输入。
- 某个任务输出持续不稳定，需要检查提示词版本。
- 需要确认提示词和模型路由的绑定关系。
- 开发者准备调整结构化输出或任务契约。

普通用户优先调整小说资料、知识库、写法引擎和模型路由。只有当同类任务长期表现异常，并且数据和模型都已排查后，再考虑提示词。

## 界面结构

提示词管理页分成三个主要区域：

| 区域 | 功能 |
| --- | --- |
| 左侧提示词目录 | 按任务类型列出提示词资产，例如正文生成对应 `novel.chapter.writer` |
| 中间编辑区 | 查看和修改 system / human 模板，生成预览，测试当前草稿产出 |
| 右侧上下文面板 | 查看本次预览注入了哪些资料，例如书级合约、章节任务、角色硬事实、时间线、风格合约 |

底部操作区用于生成预览、测试产出、保存本书覆盖、重置修改或恢复官方模板。

## 提示词分类

提示词通常按任务家族组织，每类对应明确任务：

| 任务家族 | 典型用途 |
| --- | --- |
| 开书方向 | 自动导演生成新书创意和方向 |
| 世界和角色准备 | 世界观、角色设定生成 |
| 卷规划和章节计划 | 卷结构、章节任务编排 |
| 正文生成 | 章节正文写作，对应 `novel.chapter.writer` |
| 审核和修复 | 正文审阅、问题修复 |
| 拆书分析 | 参考作品结构拆解 |
| 知识库摘要 | 资料摘要和检索 |
| 写法提取 | 从样本文本提取风格规则 |

每类提示词应对应明确任务，而不是把大量无关指令堆在一起。

## 编辑正文生成提示词

正文生成提示词是最常被调试的提示词。进入方式如下：

<Steps>
  <Step title="打开提示词管理">
    在左侧目录选择 `novel.chapter.writer`。
  </Step>
  <Step title="选择范围">
    选择本书范围，并指定要预览的小说和章节。
  </Step>
  <Step title="切换编辑模式">
    在中间区域切换「安全槽位」或「高级模板」。
  </Step>
  <Step title="生成预览">
    点击「生成预览」，检查最终 messages 和右侧上下文注入结果。
  </Step>
  <Step title="测试产出">
    需要验证效果时，点击「测试产出」，在弹窗中选择测试模型并开始测试。
  </Step>
</Steps>

### 安全槽位

安全槽位适合修改局部规则，例如语气、节奏、反 AI 味规则或补充写作要求。它不会改变提示词的整体结构，适合多数调试场景。

### 高级模板

高级模板适合成熟用户完整调整 `novel.chapter.writer` 的 system / human 模板。它只作用于当前书籍的正文生成，不开放 schema、上下文策略、后处理校验或其他提示词的自由替换。

## 可视化引用标签

高级模板默认使用可视化引用标签。编辑器里看到的是「书级合约」「章节任务」「角色硬事实」「时间线」「章节标题」「语气与节奏」这类中文标签，而不是要求用户记住 `{{context.book_contract}}`、`{{input.chapterTitle}}` 或 `{{slot.tone_and_pacing}}`。

### 使用方法

- 在编辑器里输入 `@`，从引用菜单选择上下文、运行变量或槽位。
- 选择后会插入一个标签；保存和预览时，系统仍会把它编译为底层模板 token。
- 鼠标悬停标签可以查看 key、原始 token、说明和是否为必需上下文。
- 删除标签后重新用 `@` 插入，适合替换错误引用。
- 如果模板里存在未识别 token，编辑器会保留原始内容并显示异常状态，方便排查但不会悄悄丢失文本。

### 常见标签含义

| 类型 | 标签示例 | 用途 |
| --- | --- | --- |
| 上下文 | 书级合约、章节任务、时间线、角色硬事实 | 把当前书籍和章节的资料注入正文生成 |
| 运行变量 | 章节标题、目标字数、章节序号 | 使用本次运行时传入的参数 |
| 槽位 | 语气与节奏、反 AI 味规则、自定义补充规则 | 复用安全槽位中的可编辑规则 |

### 源码视图

高级模板保留源码视图，适合调试底层模板：

- 可视化视图面向日常编辑，优先显示中文标签。
- 源码视图显示真实模板文本，例如 `{{context.chapter_mission}}`。
- 从源码视图切回可视化视图后，已注册引用会重新显示为标签。

如果只是调整写作效果，优先使用可视化视图和 `@` 引用菜单。只有在排查 token、复制模板或确认编译结果时，再切换源码视图。

## 上下文注入面板

右侧上下文面板用于确认模型实际会看到哪些资料：

| 显示项 | 说明 |
| --- | --- |
| 上下文块名称和分组 | 明确资料来源 |
| 是否为必需上下文 | 系统治理规则锁定，不能在界面中关闭 |
| token 估算 | 帮助判断上下文长度 |
| 当前状态 | 被选中、裁剪、摘要或缺失 |
| 预览内容 | 检查资料是否来自当前小说和当前章节 |

正文生成常见必需块包括书级合约、章节任务、角色硬事实、义务合约、风格合约和时间线。这样可以避免用户误删关键资料，导致章节脱离主线或违反前文状态。

## 预览、测试与保存

推荐每次修改后按这个顺序操作：

<Steps>
  <Step title="生成预览">
    检查 system / human messages 和上下文注入是否完整。
  </Step>
  <Step title="确认上下文">
    查看右侧上下文，确认资料来自目标小说和目标章节。
  </Step>
  <Step title="测试产出">
    在弹窗中选择测试模型，查看当前草稿在真实模型下的返回。
  </Step>
  <Step title="保存覆盖">
    如果只是局部调整，优先保存为本书覆盖。
  </Step>
  <Step title="版本管理">
    高级模板改坏时，可回滚历史版本或恢复官方模板。
  </Step>
</Steps>

### 生成预览与测试产出的区别

| 操作 | 作用 | 是否调用模型 |
| --- | --- | --- |
| 生成预览 | 查看最终 messages、上下文注入、缺失资料和诊断信息 | 否 |
| 测试产出 | 用当前草稿和所选模型生成一次结果，判断改动效果 | 是 |

测试产出不会要求先保存草稿。结构化提示词会显示解析后的 JSON 和修复次数，文本提示词会显示模型返回正文；如果测试不理想，可以继续调整后再保存。

保存高级模板会生成本书版本历史。恢复官方模板不会删除历史版本，后续仍可查看和回滚。

## 正文效果实验室

正文效果实验室用于比较「模板修改后会写成什么样」，入口位于章节编辑器和写法引擎。它会自动定位正文生成提示词，并带入当前小说和章节。

推荐流程：

<Steps>
  <Step title="打开实验室">
    从章节编辑器或写法引擎打开「正文效果实验室」。
  </Step>
  <Step title="确认范围">
    选择目标小说和章节，确认右侧上下文来自正确项目。
  </Step>
  <Step title="调整草稿">
    在安全槽位或高级模板中调整当前草稿。
  </Step>
  <Step title="开始试写">
    使用真实模型生成对照正文，根据流式显示的结果继续调整。
  </Step>
  <Step title="保存版本">
    满意后再保存本书模板版本。
  </Step>
</Steps>

试写使用当前未保存模板，不会覆盖章节正文，也不会修改章节状态。它会调用真实模型并消耗额度；如果只想检查最终 messages 和上下文，使用「生成预览」。

| 操作 | 适合做什么 | 会不会改正文 |
| --- | --- | --- |
| 生成预览 | 检查模板、引用和上下文是否完整 | 不会 |
| 开始试写 | 比较模板修改后的正文读感 | 不会 |
| 保存为新版本 | 让后续本书正文生成使用该模板 | 只影响后续生成 |

## 使用边界

提示词管理不会绕开系统治理规则：

- 不能关闭 required context。
- 不能在页面里修改 `contextPolicy`。
- 不能修改结构化输出 schema。
- 不能关闭正文生成后的校验、修复或状态同步链路。
- 高级模板第一优先覆盖正文生成 `novel.chapter.writer`，其他提示词仍以安全槽位和预览为主。
- 测试产出只执行已注册提示词和当前草稿，不提供任意 system prompt 绕过入口。

<Warning>
  如果问题来自小说资料缺失、章节任务不完整、模型能力不足或结构化输出不稳定，单纯改提示词可能无法解决。应先回到对应模块补齐资料或检查任务失败原因。
</Warning>

## 编辑提示词前先确认

修改提示词前，建议先确认以下事项：

- 当前问题是否真的来自提示词。
- 模型路由是否合适。
- 输入数据是否完整。
- 输出 schema 是否被遵守。
- 失败是否可通过重试或换模型解决。

提示词不是所有问题的第一修复点。结构化输出、模型能力、上下文资料和任务状态都可能影响结果。

## 版本和回退

提示词调整会影响后续 AI 任务。建议保留版本意识：

- 明确记录调整目的。
- 只修改与目标任务相关的提示词。
- 用测试小说验证结果。
- 保留可回退版本。
- 避免同时改模型、数据和提示词，导致问题来源难判断。

公开产品级提示词应走统一注册和 schema 管理，不建议在业务代码中临时内联。

## 和任务绑定

提示词管理的价值在于理解「哪个任务使用哪个提示词」。排查时可以按路径看：

<Steps>
  <Step title="确认任务类型">
    在任务中心确认失败任务类型。
  </Step>
  <Step title="检查模型路由">
    确认当前任务使用的模型是否合适。
  </Step>
  <Step title="查看提示词">
    在提示词管理确认任务提示词和输出要求。
  </Step>
  <Step title="测试验证">
    回到测试小说验证修改效果。
  </Step>
</Steps>

如果任务需要结构化输出，提示词和输出 schema 必须一起考虑。
