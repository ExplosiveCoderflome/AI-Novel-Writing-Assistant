## 安装与启动

<AccordionGroup>
  <Accordion title="Mac 提示「无法打开」或「已损坏」">
    当前 Mac 安装包未做 Apple 签名与公证。到 **系统设置 → 隐私与安全性** 点「仍要打开」；提示「已损坏」时在终端执行：

    ```bash
    xattr -dr com.apple.quarantine "/Applications/Biz Novel Studio.app"
    ```
  </Accordion>
  <Accordion title="启动页一直停在「启动受阻」">
    1. 完全退出应用，再重新打开。
    2. 检查杀毒软件或安全软件是否拦截了本地服务。
    3. 仍然失败时，从启动页打开日志，或在「版本与更新」里保存日志包，附在 [Issues](https://github.com/ExplosiveCoderflome/AI-Novel-Writing-Assistant/issues) 中反馈。
  </Accordion>
  <Accordion title="数据存在哪里，怎么备份">
    见 [安装下载](/installation) 中的「数据保存在哪里」。备份前先完全退出应用，再复制整个数据目录。
  </Accordion>
  <Accordion title="便携版和 Mac 版为什么不能自动更新">
    只有 Windows 安装版支持应用内更新。便携版下载新版替换程序并保留 `-data` 文件夹；Mac 版下载新 `.dmg` 覆盖安装，数据不受影响。
  </Accordion>
</AccordionGroup>

## 模型与连接

<AccordionGroup>
  <Accordion title="连接测试失败">
    依次检查：

    1. API Key 是否完整，有没有多复制空格。
    2. API 地址是否是接口地址，而不是供应商的网页地址；路径有没有多写或少写。
    3. 模型名称是否和供应商文档完全一致。
    4. 网络能否访问供应商接口，账户是否还有额度。

    连接不通时不要继续开书，先让检测通过。
  </Accordion>
  <Accordion title="普通文本通过，结构化输出不通过">
    规划步骤需要模型返回严格的结构化结果。思考型（推理）模型容易把输出额度耗在思考过程上。换一个非思考模型，或在供应商支持时关闭思考模式；新版已内置兼容层，先升级到最新版本再试。
  </Accordion>
  <Accordion title="连接测试通过，生成还是失败">
    连接测试只验证地址、密钥和模型可达。生成失败通常是：额度不足、某个步骤路由到了不可用的模型、或输出上限（maxTokens）设得太小导致截断。到本书导演台看暂停原因，再到 [模型配置](/model-configuration) 调整对应步骤。
  </Accordion>
  <Accordion title="本地模型总是超时">
    本地大参数模型生成慢，规划这类长输出步骤最容易超时。把规划步骤路由到云端模型、本地模型只跑正文，或换更小的本地模型，并确认本地服务全程开着。
  </Accordion>
</AccordionGroup>

## 创作过程

<AccordionGroup>
  <Accordion title="全自动为什么也会停下">
    全自动只执行你授权的范围。例如提交第 1—3 章，写完就停，不会擅自写第 4 章，需要你选择下一段。

    另外，遇到模型不可用、需要重新规划、达到用量保护上限或数据完整性问题时也会暂停。暂停不等于失败，进度和已保存正文都会保留。
  </Accordion>
  <Accordion title="暂停后怎么继续">
    1. 打开本书导演台，阅读暂停原因。
    2. 排除外部问题：补充额度、切换模型、检查网络。
    3. 按提示从本书导演台继续。

    需要追溯时打开「运行记录」查看状态和来源。不要靠重复点击生成来代替恢复，也不要删除小说重来。
  </Accordion>
  <Accordion title="提示达到单章用量上限">
    V2 单章默认上限是 100,000 Tokens，累计该章的生成、检查、修文和资料整理调用。可以在本书导演台按建议或自定额度继续本章；想改全局默认值，到 **设置 → 自动导演** 调整。详见 [AI 用量](/features/token-usage)。
  </Accordion>
  <Accordion title="章节有质量提醒，要不要停下来修">
    默认的「优先完成整本书」策略会把普通局部问题记录为章节提醒并继续写。想更严格，可以在 **设置 → 自动导演** 切换为「质量优先」，或只为某本书单独设置。
  </Accordion>
  <Accordion title="导演 V1 和 V2 选哪个">
    新书推荐 V2。已有小说可以继续用原来的版本；切换前需要先结束当前创作，切换只保存选择，不会自动开始生成。对比见 [快速开始](/quickstart)。
  </Accordion>
</AccordionGroup>

## 知识库

<AccordionGroup>
  <Accordion title="不配 Qdrant 能用吗">
    能。Qdrant 只用于知识库向量检索，不是开书和写第一章的前提。想先跑通主线，源码运行时设置 `RAG_ENABLED=false` 即可。
  </Accordion>
  <Accordion title="知识库检索不到内容">
    按顺序检查：文档是否上传成功、索引任务是否完成、Qdrant 是否能连接、检索设置是否过窄。文档很长时，在标题或关键段落里写明设定名、角色名和地点名，更容易被召回。详见 [知识库](/features/knowledge-base)。
  </Accordion>
</AccordionGroup>

## 反馈问题

到 [GitHub Issues](https://github.com/ExplosiveCoderflome/AI-Novel-Writing-Assistant/issues) 提交时，尽量带上：

- 应用版本（顶部栏版本号）和系统
- 操作入口和步骤
- 使用的模型供应商和模型名
- 暂停原因或报错原文、截图
- 桌面版日志包（在「版本与更新」中保存）
