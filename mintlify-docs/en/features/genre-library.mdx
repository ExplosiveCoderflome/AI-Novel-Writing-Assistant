The Genre Library is used to organize the type foundations of your work. It helps you explain roughly what genre a book belongs to, what readers will expect, and what the common selling points and boundaries of that genre are. A genre base does not replace a specific outline, but it provides direction for the world, characters, and chapter planning.

<Note>
  Content in the Genre Library is reusable assets, not the genre currently in use by a specific novel. After referencing it when starting a book, you can still adjust it separately for the current work.
</Note>

## What It Can Do / Applicable Scenarios

- Prepare a clear genre direction for a new book, such as fantasy, urban, sci-fi, suspense, history, cyberpunk, post-apocalyptic, etc.
- Record common reader expectations, core satisfying moments, world boundaries, and taboo pitfalls for a certain genre.
- Make Auto Director, project settings, character preparation, and chapter generation clearer about "what this book should be like."
- Accumulate your frequently written and researched type experience into reusable assets.
- When the story direction generated by the system is too generic, use a specific genre constraint to pull it back on track.

## Getting Started

<Steps>
  <Step title="Open the Genre Library">
    Find the "Genre Library" (题材基础库) entry in the workbench navigation, view existing genres, or create a new genre base.
  </Step>
  <Step title="Select or Create a Genre">
    Select an existing genre to supplement, or create a genre you plan to write. Name it in a way readers can understand, such as "Urban Superpower Leveling," "Female-led Revenge Satisfying Read," or "Post-Apocalyptic Base Management."
  </Step>
  <Step title="Fill in Core Information">
    First write the genre positioning, reader expectations, core selling points, and world boundaries. It does not need to be an encyclopedia at once; just cover the parts that can guide starting a book.
  </Step>
  <Step title="Supplement Conflicts and Risks">
    Then supplement common conflicts, protagonist types, easily deviated writing styles, and taboo pitfalls.
  </Step>
  <Step title="Reference When Starting a Book">
    Select this genre on the Auto Director start book page or in project settings, and the system will bring the genre information into direction generation and subsequent planning.
  </Step>
</Steps>

## The Relationship Between Genre Base and Progression Mode

Genre bases and progression modes are often used together, but they answer different questions:

| Module | Question It Answers | Examples |
| --- | --- | --- |
| Genre Base | What is this book like, which shelf does it go on | Urban superpower, immortal cultivation, suspense mystery |
| Progression Mode | Why does the reader continue to the next chapter | Leveling up, business expansion, mystery solving, relationship tension |

The same genre can be paired with different progression modes. For example, "Urban Superpower" can be a leveling stream, business warfare management, suspense mystery solving, or emotional tension. When both are clear at the start of the book, subsequent planning and main text will be more stable.

## How It Enters the Subsequent Creative Chain

The genre base mainly serves the book starting and planning phases. It will affect the following stages:

- **Shelf Positioning**: Book title, synopsis, and selling point expression
- **World Selection**: Rule boundaries when Auto Director generates the world
- **Character Function**: Common protagonist situations and growth directions
- **Chapter Rhythm**: Genre-corresponding rhythm expectations and conflict types

You can think of it as an explanation of "which reading market this book belongs to." It does not replace a specific outline, nor does it replace world-building and character settings, but it provides direction for these modules.

<Info>
  The genre base only participates in context judgment and does not directly generate main text. The actual writing of main text is still completed in the novel workbench and chapter execution.
</Info>

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="What is the difference between a genre base and a progression mode">
    A genre base is more like the shelf and reader expectations of a work, such as "Urban Superpower," "Immortal Cultivation," or "Suspense Mystery." A progression mode is more like the engine of the story, such as "Leveling Up," "Business Expansion," "Mystery Solving," or "Relationship Tension."
  </Accordion>

  <Accordion title="How detailed should a genre be">
    The first time, just write the parts that can guide starting a book: positioning, reader expectations, core selling points, world boundaries, and risks. If you find the generated results are still too generic, continue to supplement.
  </Accordion>

  <Accordion title="Will a genre base directly generate main text">
    No. It is a long-term reference asset that participates in direction, planning, and main text context judgment. The actual writing of main text is still completed in the novel workbench and chapter execution.
  </Accordion>

  <Accordion title="What if I don't know how to name a genre">
    First name it in a way readers can understand, such as "Urban Superpower Leveling," "Female-led Revenge Satisfying Read," or "Post-Apocalyptic Base Management." The name does not need to be professional, but it should allow you to understand at a glance which type of work it serves.
  </Accordion>

  <Accordion title="Will a genre base affect all novels">
    No. A genre base needs to be referenced by a specific novel first to become that project's creative reference. Each novel can be adjusted separately after referencing, and it will not affect the original genre sample.
  </Accordion>

  <Accordion title="Will signals from the Trending Genre Radar be written into the Genre Library">
    No. Signals collected by the Trending Genre Radar are written into an independent trending genre list, not into the general Genre Library or Progression Modes Library. You can manually create a corresponding genre base based on radar signals.
  </Accordion>
</AccordionGroup>
